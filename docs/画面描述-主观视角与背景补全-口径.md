# 画面描述层口径：主观视角 / 背景与群众 / 文字零遗漏

> 2026-10-07。对应 `promptTemplateRegistry.ts` 的 `storyboard` + `panel-prompt` ×2。
> 方案文档 §22。**四个诉求**：① 旁白与对话不能遗漏、要准确；② 没有场景的格要补背景；
> ③ 群众要简单描述出来；④ 人物看东西（手机/信件/书……）必须拆视角画。

---

## 一、主观视角：一个镜头塞两个视角，物理上不成立

### 1.1 错在哪

```
❌ 第2格：中景，林小雨坐在床边低头看手机，手机屏幕上显示一条未读消息“明天别来”，
         屏幕正对读者清晰可见，屏幕冷光映在她脸上。
```

这一格的指令是**自相矛盾**的：

- 「她在看手机」→ 她得侧对/背对镜头，屏幕背对观众；
- 「屏幕内容正对读者清晰可见」→ 屏幕得正对镜头，那她就在屏幕后面背对镜头。

模型只能二选一，而它通常选「让读者看见内容」——于是**人物被画成面向读者举着屏幕**，
角度彻底反过来。**这不是模型不听话，是写的人要它同时做两件做不到的事。**

### 1.2 正确的分工（两层各管一段）

| 层 | 管什么 |
|---|---|
| `storyboard`（分镜） | **拆不拆格**。内容影响剧情 → 拆成两格；不重要 → 不拆。**格数/格序只有分镜能定。** |
| `panel-prompt`（画面描述） | **这两格各自怎么画**。观看格只画背面/侧缘；POV 格只画内容物正面。 |

分镜层原本已有这条意图（【分格原则】「看手机/电视/书/窗外，同时读者也要看到内容时，
必须拆成两格（一格角色反应 + 一格主观 POV）」），但**画面描述层没有落地口径**，
于是拆格意图在下一环节蒸发，「看手机」被逐字搬进画面描述。

### 1.3 改后（分镜层）

```
第2格
景别：中景
镜头：平视，人物侧对镜头
画面：林小雨坐在床边，侧身对着画框右侧，低头看向手里的手机，手机只露出后盖与侧边框，
     屏幕与她自己的视线都背对读者；床头台灯暖光从左侧打来。
动作：双手握着手机，拇指停在屏幕边缘
表情：眉头收紧，呼吸放轻
出场资产：A1 林小雨（便装）

第3格
景别：POV
镜头：主观视角，贴近屏幕
画面：手机屏幕正面特写，占满整格：一条来自“陈默”的未读消息，写着“明天别来”；
     屏幕冷光溢出到画面边缘，右下角入画一小截握持的拇指。
```

### 1.4 改后（画面描述层）——写出来的硬口径

```
【主观视角】（人物在看什么东西——条漫最容易画反的一类）
- 被看的内容物绝不能和观看者挤在同一格里、还正面朝向读者。
- 观看格：人物朝物件看，物件只露背面或侧缘——手机给后盖与边框、信纸给背面、
  书本给封面与书口、照片给背面；屏幕内容、信纸字迹、书页图文一律不画。
- 内容要给读者看，就另占一格做主观 POV 格：只画内容物正面，占满画面或做特写，
  可带一点手指/手掌交代归属，这一格不出现人物的脸和上半身。
- 位置关系必须对得上：观看格人物朝画面哪一侧看，POV 格的取景就落在那条视线上。
- 分镜没给 POV 格时不许自己加格（格数、格序由分镜锁定）：只画背面/侧缘、不画内容。
- 一格里只允许一个观看方向；多人各看各的必须拆格。
```

### 1.5 判断表：什么时候需要 POV 格

| 场景 | 内容影响剧情？ | 处理 |
|---|---|---|
| 收到一条关键短信、告密信息 | 是 | **拆两格**（看的动作 + POV 格） |
| 看一张照片，认出里面的人 | 是 | **拆两格** |
| 看合同/账单/名单/告示上的关键信息 | 是 | **拆两格** |
| 从门缝/猫眼看到外面有人 | 是 | **拆两格**（或一格「透过缝隙的局部」+ POV） |
| 等回复、随手刷手机、合上书、看窗外发呆 | 否 | **不拆**，只画看的动作，且**不让内容物正面入画** |
| 照镜子 | — | 镜中影像**单独成格**，不与照镜人挤在一格里 |

> ⚠️ 单格满版页（1 格）没有地方放 POV 格 —— 这种页里**内容就不画**，只画看的动作。
> 内容必须露出的剧情点，应当在分镜阶段就别用 1 格页。

## 二、背景与群众：给定信息没写的，必须自己补

### 2.1 场景为空 → 不许留白

```
❌ 第4格：近景，林小雨含着泪抬头。（背景留着空白/虚化）
✅ 第4格：近景，林小雨含着泪抬头；背景是她租住小屋的床头一角——
        墙面泛黄、贴着一张卷边的乐队海报、床头柜上摆着半杯凉水和旧闹钟，
        窗外是凌晨的灰蓝冷光，从画面右侧斜切进来。
```

口径：

- **先沿用，再补**：同页或相邻镜已交代过空间 → 沿用同一套（空间类型、时代与地域、标志性物件、光线方向都要接得上）。
- **确实没有 → 按剧情处境补**：在哪、什么时间、什么气氛 → 写成 **空间类型 + 时代与地域 + 2~3 件标志性物件 + 光源方向与色温**。
- **禁止**「背景虚化」「纯色背景」「无背景」「留白」。
- **可以省细节，不能省光线**：补出的环境同样要给光源方向与色温，并与同页其余格一致。

### 2.2 群众：是背景，不是角色

```
❌ 背景站着王大爷和李婶，正看着她。
✅ 背景三两个撑伞的路人匆匆走过，没人回头。
✅ 柜台后一个低头结账的店员，只入画半个肩膀。
```

| 写 | 不写 |
|---|---|
| 数量 + 随身特征 + 在做什么 | 姓名、名号、身份代号 |
| 群体词：人群 / 路人 / 围观群众 / 店员 / 乘客 / 士兵队列 | 资产名、状态名 |
| 一笔带过，可裁切、可虚化 | 面部特写、与主要角色互动、参与剧情动作 |
| 与主角不同的服装与发色发型 | 与主角团撞辨识特征 |

### 2.3 ⚠️ 为什么「不许起名号」是硬红线（不是审美问题）

绑定审计会读**画面描述**：

- `promptAssetService.panelScanText(panel)` = `[panel.content, panel.imagePrompt]`
- `auditPanelBindings` 里有 `auditText(panel.imagePrompt ?? '', …)`
- 写描述后还会走 `syncBindingsAfterPromptWrite` 回填绑定

所以**画面描述里任何能命中资产名/别名/状态标签的词，都会被判成「未绑定」**，
并在一键补绑里凭空多出候选。给群众起个名字（哪怕是「王大爷」）恰好撞上某个资产别名，
就会稳定误报。

> 同理，**补出的背景也不要自造资产生意名**（「城东旧宅」这类）。需要指代已知场景时，
> 用分镜给的资产名，而不是另起一个名字。

## 三、文字零遗漏：旁白与台词一条都不能丢

画面描述是**下游唯一**把「台词/旁白」变成画面上文字的地方——漏一条，那一句在成图里就不存在，
读者看到的就是断掉的剧情。

口径（三处同源：正文【文字元素与气泡】、正文【文字铁律】、格式段）：

- **先清点再落笔**：把给定信息里的 台词／心声／画外／旁白 逐条对到格上；
- **一条不少、一条不错格、一字不改**；不许两句合成一条、不许转述改写、不许因为格子挤就省掉某一句；
- 「允许出现的文字」同时是一条**下限**：给定了几条就写几条；
- `写作要求` 里补一条**交付前文字清点**自检，并注明**「不要写进输出」**（否则模型会把它当成每格必答内容 → 新的固定尾段）。

## 四、生效与验收

⚠️ 模板是**存量优先**：到 设置页 → 提示词模板，对下面三类各点一次**「填入推荐模板」**：

1. **长篇章节分镜**（POV 拆格属分镜职责）
2. **分镜画面描述**
3. **分镜画面描述（整章一次生成）**

存量分镜与存量画面描述需要**重新生成**才会带上这一层。

土办法验收：随便翻一页有「看手机/看信/看书」的分镜 ——
① 观看格是不是只有背面/侧缘？② 内容有没有单独一格？③ 有没有一格是空背景？
④ 分镜给的每一句台词/旁白是不是都在「文字元素」里？
