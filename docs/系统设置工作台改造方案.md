> 状态：设计定稿，待实施

四块区域职责：
| 区域 | 职责 | 备注 |
|---|---|---|
| 顶部分类分段条 | 切换 6 个一级分类 | 小圆角（4px）分段控件，浅灰底+细描边，激活块蓝色实底白字，切换时平移动画 150ms |
| 顶部条目切换条 | 快速切换当前分类的编辑对象 | 横向胶囊（图标+名称），顺序跟随左栏排序，末端虚线"＋"新增，条目多时横向滚动 |
| 左栏资源库 | 管理所有条目 | 顶部搜索框跨全库搜索；按分类分组；行内悬浮⧉复制/✕删除；整行拖拽组内排序；底部"＋添加"；LLM 条目显示连接状态点（绿=成功/红=失败） |

特殊分类适配：
- **存储与上传**：无条目 → 隐藏条目切换条与左栏，右栏整宽显示现有表单分区
- **微信公众号**：条目即账号；头像做行图标；"默认同步"账号加星标置顶；"当前账号"高亮
- **空分类**：条目切换条只剩"＋"，右栏显示引导空态

## 四、状态设计（SettingsView 中枢）

```ts
interface SettingsState {
  activeTab: Ref<SettingsTab>          // 一级分类，'llm' | 'image' | 'video' | 'template' | 'wechat' | 'paths'
  activeItemId: Ref<string | null>     // 当前编辑的条目 id；null = 未选中/空态
  creating: Ref<boolean>               // 是否处于"新增中"（右栏显示空白表单）
  dirty: Ref<boolean>                  // 右栏表单有未保存修改
  searchKeyword: Ref<string>           // 左栏搜索关键字
}
```

关键交互规则：

1. **选中链路**：左栏点击条目 / 顶部胶囊点击 / 搜索结果点击 → 统一走 `selectItem(id, tab?)`（跨分类点击自动切 tab）→ 右栏加载表单。
2. **未保存保护**：`dirty === true` 时任何切换（换条目/换分类/新增/删除当前条目）先弹确认：「放弃修改并离开 / 留下继续编辑」。表单组件通过 `v-model:dirty` 或 `@dirty-change` 上报。
3. **保存链路**：右栏表单 `emit('save', value)` → SettingsView 调 comicDb 写入 → 刷新左栏数据 → 新增时把 `activeItemId` 指向新条目。
4. **删除链路**：左栏行内 ✕ / 直接调 comicDb 删除（带确认）；删的是当前编辑条目时 `activeItemId` 顺位移到相邻条目。
5. **复制链路**：左栏行内 ⧉ → 深拷贝条目、名称加"副本"后缀 → 插入到该条目下方并选中。
6. **路由同步**：`?tab=llm&id=xxx`；切 tab / 切条目均 `router.replace`；进入时读 query 恢复（保持现有 `?tab=` 直达兼容，`id` 缺省时选该分类第一个条目）。

## 五、各区域实现细节

### 5.1 分类分段条 SettingsCategoryBar

- 容器：`flex bg-app-bg border rounded-[4px] p-0.5`，激活块 `rounded-[3px]`
- 激活块滑动动画：用绝对定位的指示块 + `transition: left 150ms`（或 transform），通过 `ref` 测量激活按钮 offsetLeft
- 复用现有 6 个 tab 定义（图标、label、key），props/emits 与现 SettingsView 的 categoryTabs 一致
- 存储与上传等 6 项均分宽度 `flex-1`

### 5.2 条目切换条 SettingsItemChips

- props：`items: { id, name, icon }[]`、`activeId`；emits：`select(id)`、`add()`
- 胶囊：`rounded-full border px-3 py-1.5 flex items-center gap-1.5`，激活态蓝色实底白字，非激活白底描边
- 末端"＋"虚线胶囊；容器 `overflow-x-auto` 隐藏滚动条（`custom-scrollbar` 样式已有）
- `activeTab === 'paths'` 时整个组件 `v-if` 隐藏

### 5.3 左栏资源库 SettingsResourceList

- **数据源**：SettingsView 统一从 comicDb / wechatStore 加载全部分类条目，向下传 `groups: { tab, label, items }[]`
- **搜索**：前端 filter（name / model 字段模糊匹配），命中结果跨分组显示，命中分组外的折叠隐藏
- **行结构**：`[图标] 名称 ... [⧉] [✕]`（操作按钮 `opacity-0 group-hover:opacity-100`）；名称超长 truncate；LLM 行尾加状态点
- **拖拽排序**：沿用现 ModelSettings 的 HTML5 dragstart/dragover/drop 实现，限制同分组内调序；落库调用现有 sortOrder 更新逻辑（三个分类的 models 共用 `sortOrder`，模板同理；公众号账号若现无排序字段则不提供拖拽——待实施时确认 wechatStore 是否支持排序，不支持则该分组禁用拖拽）
- **宽度**：`w-56 shrink-0`，独立 `overflow-y-auto`
- 图标：模型类按 category 用 `BotMessageSquare/Image/Video`，模板 `FileText`，公众号用账号头像或 `MessageCircle`

### 5.4 右栏编辑器（三个表单组件）

**ModelEditorForm.vue**（llm/image/video 三分类复用）
- 从 ModelEditorModal 原样迁移表单字段与校验逻辑（`defaultForm`、`canSave`、openaiExtraParams 序列化、`watch model` 回填）
- 底部操作条：左侧测试连接（仅 llm；按钮样式与结果文案沿用现逻辑），右侧重置+保存
- 新增 `reset()` 方法（重置=恢复为当前条目原始值，新增态=清空）
- 新增 dirty 检测：`watch(form, deep)` 与初始快照比对（JSON 序列化对比，字段量小可接受）
- props：`category`、`model: ModelConfig | null`（null 且 creating=true 为新增）；emits：`save(value)`、`dirty-change(bool)`
- 测试结果通过 `emit('test-result', { id, result })` 上抛，SettingsView 存入 `testResults` 映射供左栏状态点使用（沿用现 ModelSettings 的 reactive testResults 结构）

**TemplateEditorForm.vue**
- 从 PromptTemplateSettings 迁移：type 选择按钮组、description、outputProtocol（含推荐协议插入）、content（含 6 种推荐模板填入按钮）
- 校验：name + content 非空；无测试连接（操作条左侧留空）

**WechatEditorForm.vue**
- 字段：AppID、AppSecret（眼睛切换）；鉴权错误展示沿用现逻辑
- 保存 = 请求鉴权并添加/更新（沿用 wechatStore 现有 action）
- 左栏行操作复用：切换当前账号（点行）、设为默认同步（表单内 checkbox 或左栏星标按钮——实施时取更简者）

### 5.5 测试连接位置说明

统一放右栏底部操作条**左侧**（对齐定稿设计）；表单滚动时操作条 `sticky bottom-0` 保持可见。

## 七、风险评估

| 风险 | 等级 | 应对 |
|---|---|---|
| 表单字段多（模型 openai 扩展参数），迁移时遗漏 | 中 | ModelEditorForm 逻辑整体平移不改写，仅换外壳；迁移后与旧弹窗字段逐项对照 |
| 拖拽排序跨分组误放 | 低 | drop 时校验同分组才生效 |
| 公众号账号无排序字段 | 低 | 该分组禁用拖拽（只支持置顶默认账号） |
| `?tab=` 外部跳转入口失效 | 低 | query 结构向后兼容（id 可选，缺省自动选第一项）；全库搜索 `?tab=` 引用点 |
| dirty 检测 JSON 深比较的性能 | 低 | 表单字段量小（<30 字段），可忽略 |
| 弹窗废除后其他页面直接 import 编辑弹窗 | 低 | 实施前 grep `ModelEditorModal|PromptTemplateSettings|WechatAccountSettings` 引用面确认仅设置页使用 |
