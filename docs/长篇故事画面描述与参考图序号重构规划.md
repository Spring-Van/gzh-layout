## 二、现状盘点（含代码位置）

### 2.1 现有「批量推导画面描述」链路

```
LongProjectStoryboardTab.vue
  「批量推导描述」按钮 → PanelPromptGenerateModal.vue（选模型 / 选 panel-prompt 模板 / 范围 missing|all / 预览首镜）
    → runBatchPrompts()  逐镜 for 循环，串行 LLM 调用
      → buildPanelPromptPrompt()  panelPromptService.ts
        → renderPromptTemplate({ type:'panel-prompt', values: 7 个变量 })
          → 结果写入 panelArtworks[].imagePrompt
            → 生图：generatePanelImage(panel) → prompt = imagePrompt，refImages = panelRefImages(panel)
```

### 2.2 现有 7 个模板变量（`VARIABLE_REGISTRY['panel-prompt']`）

| 变量 | 现状内容 | 问题 |
|---|---|---|
| `{{当前分镜}}` | 序号 / 镜头 / 画面内容 / 分格详情 / 分镜参考描述 | 无参考图信息 |
| `{{镜头}}` | 镜头类型 | — |
| `{{前文分镜}}` | 前 2 镜 + 已推导描述（滑动窗口） | — |
| `{{本章分镜概要}}` | 每镜一行 | — |
| `{{绑定资产}}` | 资产名/类型/视觉状态/视觉描述/绘画提示词/固定特征 | **无图号** |
| `{{风格上下文}}` | `buildStyleContext` → 只取 `block.description` 平铺 | **无图号、无参考图、不分前后** |
| `{{目标生图模型}}` | 生图模型名 | — |

### 2.3 三个具体缺口

- **缺口 A — 序号缺失**：提示词里没有任何「图 N = 谁」的约定。模型写「参考图中的人物」时，实际传给生图模型的第 N 张图是什么，无从对应。
- **缺口 B — 图序与要求相反**：`LongProjectStoryboardTab.vue:1107` `panelRefImages()` 为 `[...assetRefs, ...sharedRefs]` —— 共用属性图排在**最后**；且 `assetRefs` 顺序来自 `panel.assetBindings`（不保证 人物→场景→道具）。
- **缺口 C — 共用属性描述会被覆盖**：`ImageConfigDrawer.vue:888` 上传图后自动调 `refreshBlockDescriptionWithNumbers` **整体覆盖** `block.description`。而 `description` 同时是用户手填的正文 → 用户写的描述会被模板话术冲掉。删除图片时同样会刷新。

### 2.4 短篇已具备、可直接复用的件（`utils/sharedBlocks.ts`）

| 函数 | 作用 | 复用结论 |
|---|---|---|
| `sortSharedBlocks` / `getBlocksByPosition` | front / back 分组排序 | ✅ 直接复用 |
| `computeBlockImageNumbers` | 共用属性内全局图号 | ✅ 复用思路，**需扩展为跨资产编号** |
| `buildBlockRefDescription` | 生成图号话术 | ⚠️ 话术要改（见 §3.2） |
| `refreshBlockDescriptionWithNumbers` | 上传/删图后刷新描述 | ❌ **停用**（正是缺口 C 的成因） |
| `buildSharedPromptFields` | → `{front:{名:文本}, back:{…}}` | ✅ 复用（长篇拼中文而非 JSON） |
| `getSharedRefImages` | 扁平取共用属性图 | ⚠️ 改为**只取 front 组** |

> **唯一核心缺口**：没有「共用属性图 + 资产图」的全局统一编号函数。

## 三、核心设计

### 3.1 新建唯一事实来源：参考图清单 `PanelRefManifest`

新建 `src/modules/comic/services/panelRefManifest.ts`（纯函数，无副作用）：

```ts
export interface PanelRefEntry {
  index: number                    // 全局 1-based 图号 = 传给生图模型的数组下标 + 1
  source: 'shared' | 'asset'
  label: string                    // 共用属性：块名；资产：资产名
  blockId?: string                 // 共用属性条目
  assetType?: LongProjectAssetType // 资产条目：character | scene | prop
  variantName?: string             // 资产条目
  cellIndexes?: number[]           // 资产条目：出现格（0 起），空 = 整镜
  image: string
}

export interface PanelRefManifest {
  images: string[]                 // 与 entries 一一对应，直接喂给生图模型
  entries: PanelRefEntry[]
  dropped: number                  // 因超出上限未发送的张数
}

export function buildPanelRefManifest(args: {
  panel: LongProjectStoryboardPanel
  assets: LongProjectAsset[]
  sharedBlocks?: SharedPromptBlock[]
  maxImages: number
}): PanelRefManifest
```

**编号规则（严格按诉求顺序）**：

| 段 | 来源 | 排序 |
|---|---|---|
| 1..N | 「插入最前」且 `enableRefImages` 的共用属性块 | `sortOrder` 升序 → 块内上传顺序 |
| N+1.. | 资产图 | **人物 → 场景 → 道具**；组内按 `resolvePanelAssetStates` 顺序；每状态取 1 张（`resolvePanelRefImage` 单选口径） |
| — | 「插入最后」的块 | **不参与**（见 §3.4） |
| 超限 | — | 按上述顺序截断，`dropped` 计数并在 UI 明示 |

**关键不变式：`images[i]` 就是「图 i+1」。** 只要清单与数组同源，图号永远准 —— 这也是「改图后实时更新」的实现方式：清单是纯函数实时算的，改图/换状态/调顺序都会立刻反映到下一次拼装，**不需要任何刷新按钮或落库同步**。

**消费方统一**（全部改为读清单，消除口径漂移）：

| 消费端 | 现状 | 改造后 |
|---|---|---|
| 生图取图 `panelRefImages()` | 自建 `[...assetRefs, ...sharedRefs]` | `manifest.images` |
| 右栏参考图分组 `currentRefGroups` | 自建分组循环 | 由 `manifest.entries` 按 `assetType` 分组 |
| 画面描述提示词 | 无 | `{{参考图清单}}` |
| 最终 prompt 拼装 | 无 | 图号清单段 |
| 资产工作台「N 镜引用」`assetUsageService` | 自建展开口径 | 改用清单（口径自然同源） |
| `PanelPromptPanel` 参考图区 | 无图号 | 显示 `图1 / 图2` 角标 |

### 3.2 共用属性段的中文拼装格式

按诉求给定形态（`属性名` → `图号行` → `描述正文`）：

```
绘画风格参考图
图1、图2：绘画风格参考图。
综合图1～图3的共同视觉特征，确定本页漫画的整体绘画风格，包括线稿、人物画法、上色方式、光影、色彩、背景表现和画面质感。
图1～图3仅用于参考绘画风格，不用于参考人物身份、人物外貌、场景、道具或构图。
不要将图1～图3中的人物、场景或物体直接带入最终画面。
```

实现：

```ts
// 图号行由代码生成，不落库
function buildBlockText(block: SharedPromptBlock, nums: number[], position: 'front' | 'back'): string {
  const lines: string[] = [block.name]
  if (position === 'front' && nums.length) lines.push(`${nums.map(n => `图${n}`).join('、')}：${block.name}。`)
  if (block.description?.trim()) lines.push(block.description.trim())
  return lines.join('\n')
}
```

> **注意**：`buildBlockRefDescription` 的旧话术（`绘画风格参考图参考上传的图1，图2`）不再使用；`description` **只存用户手填正文**，不再被代码覆盖。

### 3.3 新增 3 个模板变量

写入 `VARIABLE_REGISTRY['panel-prompt']`（设置页变量 tag 自动出现）：

| 变量 | 内容 | 建议位置 |
|---|---|---|
| `{{前置共用属性}}` | front 组各块拼接文本（含图号行 + 描述） | 模板最前 |
| `{{参考图清单}}` | 图号 → 用途映射（见下） | 「当前分镜」附近 |
| `{{后置共用属性}}` | back 组各块拼接文本（**不含图号行**） | 模板最后 |

`{{参考图清单}}` 示例（由 `manifest.entries` 生成）：

```
图1 = 绘画风格参考图（共用属性，仅用于整体画风/线稿/上色/光影，不得带入人物与场景）
图2 = 萧薰儿 · 战斗服（人物，第1-2格；仅用于人物身份、脸部、发型、服装与外貌）
图3 = 萧家测试广场（场景，第1格；仅用于环境与空间布局）
图4 = 测验魔石碑（道具，第2格；仅用于道具外观）
```

**为什么必须有这个变量**：诉求里「图1 = 萧薰儿角色参考，仅用于人物身份…」这段逐图用途声明，模型只有拿到清单才写得对。原则是 **序号由代码算，语义由模型写**：模型只负责「使用图1保持萧薰儿与第1格一致」，绝不允许模型自己数图号。

`{{风格上下文}}`：**保留但标记 deprecated**（`desc` 改为「已并入 `{{前置共用属性}}`，建议改用新变量」），存量模板不炸；第一阶段不删。

### 3.4 「插入最后」去掉参考图能力

- `SharedPromptBlockCard.vue`：`insertPosition === 'back'` 时不渲染「需要参考图」开关与图区，改为一行灰字「插入最后的属性不支持参考图（图号从前往后编号，后置图会与画面描述中的图号错位）」。
- `computeBlockImageNumbers` / `getSharedRefImages` / `buildPanelRefManifest`：**跳过 back 组**。
- 数据兼容：`enableRefImages` 与 `referenceImages` **保留不删**（切回 front 即恢复）；仅运行时失效，并在卡片上提示「N 张图当前不参与生图」。
- `ImageConfigDrawer.vue`：back 块的上传入口一并去掉，避免新写入。

> 理由（回复「为什么后置属性不该有图」）：最终 prompt 的图片数组顺序是 `共用属性图 → 资产图`，而后置属性的**文字**出现在画面描述之后。若它也带图，图号顺序与文字出现顺序就错位，模型必然混淆。

### 3.5 最终送生图的 prompt：三层拼接

```
┌─────────────────────────┐
│ ① 前置共用属性（代码拼） │  ← 不经模型：稳定、不被改写、改画风无需重跑 LLM
├─────────────────────────┤
│ ② 画面描述（LLM 输出）   │  ← 可在右栏人工编辑；可复制到外部 AI 再导回
├─────────────────────────┤
│ ③ 后置共用属性（代码拼） │
└─────────────────────────┘
```

实现：`generatePanelImage` 内 `prompt = composeFinalPrompt(panel, artwork.imagePrompt, sharedBlocks, manifest)`。

三个好处：
1. 画面描述字段保持**纯净** → 可单独复制到外部 AI / 人工编辑，不被共用属性污染；
2. 改画风 / 换共用属性图 → **不必重跑 LLM**，下次生图自动生效；
3. 固定文案（尤其参考图用途声明）不会因模型改写而漏句、串图。

`{{前置共用属性}}` ~~同时作为 LLM 输入变量出现（模型需知道画风要求才能收笔）~~，但**输出侧仍由代码拼**，保证一致。

> **⚠️ 已推翻（见 §六 v2 修订）**：共用属性**不再作为任何推导变量**。原判断（"模型需知道画风要求才能收笔"）经实跑证伪 ——
> 画面描述只描述画面本身，画风由生图时拼接的共用属性负责；把画风塞进推导输入只会让模型把风格词抄进每条描述，
> 生图时又拼一遍，形成重复。

### 3.6 回答三个问题

**Q1：需要一次生成所有分镜的绘画提示词吗？**

| 维度 | 逐镜依次（现状，建议默认） | 一次全章（建议第二阶段） |
|---|---|---|
| 调用次数 | N 次 | 1 次 |
| 上下文 | 滑动窗口前 2 镜（含已生成描述） | 全章分镜原文（无已生成描述） |
| 连续性 | 强（站位/光线靠前镜描述携带） | 中 |
| 抗截断 | 强（单镜失败只补单镜） | 弱（长章易截断，失败全重跑） |
| 速度 / 成本 | 慢 / 高 | 快 / 低 |
| 参考图清单 | 逐镜不同，天然正确 | 每镜仍需各自清单，须在输出格式里逐镜声明 |

结论：**先做逐镜（改动小、质量稳、可续跑），并在弹窗加「生成方式」二选一**；「一次全章」需要新的输出格式协议 + 新解析器（`【分镜N】` 分段），列为后续。

**Q2：提示词模板能共用吗？** —— **能。**
- `panel-prompt` 是同一个 `TemplateType`，设置页一份模板列表，长短篇共用同一份 `VARIABLE_REGISTRY`；新增变量设置页自动出现。
- 共用属性配置本就是项目级（长短篇各自项目持有），`sharedBlocks.ts` 的函数共用。
- 唯一例外：短篇 `PageEditor.buildPagePrompt` 目前**不走模板**（直接 JSON 拼接），本次不动；后续可考虑切换。

**Q3：能复制到外部 AI 再手动导入吗？** —— **能，复用现有 `ManualResultImportDialog`。**
- **复制**：预览弹窗加两个入口 —— 「复制本镜提示词」（与内置单镜调用完全一致）、「复制整章提示词（N 镜）」= 逐镜提示词顺序拼接 + **附加一段输出格式要求**（`【分镜N】` 分段）。
- **格式段只附加在复制文本里，不写进模板** —— 内置调用是逐镜的、本就知道是哪一镜，不需要标记；写进模板反而污染内置输出。
- **导入**：`ManualResultImportDialog` 新增「画面描述」模式，解析器优先按 `【分镜N】` 对位；无标记时按顺序对位并提示「已按顺序对位，请核对序号」。写入 `imagePrompt`，`promptSource: 'manual'`。

## 五、拍板结论（2026-09-18，已按此实施）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 「插入最后」的已有参考图 | **保留数据仅失效**：`getSharedRefImages` / `computeBlockImageNumbers` / `buildPanelRefManifest` 全部只算 front 组；卡片隐藏开关与图区，数据不动，切回 front 即恢复 |
| 2 | 超限截断（原 `MAX_REF_IMAGES = 14`） | **不做截断**：清单返回全部参考图，生图侧不再 `slice`，上传侧的 14 张校验一并放开 |
| 3 | 「一次全章」 | **本次就做**，且**独立模板类型** `panel-prompt-chapter`（用户确认两者不该共用一个模板：全章模式下 `{{镜头}}` / `{{前文分镜}}` / `{{本章分镜概要}}` 全部冗余，改用 `{{全章分镜}}` / `{{全章资产设定}}` / `{{全章参考图清单}}`） |
| 4 | `{{风格上下文}}` | **移除**（变量注册与推荐模板同步清理；存量模板里的该占位符在渲染时按未注册占位符清理，设置页会给红色告警） |
| 5 | 是否要求模型写图号 | **要求**：逐镜与全章两套输出协议都写明「必须用清单里的图号声明用法，不要自己数图」；模板正文同步补写作要求 |

### 与规划稿的第 3 点差异说明

规划稿原建议「先逐镜、整章放第二阶段」。用户拍板改为**本次一起做**，并且**不做成同一个模板类型**：

| | `panel-prompt`（逐镜） | `panel-prompt-chapter`（整章一次） |
|---|---|---|
| 调用次数 | N 次 | 1 次 |
| 分镜变量 | `{{当前分镜}}` | `{{全章分镜}}` |
| 资产变量 | `{{绑定资产}}` | `{{全章资产设定}}`（按「分镜N」分组） |
| 图号变量 | `{{参考图清单}}` | `{{全章参考图清单}}`（按镜分组；图号沿用生图真实序号） |
| 冗余变量 | — | **不含** `{{镜头}}` / `{{前文分镜}}` / `{{本章分镜概要}}` |
| 输出协议 | 一段描述 | 逐镜 `【分镜N】` 分段 |
| 解析 | 不需要 | `parseChapterPanelPrompts`（标记对位 / 顺序兜底 / 漏段提示） |
| 共用属性 | **不进推导提示词**：只由 `composeFinalPrompt` 在生图时前后拼接（v2 修订，见 §六） | |

## 六、v2 修订（2026-09-18 晚）：共用属性退出生意，模板改为用户自建

### 6.1 两条修订

**修订 A — 共用属性不再进推导提示词。**

v1 把 `{{前置共用属性}}` / `{{后置共用属性}}` 作为模板变量塞进推导提示词，理由是"模型得知画风才能收笔"。实跑后证伪：

| 问题 | 表现 |
|---|---|
| 内容重复 | 模型会把风格词抄进画面描述，生图时 `composeFinalPrompt` 又拼一遍 → 同一条提示词里画风说两遍 |
| 图号冗余 | 描述里写"使用图1保持画风一致"，而图1 的用途行本来就在前置共用属性里，模型越权复述 |
| 无法复用 | 描述被画风污染 → 换画风必须重跑 LLM，v1 承诺的"改画风不必重跑"落空 |
| Token 浪费 | 每镜（或整章）都带一份共用属性正文，逐镜模式下被重复 N 次 |

v2 口径：**推导提示词只给三样东西** —— 分镜内容、资产视觉设定、资产参考图号清单；
共用属性只在生图时由 `composeFinalPrompt` 前后拼接，仍然不进 `imagePrompt` 字段。

**修订 B — 画面描述环节不再有内置默认模板。**

`DEFAULT_PANEL_PROMPT_TEMPLATE` / `DEFAULT_CHAPTER_PANEL_PROMPT_TEMPLATE` 已删除；拼法完全由用户自己的模板决定。
弹窗里的选项从「内置默认模板 / 我的模板」变成「选模板」，列表为空时给「新建模板（填入推荐内容）」——
一键落库该类型的 `RECOMMENDED_TEMPLATES` 内容，之后在系统设置 → 提示词模板里随便改。

### 6.2 变量表（v2，最终）

| 类型 | 变量 | 谁生成 |
|---|---|---|
| `panel-prompt`（逐镜） | `{{当前分镜}}` `{{镜头}}` `{{前文分镜}}` `{{本章分镜概要}}` `{{绑定资产}}` `{{参考图清单}}` `{{目标生图模型}}` | 代码 |
| `panel-prompt-chapter`（整章） | `{{全章分镜}}` `{{全章资产设定}}` `{{全章参考图清单}}` `{{目标生图模型}}` | 代码 |
| （已删除） | `{{前置共用属性}}` `{{后置共用属性}}` `{{风格上下文}}` | — |

### 6.3 图号：只给资产图，号不变

清单文本新增 `assetsOnly` 口径（`buildRefManifestText(manifest, { assetsOnly: true })`）：
只列资产条目，**但沿用生图时的真实图号**（前置共用属性图先占号），并附一行占位说明。

```
（图1、图2 为前置共用属性参考图，由系统在画面描述之外另行拼接，无需在描述中引用）
图3 = 萧薰儿 · 便装（人物，第1格；仅用于人物身份、脸部、发型、服装与外貌特征）
图4 = 测验魔石碑 · 常态（道具，第2格；仅用于道具外观与材质）
```

于是链条自洽：代码算号 → 模型照抄「图3」→ `composeFinalPrompt` 把前置共用属性（含 `图1、图2：…` 的图号行）拼在最前 →
生图图片数组 `[style-1, style-2, casual-1, stone-1]` 的第 3 张正好是图3。

### 6.4 输出要求（两套协议同步补的两条）

1. **必须**用清单里的图号声明参考图用途（如「使用图3保持萧薰儿与第1格一致」），图号不得自数、改写、编造；
2. **不要**写全局画风与共用属性内容 —— 它们由系统在生成后自动拼接到描述之外，写进描述里会重复。
