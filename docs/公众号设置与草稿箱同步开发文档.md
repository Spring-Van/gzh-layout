# 公众号设置与同步到草稿箱 — 开发文档

> 本文档基于本项目（`gzh-layout`）实际实现整理，供其他项目复用。  
> 核心目标：绑定公众号 AppID/AppSecret → 鉴权拿 Token → 上传封面/正文图 → 创建草稿（可选发布）。

---

## 1. 整体架构

本项目是 **Electron 桌面应用**，微信 API 调用放在 **主进程**，渲染进程通过 IPC 调用。

```
渲染进程 (Vue)
  ├─ ModalAccount.vue          账号绑定 UI
  ├─ wechatAccount.ts (Pinia)  账号状态
  ├─ SyncView.vue              同步页
  ├─ useWechatUpload.ts        组装文章参数 + 触发批量上传
  └─ api/wechat.ts             封装 window.electronAPI.wechat / db
         │
         │  IPC (preload.ts)
         ▼
主进程 (Electron)
  ├─ ipc/wechat.ts             注册 IPC + 批量上传编排
  ├─ services/wechat.service.ts  微信开放接口封装
  └─ services/database.service.ts  账号持久化（本地 JSON）
```

**其他项目接入时的两种方式：**

| 场景                      | 建议                                                                           |
| ------------------------- | ------------------------------------------------------------------------------ |
| 同样是 Electron           | 可直接复用 `wechat.service.ts` + IPC 模式                                      |
| Node 后端 / 纯 Web 服务端 | 只复用「微信 API 调用逻辑」，Token 与上传在服务端完成                          |
| 纯前端浏览器              | **无法直接调微信公众号服务端 API**（有 CORS 与密钥泄露风险），必须走自己的后端 |

---

## 2. 前置条件（公众号后台）

1. **已认证**的订阅号或服务号（草稿箱、永久素材等能力与认证相关）。
2. 在 **设置与开发 → 基本配置** 获取：
   - `AppID`
   - `AppSecret`
3. 将调用方公网 IP 加入 **IP 白名单**（常见错误 `40164`）。
4. 图片限制：
   - 格式：**JPG / PNG / GIF**（本项目明确拒绝 **WebP**，需先转 PNG/JPG）
   - 封面推荐比例 **2.35:1**，大小建议 ≤ 1MB（接口上限约 5MB）
   - 永久图片素材额度：约 10 万

---

## 3. 业务总流程

```
① 绑定公众号（AppID + AppSecret）
        ↓
② 获取 AccessToken（内存缓存，提前 300s 过期）
        ↓
③ 校验 Token / 拉取账号基本信息（昵称等）
        ↓
④ 对每篇文章：
   4.1 上传封面图 → material/add_material → thumb_media_id
   4.2 上传正文图 → media/uploadimg → 微信 CDN URL
   4.3 把 HTML 中本地路径替换为微信 URL
   4.4 创建草稿 → draft/add → media_id
   4.5 （可选）发布 → freepublish/submit → publish_id
```

本项目默认 **只同步到草稿箱**，`publish` 开关在同步页为 `false`（hidden input）。

## 4. 公众号设置（账号管理）

### 4.1 账号数据模型

```typescript
/** 本地持久化的公众号账号 */
interface WechatAccount {
  id: string;
  appId: string;
  appSecret?: string;
  nickname: string;
  headImg?: string;
  accessToken?: string;
  tokenExpiresAt?: number; // 毫秒时间戳
  isActive: boolean; // 当前活跃账号（UI 当前选中）
  isDefaultSync: boolean; // 默认同步账号（同步页默认选这个）
}
```

### 4.2 账号操作流程

| 操作         | 行为                                                                         |
| ------------ | ---------------------------------------------------------------------------- |
| 添加账号     | 用 AppID/AppSecret 调用 `authenticate` → 成功后写入本地库，并设为 `isActive` |
| 编辑账号     | 重新鉴权，更新 nickname / token / secret                                     |
| 切换活跃账号 | `setActiveWechatAccount(id)`，仅允许一个 `isActive=true`                     |
| 设为默认同步 | `setDefaultSyncWechatAccount(id)`，仅允许一个 `isDefaultSync=true`           |
| 删除账号     | 从本地库移除；若删的是活跃/默认，会尝试切到列表第一个                        |

### 4.3 鉴权步骤（绑定账号时）

```
getAccessToken(appId, appSecret)
    ↓
getcallbackip 校验 token 是否有效
    ↓
account/getaccountbasicinfo 拉昵称/头像等（失败时允许空信息，不阻断绑定）
    ↓
返回 AuthResult，前端组装 WechatAccount 并 save
```

**AuthResult：**

```typescript
interface AuthResult {
  success: boolean;
  accessToken: string;
  expiresIn: number; // 秒（相对缓存过期时间计算）
  accountInfo: {
    nickname: string;
    headImg: string;
    serviceType: number;
    verifyType: number;
    userName: string;
    alias: string;
    qrcodeUrl: string;
  };
}
```

## 5. 微信接口一览（必须实现）

基础域名：`https://api.weixin.qq.com`

### 5.1 获取 AccessToken

- **方法**：`GET`
- **URL**：`/cgi-bin/token?grant_type=client_credential&appid={APPID}&secret={SECRET}`
- **成功响应**：

```json
{
  "access_token": "ACCESS_TOKEN",
  "expires_in": 7200
}
```

**本项目缓存策略：**

- 内存缓存 `tokenCache: { accessToken, expiresAt }`
- 过期缓冲：`TOKEN_EXPIRE_BUFFER = 300` 秒（提前 5 分钟视为过期）
- 提供 `clearTokenCache()` 在重置上传状态时清空

> 注意：同一 AppID 的 Token 全局共享，多处频繁刷新会导致互相失效。

---

### 5.2 校验 Token

- **方法**：`GET`
- **URL**：`/cgi-bin/getcallbackip?access_token={TOKEN}`
- **用途**：判断 token 是否仍有效（有 `errcode` 则失败）

---

### 5.3 获取账号基本信息

- **方法**：`POST`
- **URL**：`/cgi-bin/account/getaccountbasicinfo?access_token={TOKEN}`
- **用途**：取 `nickname`、`head_img` 等用于 UI 展示
- **说明**：部分账号可能无权限，本项目失败时返回空字段，不抛错阻断绑定

---

### 5.4 上传封面图（永久素材）

- **方法**：`POST` `multipart/form-data`
- **URL**：`/cgi-bin/material/add_material?access_token={TOKEN}&type=image`
- **表单字段**：`media` = 图片文件
- **成功响应**：

```json
{
  "media_id": "MEDIA_ID",
  "url": "https://mmbiz.qpic.cn/..."
}
```

**用途：**

- `media_id` → 创建草稿时的 `thumb_media_id`（封面）
- `url` → 本地记录展示

**限制：**

- 必须 JPG/PNG/GIF
- WebP 需先转换（本项目在同步前用 `webpConvertedMap` 替换路径）

---

### 5.5 上传正文图片（图文内图片）

- **方法**：`POST` `multipart/form-data`
- **URL**：`/cgi-bin/media/uploadimg?access_token={TOKEN}`
- **表单字段**：`media` = 图片文件
- **成功响应**：

```json
{
  "url": "https://mmbiz.qpic.cn/..."
}
```

**与封面接口的区别：**

| 对比项               | 封面 `add_material`       | 正文 `uploadimg`         |
| -------------------- | ------------------------- | ------------------------ |
| 返回                 | `media_id` + `url`        | 仅 `url`                 |
| 是否占用永久素材额度 | 占用                      | **不占用**               |
| 用途                 | 草稿封面 `thumb_media_id` | 正文 HTML 的 `<img src>` |

**批量上传建议：**

- 逐张上传，张与张之间 `delay(300ms)`，降低 `45009` 频率限制风险

---

### 5.6 新建草稿

- **方法**：`POST` `application/json`
- **URL**：`/cgi-bin/draft/add?access_token={TOKEN}`
- **请求体：**

```json
{
  "articles": [
    {
      "title": "文章标题",
      "thumb_media_id": "封面永久素材 media_id",
      "author": "",
      "digest": "摘要，默认可用标题",
      "content": "<section>...</section>",
      "content_source_url": "",
      "need_open_comment": 1,
      "only_fans_can_comment": 0,
      "pic_crop_235_1": "0_0_1_1",
      "pic_crop_1_1": "0.287234_0_0.712766_1"
    }
  ]
}
```

**成功响应：**

```json
{
  "media_id": "DRAFT_MEDIA_ID"
}
```

#### 字段说明

| 字段                    | 必填 | 说明                                          |
| ----------------------- | ---- | --------------------------------------------- |
| `title`                 | 是   | 标题，注意字节长度限制                        |
| `thumb_media_id`        | 是   | 封面永久素材 ID                               |
| `content`               | 是   | 图文 HTML（图片 src 必须是微信 CDN URL）      |
| `digest`                | 否   | 摘要；本项目默认用标题/副标题                 |
| `author`                | 否   | 作者                                          |
| `content_source_url`    | 否   | 原文链接                                      |
| `need_open_comment`     | 否   | 1 开评论 / 0 关                               |
| `only_fans_can_comment` | 否   | 是否仅粉丝可评论                              |
| `pic_crop_235_1`        | 否   | 2.35:1 封面裁剪 `x1_y1_x2_y2`（0~1 相对坐标） |
| `pic_crop_1_1`          | 否   | 1:1 封面裁剪                                  |

#### 裁剪参数计算（本项目默认）

封面按 2.35:1 全图使用，1:1 居中裁切：

```typescript
function calculateCropParams(originalRatio = 2.35) {
  const pic_crop_235_1 = "0_0_1_1";
  const cropWidth = 1 / originalRatio;
  const margin = (1 - cropWidth) / 2;
  const x1 = margin.toFixed(6);
  const x2 = (1 - margin).toFixed(6);
  const pic_crop_1_1 = `${x1}_0_${x2}_1`;
  return { pic_crop_235_1, pic_crop_1_1 };
}
// 默认 2.35 时：pic_crop_1_1 ≈ "0.287234_0_0.712766_1"
```

### 5.7 发布草稿（可选）

- **方法**：`POST` `application/json`
- **URL**：`/cgi-bin/freepublish/submit?access_token={TOKEN}`
- **请求体：**


## 6. 同步到草稿箱 — 详细实现

### 6.1 单篇文章上传参数

```typescript
interface UploadArticleParams {
  title: string;
  coverImagePath: string; // 本地封面绝对路径
  contentImagePaths: string[]; // 需要上传到微信的正文本地图路径
  contentHtml?: string; // 可选：已排版好的 HTML（含本地路径）
  author?: string;
  digest?: string;
  contentSourceUrl?: string;
  picCrop2351?: string;
  picCrop11?: string;
}
```

### 6.2 批量上传参数 / 结果

```typescript
interface BatchUploadParams {
  appId: string;
  appSecret: string;
  articles: UploadArticleParams[];
  publish?: boolean; // 默认 false：只进草稿箱
}

interface ArticleUploadResult {
  title: string;
  draftMediaId: string;
  coverUrl: string;
  publishId?: string;
  publishError?: string;
}

interface BatchUploadResult {
  success: boolean;
  results: ArticleUploadResult[];
  error?: string;
}
```

### 6.3 批量上传伪代码（核心）

```typescript
async function batchUpload(params: BatchUploadParams) {
  // 1. Token
  const accessToken = await getAccessToken(params.appId, params.appSecret);

  const results = [];
  for (const [i, article] of params.articles.entries()) {
    // 2. 封面 → media_id
    const cover = await uploadCoverImage(accessToken, article.coverImagePath);

    // 3. 正文图 → url 列表（带 300ms 间隔）
    const contentResults = await batchUploadContentImages(
      accessToken,
      article.contentImagePaths,
    );

    // 4. HTML：本地路径 → 微信 URL
    let html = article.contentHtml
      ? replaceLocalPathsWithWechatUrls(article.contentHtml, contentResults)
      : buildSimpleHtml(
          article.title,
          contentResults.map((r) => r.url),
        );

    html = minifyHtml(html); // 压缩空白，减少微信侧异常空格

    // 5. 创建草稿
    const draftMediaId = await createDraft(accessToken, {
      title: article.title,
      thumbMediaId: cover.mediaId,
      digest: article.digest,
      content: html,
      contentSourceUrl: article.contentSourceUrl,
      picCrop2351: article.picCrop2351,
      picCrop11: article.picCrop11,
    });

    const item = {
      title: article.title,
      draftMediaId,
      coverUrl: cover.url,
    };

    // 6. 可选发布
    if (params.publish) {
      try {
        item.publishId = await publishDraft(accessToken, draftMediaId);
      } catch (e) {
        item.publishError = String(e);
      }
    }

    results.push(item);
    await delay(500); // 文章之间间隔
  }

  return { success: true, results };
}
```

### 6.4 HTML 本地路径替换（重点）

正文 HTML 在上传前使用 **本地路径**（或 `file://`）作为 `src`，上传后必须替换为微信 `uploadimg` 返回的 URL。

本项目替换顺序（**先长匹配 / file:// 变体，最后裸路径**，避免误伤）：

1. `file:///{encodedPath}`
2. `file://{encodedPath}`
3. `file:///{normalizedPath}`
4. `file://{normalizedPath}`
5. 原始绝对路径字符串

```typescript
// contentResults: { originalPath, url }[]
for (const { originalPath, wechatUrl } of contentResults) {
  const normalized = originalPath.replace(/\\/g, "/");
  const encoded = encodeURIComponent(normalized).replace(/%2F/g, "/");
  // 依次 split/join 上述几种变体...
}
```

**同步前前端还会：**

1. 从 HTML 提取本地图路径（`<img src>` + `background-image: url(...)`）
2. 与文章图片列表合并，作为 `contentImagePaths` 全部上传
3. 若存在 WebP 转换表 `webpConvertedMap`，同步前把 HTML 与路径中的 webp 换成 png 路径

### 6.5 HTML 压缩

```typescript
function minifyHtml(html: string): string {
  return html.replace(/>\s+</g, "><").replace(/\s+/g, " ").trim();
}
```

目的：减少微信后台展示时多余空白/`&nbsp;` 类问题（不完全消除微信侧二次处理）。

### 6.6 无自定义 HTML 时的兜底正文

```html
<section style="text-align:center;...">{标题}</section>
<p>
  <img src="{微信URL}" style="max-width:100%;display:block;margin:0 auto;" />
</p>
...
```

## 7. 本项目前端同步页调用链

```
SyncView.startBatchSync()
  → 取选中公众号 appId / appSecret
  → useWechatUpload.startBatchUpload(articles, { appId, appSecret, publish, webpConvertedMap })
      → 组装 UploadArticleParams（封面路径、正文图、digest、裁剪参数）
      → wechatBatchUpload(...)  // IPC → 主进程 batchUpload
      → onWechatUploadProgress 监听进度（token/cover/images/draft/publish/done）
```

### 7.1 进度事件结构

```typescript
interface UploadProgress {
  currentArticleIndex: number;
  totalArticles: number;
  step: "token" | "cover" | "images" | "draft" | "publish" | "done";
  message: string;
}
```

主进程通过 `event.sender.send('wechat:uploadProgress', progress)` 推送。

### 7.2 同步页前置校验

- 已选择公众号账号
- 至少选中 1 篇文章
- 每篇文章应有封面路径（推荐使用已生成封面 `generatedCoverImagePath`）

## 9. multipart 上传实现要点

微信素材接口要 `multipart/form-data`。Node 主进程无浏览器 `FormData` 时，可手写 boundary（本项目做法）：

```typescript
// field 名固定为 "media"
Content-Disposition: form-data; name="media"; filename="xxx.jpg"
Content-Type: image/jpeg
```

MIME 映射：

```typescript
{ '.jpg': 'image/jpeg', '.jpeg': 'image/jpeg', '.png': 'image/png', '.gif': 'image/gif' }
```

## 10. 迁到其他项目的最小实现清单

### 10.1 必做

1. 安全存储 `AppID` / `AppSecret`（不要写死在前端公开仓库）
2. 实现 Token 获取 + 缓存
3. 实现封面上传（`add_material`）
4. 实现正文图上传（`uploadimg`）
5. 实现草稿创建（`draft/add`）
6. 确保正文 HTML 中图片 URL 全部为微信返回地址

### 10.2 建议

1. 批量时限流（图 300ms，文 500ms）
2. WebP 预转换
3. 封面裁剪参数 `pic_crop_*`
4. 进度回调与失败重试（token 失效 `40001` 时清缓存重取）
5. IP 白名单运维说明

### 10.3 最小可运行示例（Node / 服务端）

```typescript
/**
 * 同步一篇图文到公众号草稿箱
 * @param appId 公众号 AppID
 * @param appSecret 公众号 AppSecret
 * @param article 标题、封面本地路径、正文图路径、HTML
 * @returns 草稿 media_id
 */
async function syncOneDraft(
  appId: string,
  appSecret: string,
  article: {
    title: string;
    coverPath: string;
    contentImagePaths: string[];
    contentHtml: string;
    digest?: string;
  },
): Promise<string> {
  const token = await getAccessToken(appId, appSecret);
  const cover = await uploadCoverImage(token, article.coverPath);

  const uploaded: { path: string; url: string }[] = [];
  for (const p of article.contentImagePaths) {
    const r = await uploadContentImage(token, p);
    uploaded.push({ path: p, url: r.url });
    await delay(300);
  }

  let html = article.contentHtml;
  for (const u of uploaded) {
    html = html.split(u.path).join(u.url);
  }

  return createDraft(token, {
    title: article.title,
    thumbMediaId: cover.mediaId,
    digest: article.digest ?? article.title,
    content: html,
  });
}
```

## 11. 常见错误码

| errcode          | 含义               | 处理                                |
| ---------------- | ------------------ | ----------------------------------- |
| `40001`          | access_token 无效  | 清缓存重新获取                      |
| `40164`          | IP 不在白名单      | 公众号后台加 IP                     |
| `41005`          | 媒体文件为空       | 检查本地文件是否存在/可读           |
| `40007`          | 媒体类型不合法     | 转 JPG/PNG/GIF，禁 WebP             |
| `45009`          | 接口调用超频       | 加大延时、降并发                    |
| 创建草稿相关错误 | content/封面不合规 | 检查 HTML、封面尺寸、thumb_media_id |

发布阶段若封面尺寸不合规，本项目会提示：**草稿已成功，可去公众号后台手动发布**。

## 14. 流程小结（给对接同学）

1. **设置公众号**：保存 AppID/AppSecret → 调 token 接口鉴权 → 存账号。
2. **准备文章**：标题、摘要、封面本地文件、正文 HTML、正文本地图列表。
3. **同步草稿**：token → 封面 `add_material` → 正文 `uploadimg` → 替换 HTML src → `draft/add`。
4. **验证结果**：用返回的 `media_id` 去微信公众号后台「草稿箱」查看。
5. **可选**：`freepublish/submit` 发布；失败不影响草稿存在。

按上述接口与顺序实现，即可在其他项目中复用本项目的「公众号设置 + 同步草稿箱」能力。
