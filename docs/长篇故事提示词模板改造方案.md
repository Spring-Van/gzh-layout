# 长篇故事 · 提示词模板体系改造方案（规划稿，未实施）

> 三项需求 + 四项已知问题修复 + 链路严谨化设计。
> 基线分析见《长篇故事提示词模板梳理.md》。
> 原则：**模板能配置的一切都不写死**；变量、协议、推荐文案各有单一事实来源；兜底行为可预测、全链路统一。
>
> **⚠️ 后续决策（2026-09-11）**：本文档中的「变量兜底策略」（`always` / `if-nonempty` / `drop`，见 1.2 与第 219 行）
> 已作废。最终采用**最简方案**：变量是否进入提示词完全由模板作者决定——模板里写了 `{{变量}}` 才替换，
> 没写的一律不出现，**不存在任何自动追加兜底**。相应地，各类型推荐模板与内置默认模板都必须自带全部变量
> （由单测 `推荐模板都显式插入了该类型的全部变量` 守卫）。

---

## 一、总体设计

### 1.1 现状问题（改造动机）

| 现状 | 问题 |
|------|------|
| 变量是英文（`{{chapter_content}}`） | 与中文模板语境割裂，作者需记映射 |
| 拼装逻辑分散在 4 个 service、6 个函数里 | 兜底语义三套并存（追加 / 任一变量即纯替换 / 占位文案），行为不一致 |
| 输出协议一半写死（分析/剧本/分镜/提取）、一半可自定义（资产/画面） | 自定义程度不统一 |
| 推荐模板散落两处（TemplateEditorForm 4 个 + chapterDocService 2 个） | 无单一事实来源；分镜推荐模板变量还写错了 |
| `{{style}}` 双重注入、`assetExtractionConfig` 残留、逐条路径缺 `{{target_model}}` | 已发现的缺陷 |

### 1.2 改造后的架构

```
┌─────────────────────────────────────────────────────────────┐
│ promptTemplateRegistry.ts（新建·单一事实来源）                 │
│  · VARIABLE_REGISTRY    每类型变量（中文名/说明/兜底策略/旧别名） │
│  · OUTPUT_PROTOCOLS     每类型默认输出协议（含推荐按钮文案来源）   │
│  · RECOMMENDED_TEMPLATES 每类型推荐模板（修复分镜模板变量错误）    │
│  · renderTemplate()     统一渲染引擎（替换/追加/占位/清理/迁移）   │
└──────────────┬──────────────────────────┬───────────────────┘
               │                          │
      ┌────────▼────────┐        ┌────────▼─────────┐
      │ 4 个 service     │        │ TemplateEditorForm│
      │ builder 只负责    │        │ 变量状态 tag 区     │
      │ 准备变量值 + 协议  │        │ 输出协议字段+推荐   │
      └─────────────────┘        └──────────────────┘
```

### 2.2 统一渲染引擎 `renderTemplate(type, content, values)`

规则（全链路唯一，替代现有三套逻辑）：

```
1. 归一化：旧英文占位符 → 中文占位符（legacy 别名表，兼容存量模板）
2. 逐变量处理：
   变量在模板中  → 原地替换；值为空 → 替换为该变量的 emptyText（见上表）
   变量不在模板中 → 按变量的兜底策略：
       · always      → 无条件追加【变量标签】块（关键输入：章节原文/漫画剧本/状态清单）
       · if-nonempty → 值非空才追加（辅助上下文：原文分析/风格上下文/分镜概要/已有资产…）
       · drop        → 不追加（增强信息：镜头/前文分镜/目标生图模型…）
3. 兜底信息块：若模板未使用本类型任何变量 → 追加类型级关键信息块
   （资产提示词=【待生成状态清单】；分镜画面=【当前分镜】序号/镜头/内容/参考描述）
4. 清理：移除模板中所有未注册的 {{...}} 占位符（防错插变量污染提示词）
```

**行为对照**（与现状的差异，均为修复性质）：

| 场景 | 现状 | 改造后 |
|------|------|--------|
| `{{风格上下文}}` 已插入且风格非空 | 替换后**又追加一次**（重复） | 只替换（问题②修复） |
| 模板只用了 `{{状态清单}}` 没用 `{{风格上下文}}` | 风格追加 | 风格追加（不变，if-nonempty） |
| 模板里误插了别环节的变量 | 原样发给模型 | 构建时清理；设置页红色警告 |
| 资产提取的分析/剧本/概要/已有资产 | 永远追加，作者无法控制位置 | 变量化，可插入也可不插（不插则按策略追加） |

## 三、输出协议体系（需求 3：字段化 + 推荐按钮，不再写死）

### 3.1 字段设计

`PromptTemplate.outputProtocol` 字段**扩展到全部 6 个长篇类型**（原先只有 asset-prompt / panel-prompt 有）：

- 设置页模板表单新增「输出协议」多行文本（位于提示词内容下方）；
- 旁附 **「填入推荐协议」** 按钮 → 填入该类型的默认协议（来源：注册表，与运行时兜底同一份文案）；
- 占位提示：「留空则使用系统默认输出协议」。

### 3.2 运行时优先级（统一为一条规则）

```
最终协议 = 模板自定义 outputProtocol（非空） ‖ 类型默认协议
```

- 类型默认协议 = 现在散落各 builder 里的系统固定输出协议，迁入注册表，文案不变；
- 资产提示词类型例外：按发送模式取默认 —— 批量一次性 = 可解析协议（【资产名｜状态名】逐条格式，保证回填解析）；逐条/单条 = 「只输出一段完整中文提示词正文」。自定义协议仍优先（解析失败时已有专门报错提示，保留）；
- 统一追加标签为 `【输出要求】`（原【系统固定输出协议】/【输出要求】两种标签合一）；
- 分镜画面描述原「无协议」状态改为默认协议「只输出一段完整、连贯的中文画面描述…」——结果本就全文回填，协议只会让输出更稳定。

### 3.3 各类型默认协议（迁入注册表，内容不变）

analysis / script / storyboard / extract：现有写死文案原样迁入；asset-prompt：`DEFAULT_ASSET_PARSE_PROTOCOL` + 逐条版；panel-prompt：新增一段式描述协议。

## 四、设置页 UI 设计（需求 2：变量状态字段）

### 4.1 「变量状态」区（TemplateEditorForm，提示词内容上方或下方）

```
变量状态
┌──────────────────────────────────────────────┐
│ [章节原文]  [原文分析]          ← 未使用：灰描边 │
│ ██████████  ┌─────────┐                       │
│ (已使用：青色高亮填充)                          │
└──────────────────────────────────────────────┘
⚠ 检测到不适配当前类型的变量：[章节原文] ← 红色警告 tag
提示：点击 tag 可插入到光标处
```

- 数据源：注册表 `VARIABLE_REGISTRY[当前类型]`；
- **高亮判定**：对归一化后的 content 做 `{{变量名}}` 存在性检测（归一化后旧英文模板也能正确高亮）；
- tag 悬浮 tooltip = 变量说明（注入什么内容、空值兜底文案）；
- **点击 tag → 插入到 textarea 光标处**（增强项，顺手实现）；
- 检测未知变量（content 中 `{{...}}` 不在本类型注册表内）→ 红色警告 tag + 一行提示「该变量不会在此环节生效，构建时将被清理」；
- `style`/`story` 类型显示「此类型模板无变量，内容将原样使用」。

### 4.2 表单字段顺序

模板名称+类型（现有）→ 类型用途提示条（现有）→ **变量状态（新）** → 提示词内容（现有）→ **输出协议（扩展到全部类型）+ 推荐按钮（新）** → 保存/重置。

## 六、存量兼容与迁移

1. **旧英文变量模板**：渲染引擎入口先做归一化（`{{chapter_content}}`→`{{章节原文}}` 等），存量模板不改也能正常工作；
2. **一次性数据迁移**：设置存储加载时检测含旧占位符的模板 → 归一化后回写库（无损、确定性替换）；运行时归一化保留作为兜底；
3. **outputProtocol**：旧模板该字段为空 → 自动落到类型默认协议，无需迁移；
4. **旧资产提取模板**：原本被强制追加的四个上下文块，改造后按 if-nonempty 策略追加——**默认行为完全不变**（模板没插变量时仍追加），只有作者主动插变量才改变位置。

## 九、风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| 存量模板含旧英文变量 | 低 | 双保险：运行时归一化 + 一次性迁移 |
| 分镜画面描述从「无协议」变「默认协议」 | 低 | 协议内容即现有内置模板的输出要求，只会更稳 |
| 资产提示词自定义协议与解析不匹配 | 低 | 保留现有专门报错；推荐协议按钮文案与解析器同构 |
| 一次性迁移回写用户模板 | 低 | 替换确定性无损；迁移前后留 diff 日志 |
| 删 assetExtractionConfig | 低 | 运行时从未消费，纯删字段 |

## 十、待确认决策点

1. **变量兜底策略**是否按本方案（关键输入 always / 辅助上下文 if-nonempty / 增强信息 drop）？另一选项是"没插就一律不追加"（更极简，但无变量老模板会丢关键输入）。

3. 推荐分镜模板文案重写（去掉出场资产指引）是否同步进行？
