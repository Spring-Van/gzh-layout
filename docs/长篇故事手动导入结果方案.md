# 长篇故事「手动导入结果」方案（外部 AI 代跑，规划稿）

> 状态：规划，未实施。需求背景：节约 token——在应用内拿到组装好的最终提示词 → 复制到外部 AI 生成 → 把结果粘贴回应用，走与内置 LLM **完全相同**的解析 / 审核 / 存储链路。

---

## 一、现状链路（4 个 LLM 环节一览）

| 环节 | 提示词组装 | 执行 | 解析 | 存储 | UI 入口 |
|------|-----------|------|------|------|---------|
| 原文分析 | `buildAnalysisPrompt` | `runChapterDoc` | 无（纯 Markdown） | `LongProjectChapterDoc`（chapterAnalyses） | 原文页签顶栏 PromptRunBar，产物显示在 SourceTab 右列 |
| 漫画剧本 | `buildScriptPrompt` | `runChapterDoc` | 无（纯 Markdown） | 同上（chapterScripts） | 剧本页签顶栏 PromptRunBar，产物在 ScriptTab 右列 |
| 分镜生成 | `buildStoryboardPrompt` | `generateStoryboard` | `parseStoryboardResponse` → panels | `LongProjectStoryboardRun.panels` + `panelArtworks` 迁移 | 分镜页签右列「分镜内容」PromptRunBar |
| 资产提取 | `buildAssetExtractionPrompt` | `extractChapterAssets` | `parseAssetExtractionResponse` → candidates → 人工审核确认 | `LongProjectAssetExtractionRun.candidates` → 确认后写资产库 | 分镜页签顶栏（资产子 tab），审核在 AssetExtractionReview |

**三个关键洞察**（决定方案形态）：

1. **提示词出口现成**：所有环节都有「发送前确认」弹窗（PromptPreviewDialog），里面就是最终提示词全文——只差一个复制按钮。
2. **分析/剧本无需解析**：产物是纯 Markdown 文本，手动写入 = 创建一份 `status: 'completed'` 的 doc，且两处右列本就有「编辑」能力（仅 completed 后显示）。
3. **分镜/资产解析函数可直接复用**：`parseStoryboardResponse` / `parseAssetExtractionResponse` 是纯函数（输入文本 → 输出结构），导入后进入既有审核/确认 UI，零新逻辑。

---

## 二、总体设计

```
┌─ 应用内 ────────────────────────────┐      ┌─ 外部 ──┐
│ ① PromptRunBar「复制提示词」          │      │         │
│    └→ PromptPreviewDialog（可编辑）   │ ──复制──→ │ 外部 AI │
│ ② 各环节「手动导入」按钮              │      │         │
│    └→ ManualResultImportDialog       │ ←─粘贴── │  生成   │
│         解析预览 → 确认导入           │      │         │
│ ③ 落库（source: 'manual'）           │      └─────────┘
│    └→ 后续链路与 LLM 路径完全共用      │
└─────────────────────────────────────┘
```

三个通用基建：

### 2.1 提示词出口（两处复制能力）

- **PromptPreviewDialog** footer 加「复制提示词」按钮（`navigator.clipboard.writeText`，项目内已有同款用法），复制后 toast，弹窗不关闭（可继续编辑再复制）。
- **PromptRunBar** 主按钮左侧加一个小图标按钮「复制提示词」：不弹窗直接复制 `buildPrompt()` 结果并 toast——覆盖「发送前确认」被关掉的场景。

### 2.2 统一导入弹窗 `ManualResultImportDialog`

一个通用组件，四个环节复用：

| props | 说明 |
|-------|------|
| `title` | 如「手动导入分镜」 |
| `formatHint` | 期望格式说明 = 该环节**系统默认输出协议**（registry 的 `defaultOutputProtocol`），外部 AI 用同一份提示词生成，返回自然符合格式 |
| `parse?(content)` | 可选解析函数：分镜/资产传入；分析/剧本不传（直接保存） |
| `placeholder` | 粘贴提示 |

交互为**两步式**（仅带 parse 的环节）：

1. 粘贴文本 → 点「解析预览」→ 弹窗内展示结构化摘要（分镜 N 个 / 资产 N 项，含逐条名称列表），解析失败红字提示、不落库；
2. 「确认导入」→ emit 确认事件（携原始文本），由调用方走落库逻辑。

文档类（分析/剧本）无第 1 步，直接确认保存。

### 2.3 溯源标记

- types 中 `LongProjectChapterDoc` / `LongProjectStoryboardRun` / `LongProjectAssetExtractionRun` 增加可选字段 `source?: 'llm' | 'manual'`（缺省视为 llm，旧数据零迁移）。
- 存储为 JSON blob 透传，**无 DB schema 变更**。
- UI 在各状态行显示「手动导入」小徽标（与「原文已变更」同款样式）。

## 三、各环节设计

### 3.1 原文分析 / 漫画剧本（直接写入）

- **入口**：顶部操作区 PromptRunBar 旁加「手动写入」次按钮（两个页签各一）；SourceTab/ScriptTab 右列**空态**内同步提供入口按钮（引导性更好）。
- **实现**：`useChapterDocRun` 增加 `importDoc(kind, { chapterId, content, sourceContent })`：
  - upsert 一份 doc：`status: 'completed'`、`content`、`modelId: ''`、`templateId: ''`、`prompt: ''`、`source: 'manual'`；
  - 复用现有 stage 推进逻辑（`stageOnComplete`，只升不降）。
- **覆盖语义**：每章一份 upsert，已有结果时弹确认「将覆盖本章已有分析/剧本」。
- 已有 completed doc 的微调用现有「编辑」即可，手动写入解决的是**从零创建**。

### 3.2 分镜（粘贴 → 解析 → 落库）

- **入口**：分镜页签右列「分镜内容」操作区，PromptRunBar 旁「手动导入」按钮；右列空态同步提供。
- **实现**：`useStoryboardRun` 增加 `importStoryboard({ content })`：
  1. `parseStoryboardResponse(content, assets, chapterId, chapterOrders)` → panels（「出场资产」行照常匹配资产库回填绑定）；
  2. 创建 run：`status: 'completed'`、`panels`、`rawResponse: content`、`modelId: ''`、`source: 'manual'`；
  3. `migratePanelArtworks(previousPanels, panels)`——旧分镜的已推导描述/成图迁移（与 LLM 重跑同语义）。
     归属判据：**同序号且正文逐字相同、且描述未被判过期**才继承；
     正文已变或描述已 stale 时描述只留在原记录上（不跟到新页，也不再参与绑定扫描），成图仍迁到新页；
  4. stage → `storyboard-ready`。
- **解析失败**（无 `## 分镜` 结构）：弹窗内红字，不创建 run。

### 3.3 资产提取（粘贴 → 解析 → 既有审核链路）

- **入口**：资产子 tab「信息」视图空态 + 顶栏提取操作区旁，「手动导入」按钮。
- **实现**：`LongProjectStoryboardTab` 增加 `importExtraction(content)`：
  1. `parseAssetExtractionResponse(content, assets)` → candidates（已有资产匹配/merge 建议照常）；
  2. `countCandidatesAppearances(candidates, panels)` 回填出现次数（与 LLM 路径一致）；
  3. 创建 run：`status: 'completed'`、`candidates`、`rawResponse: content`、`source: 'manual'`；
  4. **后续完全复用**：AssetExtractionReview 审核 → 「确认本章资产」写库 → 分镜绑定自动回填。
- **解析为 0 个候选**：弹窗内红字提示格式不符。

## 四、交互细节约定

- **格式提示即协议**：导入弹窗顶部展示该环节系统默认输出协议全文（折叠可展开），用户可对照检查外部 AI 返回是否符合格式。
- **覆盖确认**：目标章节已有同环节结果时 `window.confirm`；分镜覆盖时提示「已推导描述与成图将自动对位迁移」。
- **导入不需要选模型**：手动入口不依赖模型/模板下拉状态（模板选择仅影响复制出口的提示词组装）。
- **run 记录保留 prompt 字段为空**：手动路径没有真实发送行为，留空避免误导；`rawResponse` 存粘贴原文，可溯源。

## 六、风险与边界

| 风险 | 对策 |
|------|------|
| 外部 AI 返回不守格式 → 解析失败/解析残缺 | 两步式弹窗解析预览先行反馈，失败不落库；formatHint 展示协议全文供对照 |
| 覆盖已有结果丢数据 | 覆盖前 confirm；分镜走 panelArtworks 对位迁移；文档 upsert 前提示 |
| clipboard 在 Electron file:// 环境不可用 | 项目内已有 `navigator.clipboard.writeText` 用法（提示词模板页/分镜复制），沿用并保留失败 toast |
| 手动导入的资产绕过审核 | 不绕过：候选仍走 AssetExtractionReview 人工确认后才写库 |
| 与「重跑」语义混淆 | 手动导入生成的 run 与 LLM run 并列存于列表，徽标区分，互不干扰 |

## 七、待确认决策点

1. **PromptRunBar 常驻复制小按钮**：不弹窗直接复制最终提示词（推荐做，覆盖「发送前确认」关闭的场景）。
2. **分析/剧本入口位置**：顶栏执行区旁 + 右列空态双入口（推荐），还是只做其中一处？
3. **「手动导入」徽标**：所有 run/doc 状态行显示（推荐，成本极低），还是不做展示仅存字段？
