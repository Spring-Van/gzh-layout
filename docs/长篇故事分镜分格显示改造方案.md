# 长篇故事：分镜「分格可见性」改造方案

> **一句话**：分镜解析出来后，**到处都要看得见"这页是几格"**——列表、预览、内容区；
> 同时把**台词 / 旁白用【】包起来**，让台词行和画面行在纯文本里一眼可分。
> 本文只管方案与取舍。**§1（输出协议 + 模板 + 解析/序列化）已于 2026-09-10 落地**；§2~§4 的界面改动待拍板。

---

## 0. 问题盘点：现在哪 4 个地方"看不见分格"

| # | 界面 | 现状 | 分格可见吗 |
|---|------|------|-----------|
| ① | **手动导入 · 解析预览** | `分镜 1：角色A指节收紧，关键道具缠上小臂。…`（只截 `panel.content` 前 40 字） | ✗ 完全看不见 |
| ② | **左栏分镜列表** | `P01 ● 已成图` + 第二行＝一行文字预览（首句台词 / 首格画面） | ✗ 看不见，且白占一行 |
| ③ | **右栏内容编辑区** | 单一 textarea，整页页块文本 | △ 只有 `①②③` 符号，没有"分格"这件事的视觉存在 |
| ④ | **生成完成后的反馈** | 无（只有列表变长） | ✗ 不知道生成了几页、每页几格 |

另有 1 个格式问题：**台词行与画面行长得太像**，纯文本里要靠"有没有冒号"去认。

---

## 1. 改造点一：输出协议——台词 / 旁白用【】包起来 ✅ 已落地（2026-09-10）

### 1.1 改前 / 改后

```markdown
# 改前
## 分镜 1 · 双格
①【近景】角色A指节收紧，关键道具缠上小臂。
角色A：破坏了它的关键部分，跟要了它的命有什么区别？
②【中景】角色B站在沙发边，眉头拧起。
角色B（心声）：他到底想干什么
旁白：夜色压下来，屋里的灯忽然灭了
```

```markdown
# 改后（台词正文加【】，说话人仍在括号外）
## 分镜 1 · 双格
①【近景】角色A指节收紧，关键道具缠上小臂。
角色A：【破坏了它的关键部分，跟要了它的命有什么区别？】
②【中景】角色B站在沙发边，眉头拧起。
角色B（心声）：【他到底想干什么】
旁白：【夜色压下来，屋里的灯忽然灭了】
```

### 1.2 候选写法与取舍

| 方案 | 写法 | 解析安全性 | 结论 |
|------|------|-----------|------|
| **A1 只括台词正文** | `角色A：【台词】`<br>`角色B（心声）：【台词】`<br>`旁白：【文字】` | ✅ 安全：`【` 不在行首，不会被解析器当成镜头 / 字段行 | **推荐** |
| A2 括说话人 | `【角色A】破坏了它的关键部分…` | ❌ **危险**：解析器 `BRACKET_RE` 只认"行首【】"，会把它当成 `【镜头】`，`角色A` 会被写成镜头名并**新开一格**，整页错位 | 否决 |
| A3 换中文引号区分 | `角色A：「台词」` | ✅ 安全 | 用户明确要【】，且引号在纯文本里易与排版混淆 | 否决 |
| A4 台词 + 情绪双标 | `角色A：【台词】` + `〔心声〕` | ✅ | 冗余，`（心声）` 已有位置 | 否决 |

### 1.3 关键设计：**入库去括、出库带括**

【】是**排版层**的记号，不属于数据。所以：

- **解析**（`parseStoryboardResponse` / `parsePanelBlock`）：说话人行剥掉台词首尾的【】→ 存进 `cell.dialogue` 的是**干净文本**；
- **序列化 / 展示**（`serializePanelBlock`、页块文本、协议示例）：输出时补上【】；
- **页级汇总**（`summarizeCells` → `panel.dialogue`）**保持不带括号**——这个字段要喂给下一环节的画面描述提示词，带上【】会污染生图提示词。

> 一句话：**对用户和模型看得见的文本带【】；程序内部消费的字段不带。**

### 1.4 兼容性

- 解析器对**没有【】的台词行照旧工作**（正则把括号设为可选组）→ 旧 run、旧模板、旧粘贴文本都不需要迁移；
- 旧数据序列化时自动补上【】，等于"打开即升级"；
- 顺手硬化一处隐患：v2 行内分格兜底（`｜` / `‖`）判定收紧——现在只要行里出现 `｜` 或 `|` 就按 v2 拆格，台词里偶尔出现 `｜` 会误拆。加【】后更需要在剥括号**之后**再判定。

## 2. 改造点二：左栏列表——第二行换成分格信息

### 2.1 改前 / 改后

```
改前                              改后（推荐 L2）
┌──────────────────────┐         ┌──────────────────────┐
│ ▢ P01 ● 已成图        │         │ ▢ P01 ● 已成图        │
│   角色A：破坏了它的关键部分… │         │   3 格 · 近景/中景/特写│
└──────────────────────┘         └──────────────────────┘
```

### 2.2 候选方案

| 方案 | 第二行 / 布局 | 优点 | 缺点 |
|------|--------------|------|------|
| L1 只放格数 | `3 格` | 最贴字面、最简 | 一行只放 2~3 字，略空 |
| **L2 格数 + 各格镜头** | `3 格 · 近景/中景/特写` | 用满这行；一眼看出节奏（镜头组合）；仍不含"内容" | 4 格页可能被截断（`truncate` 处理） |
| L3 格数挪到第一行右对齐，去掉第二行 | `P01 ● 已成图      3 格` | 视觉最干净 | **并不省空间**：行高由左侧缩略图 `48px` 决定，删掉第二行行高不变，白白少一条信息 |

> **行高真相**：列表项高度 = `缩略图 48px` + 上下 padding，不是文字撑起来的。
> 所以"去掉第二行能省空间"不成立——第二行是**免费的**，应该拿它放有用信息。

**推荐 L2**。格数用阿拉伯数字 `3 格`（列表要快扫）；页头仍保留 `单格 / 双格 / 三格 / 四格` 的说法（协议不变）。空白页第二行显示 `空页`。

## 3. 改造点三：右栏内容区——让"分格"在内容里看得见

### 3.1 这里是本次唯一的真冲突，先说清楚

| | 之前定下的规矩 | 这次的新诉求 |
|---|---|---|
| 右栏 | **单一输入框**，内容 = 页块文本，**与生成格式 / 可复制格式完全一致**（所见即所得，直接改） | **内容里面也要展示对应的分格** |

两个诉求本身有张力：**要"单一输入框 → 所见即所得"，就注定分格只是文本符号；要"分格成为看得见的容器"，就得把输入框拆成多个块。** 所以下面给三档，从轻到重。

### 3.2 候选方案

| 方案 | 做法 | 分格可见度 | 保留单一输入框 | 工作量 |
|------|------|-----------|--------------|--------|
| **C1 单框 + 格间空行 + 顶部格导航** | 序列化时格与格之间插入空行；编辑框上方加一条只读导航条 `① 近景 · ② 中景 · ③ 特写`，点击滚动定位到对应格 | 中 | ✅ 完全保留 | 小 |
| C2 只读分格预览 + 编辑框 | 编辑框上方多一块只读渲染（① 徽标 + 镜头 + 画面 + 台词行），下方仍是原 textarea | 高 | ✅ 保留 | 中（内容双份，需实时同步） |
| **C3 分格视图 ⇄ 原文视图 切换** | 默认「分格视图」：每格一张紧凑卡片（`①` 徽标 / 镜头 / 画面 / 台词 / 旁白，可直接改、可增删格）；右上角一键切「原文」＝现在的单框 | 最高 | △ 原文视图仍在，但默认不再是它 | 大 |
| C4 格徽标 gutter | textarea 左侧按行对齐渲染 `①②③④` 徽标 | 中 | ✅ 保留 | 大且脆（textarea 软换行会错位，对齐不可靠） |

**推荐 C1**：成本最低、不破坏既有心智（所见即所得 + 与生成格式一致），且"格间空行 + 导航条"已经足够让分格在内容里站住。
若你需要**在内容区逐格编辑**（改某格镜头、单独删一格台词），那要上 C3——这是另一档投入，建议先做 C1 用一阵再决定。

### 3.3 C1 的具体形态

```
┌─ 分镜内容（剧本 → 分镜）          12 页   [分镜内容|提示词] ┐
│  ① 近景 · ② 中景 · ③ 特写                 ← 只读格导航（可点） │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ ①【近景】角色A指节收紧，关键道具缠上小臂。                    │ │
│ │ 角色A：【破坏了它的关键部分，跟要了它的命有什么区别？】            │ │
│ │                                                          │ │
│ │ ②【中景】角色B站在沙发边，眉头拧起。                      │ │
│ │ 角色B（心声）：【他到底想干什么】                          │ │
│ │                                                          │ │
│ │ ③【特写】关键道具表面在灯下泛冷光。                        │ │
│ │ 旁白：【夜色压下来，屋里的灯忽然灭了】                      │ │
│ └─────────────────────────────────────────────────────────┘ │
│  本页操作                    分镜 1 · 3 格 · 修改自动保存 [AI 优化]│
└──────────────────────────────────────────────────────────────┘
```

- 格与格之间空一行：解析器本来就**跳过空行**，零解析风险；复制出去的页块文本也更透气；
- 导航条纯只读，不参与编辑，点击把光标/滚动定位到对应格（按行号计算，不改内容）；
- 底部「本页操作」已有 `分镜 N · 3 格`，与导航条互相印证。

## 4. 改造点四：解析预览 / 生成反馈带上分格

### 4.1 手动导入 · 解析预览

```
改前：分镜 1：角色A指节收紧，关键道具缠上小臂。…
改后：分镜 1 · 双格：①近景 角色A指节收紧… ②中景 角色B站在沙发边…
```

- 标题从 `解析到 N 个分镜` 升级为 `解析到 N 页 · 共 M 格（单格 a / 双格 b / 三格 c / 四格 d）`；
- 每项摘要 = 页号 + 格数 + 每格「镜头 + 12 字画面」，让用户**确认分格拆得对不对**再导入——这正是导入预览存在的意义。

### 4.2 生成完成后的反馈

现在生成成功没有任何反馈，列表"突然变长"。建议补一句 toast：

```
已生成 12 页分镜（单格 3 / 双格 6 / 三格 3，共 27 格）
```

失败与手动导入维持现有反馈不变。

## 7. 明确不做的

- **不动页头格式** `## 分镜 N · 双格`（解析器与既有数据全靠它）；
- **不动 `①②③④` 格号**（协议、解析、`cells[]` 索引一一对应）；
- **不改数据模型**：`cells[]` 结构不变，只改"进出文本的包装"；
- **不做自动重排 / 重分格**：分格是模型与人的创作决定，本次只做"看得见"。
