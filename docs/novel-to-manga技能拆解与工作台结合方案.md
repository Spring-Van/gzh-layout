## 一、结论速览

1. **它不是提示词库，是一套「一致性工程规范」。** 真正值钱的不是那几千字提示词，而是把「角色一致性」落成了三样**可校验**的东西：ID 引用（`CHAR-林晚-三视图`）、状态矩阵（形态级 ✅/❌）、每页参考图清单（机读 + 缺图即停）。
2. **你的基础设施比它强。** 它是「文件目录 + 人工比对」，你是「数据库 + 程序推导」：`buildPanelRefManifest` 纯函数实时算图号、`syncPanelsAutoBindings` 自动推导状态绑定、资产跨章复用 —— 这三样它都没有，是它的天花板。
3. **真正的差距只有 6 条**：4 条**零代码**（改共用属性块 / 推荐模板文案），2 条需要小改代码。
4. **有 1 处正面冲突**：它的「留白属性禁止自动补全」正面对上你的「全维度脑补、不留空白维度」。不是谁错，是**诉求不同** —— 建议按「结构性留白 vs 身份性留白」切开处理（§四）。
5. **有 1 个必须先验证的坑**：把它的「节拍表先行」直接塞进 storyboard 输出，会**凭空多出一页**（`STRUCTURAL_RE` 认 `#{1,6}`，见 §5.3 与 C3）。
6. **有 1 个它提醒得很及时的风险**：你的参考图**发送前没有压缩**，而分镜成图单张 3~11MB —— 参考图数量一旦上去就是 413（见 C4）。

## 二、它是怎么生成漫画的

### 2.1 管线：四阶段串行 + 三个硬停靠

| 阶段 | 范围 | 做什么 | 产出 | 停靠 |
|---|---|---|---|---|
| S1 | 全书一次，跨章复用 | 读全书，拆人物 / 场景 / 世界观，定画风基因 | `设定总表.md`、`角色出场总表.md`、`伏笔与关键道具表.md` | 确认设定与画风才进 S2 |
| S2 | 首次建立 + 按需补 | 生成人物 / 场景设定图 | `设定图/人物/*.png`、`设定图/场景/*.png` | 用户过目，不满意重 roll |
| S3 | **单章** | 节拍表落盘 → 拆漫画分镜 → 检查清单落盘 | `节拍表.md`、`分镜脚本.md`、`检查清单.md`、`prompts/CH001-P001.md` | 确认分镜才批量出页 |
| S4 | **单章** | 逐页生成漫画（按清单传参考图 + 文字内嵌） | `03-漫画页/CH001/CH001-P001.png` | 出前校验参考图，**缺图即停** |

**关键约束**：一次只做一章，做完停靠，不自动续下一章。设定（S1/S2）是基建，跨章复用。

### 2.2 目录即数据库，ID 即外键

- 人物设定图：`CHAR-<角色名>-三视图 | 表情集 | <服装/状态变体>`
- 场景设定图：`LOC-<场景名>-<视角或时段>`
- 分镜格：`CH001-G03-02`（第 1 章第 3 页第 2 格）
- 漫画页：`CH001-P003`

一旦建立不得改名，跨文档引用全靠它。`生成日志.md` 记录每张图的提示词 / 参考图 / 状态 → 断点续跑依据。

### 2.3 九个真正有含金量的机制

| # | 机制 | 解决什么 | 一句话做法 |
|---|---|---|---|
| 1 | **前瞻阅读** | 防张冠李戴（外形相似 ≠ 同一人） | 做第 N 章前至少读到第 N+20 章；身份以「首次点名章节」为准，点名前挂「待确认」 |
| 2 | **描述考古** | 设定图提示词的事实来源 | 出图前用本名+别名+代称+变身名全文检索，汇总成「描述档案」，每条标章节出处 |
| 3 | **留白拍板** | 防模型静默编设定 | 原著未写的属性标「留白」→ **出图暂停** → 提交「补全决策表」（设计依据 / 剪影冲突检查 / 连带重 roll 范围 / 不采纳后果）→ 用户拍板 |
| 4 | **设定图先行且精确到形态** | 一致性锚点缺失 | 每个角色的每个形态是独立出图需求，总表里角色级一个 ✅ 不代表形态齐 |
| 5 | **检查清单机读 + 缺图即停** | 防「这页应该没差」 | 每页列出引用的全部设定图 ID；S4 按清单传图并逐项比对，清单有而未传 = 违规，停 |
| 6 | **场景 3×3 机位图** | 空间一致性 | 量化触发（单章 ≥2 页出镜 / 跨章复用 / 有俯仰反打）→ 出九宫格，每格一个不重复机位并标 1–9 |
| 7 | **风格基因五维 + 去 AI 味** | 千篇一律的 AI 感 | 从小说自身四维推导：线条 / 上色 / 色彩 / 构图气质 / 媒介质感；负面清单（禁 masterpiece / 8k / 泛风格词）+ 不完美注入 + 媒介质感锚；**彩漫/黑白漫必须用户选定** |
| 8 | **节拍表先行** | 页数是节拍的输出，不是输入 | 先落盘逐拍表（拍号/类型/内容/预计格数），再定页数；高潮展开成最小节拍，伏笔两端都要有画面 |
| 9 | **页级重生 + 错误类型决策表** | 提高单页返工效率 | 先改 `prompts/CH001-P001.md` 再单页重生；错误分类处置（角色错 → 整页重 roll；文字错 → **先确定性修字**再抽卡；光影 → 局部编辑；版式崩 → 整页重 roll） |

### 2.4 它的「一致性铁律」六条

1. 设定图先行且精确到形态
2. 身份核实先行（后文才揭示的身份不得提前使用）
3. 每页必带参考，清单机读、禁止手工凭记忆配图
4. 伏笔必须闭环（埋设页画「藏」，回收页画「取」）
5. **文字逐字**：台词旁白原文逐字入提示词；禁止自创台词；**禁止 ①②③④ 序号徽章入画**
6. 画风基因唯一，所有出图提示词原样复用，禁止逐页即兴改风格

### 3.5 参考图绑定（你最关心的一环）

**它的做法**：S3 分镜定稿时，把每页引用的资产 ID 汇总写进静态 `检查清单.md`；S4 生成前**按清单传图并逐项比对**，清单有而未传 = 违规 → 停。
排序规则：角色专属设定图 > 全员图 > 场景/机位图；`CHARACTERS-全员.png` 恒定图 1。

**你的做法**：三条独立通道 + 一个唯一实现

```
文本（blockText）──扫描资产名──▶ assetBindings（model / chapter-range / auto-text / manual / unmatched）
                                       │
                                       ├─ resolvePanelAssetStates（页级 ∪ 格级展开，按 资产::状态 去重）
                                       └─ resolvePanelRefImage（每状态 1 张：手选 > 第一张 > 无）
                                       ▼
                              buildPanelRefManifest（图号唯一事实来源）
                                       ▼
                         composeFinalPrompt「图N = 资产名（状态）+ 用途句」
                                       ▼
                            imageGenerationService（images 数组）
```

| 维度 | 它 | 你 | 判断 |
|---|---|---|---|
| 绑定来源 | 分镜里手写 `CHAR-林晚-三视图` ID | **文本即事实**：扫资产名自动绑 + 状态自动推导（延续上一镜 → 章节范围默认 → 首个状态） | **你的更强** |
| 图号 | 人工维护 | 纯函数实时算，与实发数组同序 | **你的更强** |
| 用途声明 | 提示词里手写一句 | `refUsage.ts` 模板化，按类型+格号，三级回落（资产 → 项目 → 内置） | **你的更强** |
| **缺图门禁** | **缺图即停**（S3 不算完成，禁止进 S4） | 无图只显示灰字「无参考图」，**不拦** | ⚠️ **你的唯一实质缺口** |
| 多图锚点 | 不设上限，靠裁切合并控体积 | **每状态单选 1 张**（`resolvePanelRefImage` 五处消费锁定） | 各有取舍，见 C2 |
| 体积控制 | 参考图统一压缩 ≤1152px JPEG 防 413 | **无压缩**，分镜成图单张 3~11MB | ⚠️ 真实风险，见 C4 |

## 四、一处正面冲突：脑补 vs 留白

### 4.1 冲突事实

| | 你的 extract 模板（`promptTemplateRegistry.ts`） | 上游技能 |
|---|---|---|
| 原文 | 「原文未提及或描述模糊的视觉细节，必须基于上下文、时代背景与物理合理性脑补补全，**不留空白维度、不遗留空白**」 | 「原著未描写的属性在描述档案中标注**留白**，**出图暂停**，由用户拍板后才可写入」 |
| 附带禁令 | 无 | **禁止循环锚定**（不得以「与已生成页面一致」为补全依据）+ **禁止静默补全**（哪怕标注了「补全」也算违规，未经用户拍板即违规） |

### 4.2 根因分析

两者诉求不同，不是谁错：

- **你要的是「信息完整度」** —— 你的下游是「仅凭这段描述就能单独出设定图」，描述留白 = 出图摆烂（模型自己乱填，且每张填得不一样）。这个诉求是对的。
- **它要的是「身份正确性」** —— 它的血泪案例是：某角色原生发色原著留白，早期无参考图时代的页面误借了另一个角色的配色，设定图反向锚定后**两个角色剪影相撞、整批资产返工**。它怕的不是空白，是**空白被错误信息填满并被固化**。

**结论：两者可以同时成立，只要按「留白的性质」分类。**

### 4.3 化解方案：结构性留白 vs 身份性留白

| 类别 | 对应 extract 的维度 | 处置 | 理由 |
|---|---|---|---|
| **结构性留白** | 场景的空间布局/材质/磨损；道具的表面纹理/细节；人物的服装面料纹理、褶皱、妆造 | **继续脑补**，且要求写具体 | 脑补错了也只是「这张图不好看」，重生成即可，不会污染身份 |
| **身份性留白** | 人物的 **体型体态 / 脸型 / 五官与瞳色 / 发型发色 / 肤色质感**、**标志性配饰与固定疤痕**；场景的**固定光源色温** | **脑补但必须显式标注 + 给候选**，让审核页能审 | 这些是**跨页识别的唯一依据**，错了会串脸、串角色，且会通过设定图反向固化 |

**关键判断：你已经有「人工确认」这道闸门（审核页 → 确认落库），缺的不是门禁，是把「脑补」与「原文事实」在审核页上区分开。** 现在两者混在「视觉描述」一行里，用户审不出来。

具体做法（模板级，见 B1）：身份性留白按它的「补全决策表」四要素输出 —— **设计依据 / 剪影冲突检查（与已出场角色逐一对错）/ 采纳后的连带返工范围 / 不采纳的后果**。

### 4.4 顺带一条：防误合并

`matchVariantForState` 第 ④ 档「双向包含」是已知的模糊匹配风险。上游技能从**视觉**角度补了同一条：**外形相似 ≠ 同一人（同配色 + 同道具可能属于两个角色）**。对应到你的链路：模型的 `别名` 字段直接决定 `matchExistingAsset` 是否命中 → 建议在 extract 模板里加一条：**身份未点名的角色（代称角色）不得填写指向已有资产的别名，状态标签必须含「待确认」**。

## 八、要不要做「全书拆解」？（章级拆解 vs 全书拆解）

### 8.1 结论

**不需要「全书拆解」这个动作，但必须补「全书视野」。**
一章一章拆是对的（比它的全书拆更贴合你的架构）。真正的漏洞不在**拆的粒度**，而在**跨章一致性信息在你的管道里被截断了**。

### 8.2 为什么在它的体系里 S1 全书拆解是必须的

它的产物是**文件**，没有数据库。所以它必须在第一次就把全书读一遍：

- 它没有「资产库」这种东西，`设定总表.md` 就是唯一事实来源，落盘一次后所有阶段只读它；
- 它没有跨章匹配算法，靠人眼比对《角色出场总表》的逐章矩阵；
- 它的设定图是文件，靠路径引用，没有「同一视觉状态被多章共享」的概念。

**它的 S1 是「用一次昂贵的全书阅读，换取后续所有章的一致性基准」。** 这个交易在你的架构里不成立，因为你已经有基准了。

### 8.3 你有等价物，而且更强

| 它做 S1 想拿到的东西 | 你的等价物 | 判断 |
|---|---|---|
| 跨章复用设定 | 资产库 + `matchExistingAsset`（name/aliases 归一化匹配） | ✅ 更强（自动） |
| 全局画风统一 | 项目级共用属性块 `imageGenConfig.sharedBlocks` | ✅ 更强（全局生效、改一次全章生效） |
| 跨章状态延续 | `variants[].chapterRange` / `firstAppearanceChapterId` + `syncPanelsAutoBindings` 章节范围默认 | ✅ 更强 |
| 知道全书有哪些角色 | 资产库列表（含 `scope:'project'`） | ✅ |
| 设定图状态矩阵 | `assetUsageService.buildAssetUsageIndex`（被 N 章 · M 镜引用） | ✅ 更强（自动统计） |
| **身份不提前绑定** | ❌ 无 | ⚠️ 真缺 |
| **剪影 / 体型互相对错** | ❌ 无 | ⚠️ 缺 |
| 伏笔闭环 | ❌ 无（属分镜层，与拆解粒度无关） | 缺，但不影响本议题 |

**它 8 项价值里，只有 2 项你没有；而剩下 6 项你已有的版本都比它强。** 为了这 2 项去背「全书一次拆」的全部成本，不划算。

### 8.4 你真正的风险：每章都在重写已有资产的描述，而模型看不到原描述

这是「一章一章拆」的结构性代价，**不在你现有的风险清单里**。三条证据：

| # | 位置 | 事实 |
|---|---|---|
| 1 | `assetExtractionService.ts:332-343` | 「已有资产」上下文的序列化是 `- 林晚（人物；已有视觉状态：便装（<锚点前 30 字>））` —— **不含 9 维外观描述、不含资产级 description**，且锚点被截断到 30 字 |
| 2 | `assetExtractionConfirm.ts:123-124` | `content: candidate.content \|\| acc.content \|\| candidate.description`、`description: candidate.description \|\| acc.description` —— **候选优先覆盖** |
| 3 | `assetExtractionConfirm.ts:108` | `description: state.description \|\| existing.description` —— 状态级视觉描述同样**候选优先覆盖** |

**合成后果**：第 5 章重新提取「林晚」→ 模型只看到名字与状态名，看不到第 1 章那份 9 维描述 → 基于第 5 章原文**重新脑补**一套 9 维 → 覆盖第 1 章那份**已被用户审过**的描述 → **描述漂移，且界面上看不出来**。

你已知的两条跨章风险（模糊匹配误合并、确认会删本批未出现的旧状态）之外，这是**第三条**，而且是最隐蔽的一条。

### 8.5 四个方案对比

| 方案 | 做什么 | 拿到什么 | 成本 / 风险 | 推荐 |
|---|---|---|---|---|
| **A 全书一次拆** | 像它那样第一次读全书建总表 | 身份防错、剪影对错 | ❌ 你的 extract 产物天然带 `chapterId` / 章节范围 / 章节引用，全书一次拆会产出**没有章节归属**的资产，与 `buildExtractionConfirmResult`（按章清空重建引用）直接冲突；一次失败全废；token ≈ 全书原文 ×1；UI 按 `node.stage` 推进，没有对应停靠点 | **不做** |
| **B 章级拆解 + 描述固化** | 不新增动作，只堵住「覆盖」这个口子（见下） | 描述不再漂移 | 低，两处代码 + 一条回归测试 | **推荐** |
| **C 轻量「全书索引」** | 纯函数从现有数据派生「角色 × 章节出场矩阵」 | 身份防错、剪影对错 | ≈0（无 LLM） | **推荐** |
| **D 按需前瞻阅读** | 做第 N 章时真读第 N+1~N+3 章原文 | 身份防错（最强） | 中；前提是用户已录入后续章节，成本随章数线性上升 | 可选，作 C 的补充 |

### 8.6 方案 B 的三个子项

| 子项 | 做什么 | 落点 | 说明 |
|---|---|---|---|
| **B1** | 「已有资产」上下文从「锚点前 30 字」扩成「状态名 + **完整视觉描述**」（或截 300 字） | `buildAssetExtractionPrompt`（`assetExtractionService.ts:332-343`） | 让模型**真能看到**原描述，才谈得上沿用 |
| **B2** | 确认落库时，命中已有资产 → 资产级/状态级描述**保留旧值**（改「候选优先」为「命中则保留」），本轮重写的版本只作为审核页对照 | `applyCandidatesToAsset`（`assetExtractionConfirm.ts:105-128`） | 让模型**改不动**已被审过的基准 |
| **B3** | 最小改动兜底：模板要求「已存在的资产只输出状态增量，描述行写 `沿用已有`」，解析端识别该标记 → 不覆盖 | `extract` 推荐模板 + `assetExtractionParser` | 只做 B3 依赖模型自觉，不如 B1+B2 稳 |

> **B1 与 B2 是一对**：只做 B1 = 覆盖变准了但还在覆盖；只做 B2 = 模型在看不到原描述的情况下被要求「沿用」（做不到）。
> **B2 的语义取舍**：改为「命中则保留」后，**真的需要修改外观设定的场景**只能走「在审核页手工改 / 或删掉旧状态重建」。这是刻意的 —— 已有资产的设定描述一旦被用户审过，就是基准，不该被下一次提取顺手改掉。

### 8.7 方案 C 的实现要点

- **输入**：节点树（章节顺序 + 名称）＋ `assets` ＋ `chapterAssets` ＋ `variants.chapterRange`／`firstAppearanceChapterId`
- **输出**：角色 × 章节出场矩阵（✅ / 空），每行附「该角色各视觉状态 + 是否已出图 + 被几镜引用」
- **落点**：资产区顶部一个可折叠表格；`assetUsageService` 已在算类似引用统计，扩一个「按章节维度」的输出即可
- **用途**：① 新出现一个无名角色时，人工核对是否已有人物（替代它的《角色出场总表》）；② 两个角色的剪影 / 体型是否撞（人工对错，机器给不了判断但能给齐信息）
- **成本**：≈ 0，无 LLM 调用

### 8.8 方案 D 的触发条件（如果要做）

章节原文都存在 `LongProjectNode.content`，所以「做第 N 章时读第 N+1~N+3 章」技术上**可行**。但必须：

- **不默认开**：只在提取结果里出现**「身份未点名的代称角色」**时提示「是否读取后续 N 章原文以确认身份」，按需 1~3 章；
- **前置校验**：后续章节未录入时不可用（要显式告知，不能静默降级）；
- **不做 N+20**：它的「读到第 N+20 章」是为全书拆解服务的，你按需读 3 章已能覆盖绝大多数「后文才点名」的场景。

### 8.9 本章一句话

**你的「设定总表」就是资产库。缺的不是拆解动作，是让它成为唯一事实来源 —— 现在每章提取的结果都在覆盖它。**

## 九、管线前两环要不要参考它？（原文分析 / 漫画剧本）

### 9.1 先认清一个事实：它没有这两个环节

上游管线是 **原文 → S1《设定总表》 → S3 分镜 → S4 出页**。它把「读原文」和「建资产」压进同一个 S1，
产物是全书一份的《设定总表.md》；**没有独立的「原文分析」，更没有「漫画剧本」** —— 原文直接进分镜。

所以这两环的答案不一样：

| 环节 | 上游有没有等价物 | 能抄什么 |
|---|---|---|
| **原文分析**（`analysis`） | 有功能等价物（S1 里「通读原文 + 建卡」那一半），但组织方式不同 | **能抄字段清单** |
| **漫画剧本**（`script`） | **没有**（原文直连分镜） | **只能抄纪律，抄不了结构** |

### 9.2 原文分析：5 条值得补，其中 3 条是真实缺口

你现在的模板（`RECOMMENDED_TEMPLATE_BASE.analysis`，`promptTemplateRegistry.ts:264-286`）是 8 个小节：
人物／场景／道具／事件与时间线／人物关系／对白／情绪／重要视觉信息。逐条对照上游 `analysis-guide.md`：

| 上游字段 | 你的现状 | 判断 |
|---|---|---|
| **世界观背景：影响画面的硬规则要显式写出**（例："此世界无热兵器""灵力可见为青色光纹"） | **完全没有这一类** | ⭐ 补（本表最高价值） |
| 人物卡「外貌锚点」：发型发色、眼、体型、年龄感、肤色，**具体到可画** | 「重要视觉信息：…可直接入画的信息」—— 一句话，无维度 | ⭐ 补：升级为维度清单 |
| 人物卡「服装：主造型 + 场景变体」 | 笼统含在「服装」二字里 | 合并进上一条 |
| 人物卡「气质：性格如何体现在表情、站姿、习惯动作」 | 无 | 补（"可画"的关键来源） |
| 场景卡「空间结构：布局、标志物、进出动线」 | 「场景：含空间特征与氛围」—— 有但粗 | 补：拆出空间结构 |
| 场景卡「光线时段：日/夜/黄昏；主光源」 | 无独立维度 | 补 |
| 人物分级（主要角色 / 次要角色 / 群演） | 「人物：有姓名或明确身份的全部角色」—— 无分级 | 补（与 `extract` 的「重要性」字段对齐） |
| 溯源：每个关键设定标注出处章节 | 已有（「每条信息标注出处要点」） | 保留不动 |

另外两条来自它**另外两份指南**，命中你没意识到的缺口：

**① 代称 / 身份未点名的角色，你现在是漏掉的。**

你的「人物」口径是「**有姓名或明确身份**的全部角色」—— 于是「那个蓝发少女」「少年」「神秘救场者」
这类**无名角色会被直接排除在分析之外**。而上游 `character-tracking-guide.md` 把它列为头号事故源：
外形相似 ≠ 同一人，点名文本出现前只能挂「待确认」，因为一旦提前绑定错误身份，
返工成本是**整页作废 + 重 roll 设定图**，且当章内看不出来。

→ 改法：「人物」口径扩成「有姓名、有明确身份、**或有无名代称的角色**」，并单列一节
「待确认角色」（代称／首次出场方式／为何存疑）。这一条与 8.8 方案 D 的触发条件是同一个东西。

**② 伏笔与关键道具，你没有登记。**

上游 `foreshadow-tracking-guide.md`：埋设拍必须有画面（"收起／藏匿"动作），回收拍必须有画面
（"取出／兑现"动作），**两端缺一即断链**。它落成一张表：伏笔/道具 ｜ 埋设 ｜ 持有动作画面 ｜ 回收 ｜ 兑现动作画面 ｜ 状态。

→ 但注意：这张表是**跨章**的，而你的 analysis 是**每章一份**。单章只能登记「本章埋了什么／回收了什么」，
真正的跨章追踪要另一个视图（可并入 8.7 的全书索引，一起看「人 × 章」与「物 × 章」）。

### 9.3 架构提醒：世界观硬规则不该只待在 analysis 里

「世界观硬规则」在它那里放在**全书一份**的《设定总表》。而你的 analysis 是**每章一份** ——
让 AI 每章重提一遍，会重复 N 遍、还可能逐章漂移。

真正「**每镜生效**」的注入点是**项目级共用属性块**（`SharedPromptBlock`）：它由生图拼装阶段
统一塞进每条提示词，这正是「此世界无热兵器」这类**全书约束**该待的地方（零代码）。

所以建议走**两段式**：

1. analysis 提炼 —— AI 每章把「本章涉及的画面硬规则」捞出来，给人看；
2. 人工确认 —— 定稿的全书级硬规则写进共用属性块（新建一个「世界观设定」块，或并入「前置条件」块）。

### 9.4 漫画剧本：只有 2 条纪律可抄

**它没有剧本层**，没有结构可抄。但它的 `storyboard-guide.md`「节拍表先行」里有两条纪律，
其职责在你管线里天然属于**剧本**（剧本决定"这一章讲什么"，分镜只是把它拆成页）：

| 上游纪律 | 你现状 | 补法 |
|---|---|---|
| **伏笔双向检查**：埋设拍有画面、回收拍有画面，两端缺一即断链 | 「叙事节点全量覆盖：每个动作都要落进某个场景，不得跳过」—— 笼统，没点名伏笔 | 剧本【忠实度要求】加一句：原文中"拿走／藏起／收到某物"这类**伏笔性动作不得作为过渡删减** |
| **高潮禁止一格带过**：变身／升级／觉醒类最小节拍模板，合计至少 1.5–2 页 | 「关键转折必须保留；确需删减…写明取舍理由」—— 没说"禁止压缩成结果" | 剧本【忠实度要求】加一句：原文高潮事件必须**完整展开为动作序列**，不得因场景合并被压成一句概括 |

另外它的**节拍类型标注**（日常／冲突／伏笔埋设／伏笔回收／高潮）可以考虑并进你剧本的「剧情目的」字段取值
—— 你现在是「铺垫／推进／转折／收束」四值，扩成六到七值即可让伏笔与高潮**显式化**，分镜侧无需改动。

⚠️ **节拍表本身不要并进去**：

- 并进**分镜**：`storyboardService.ts` 的 `STRUCTURAL_RE` 认 `#{1,6}`（见第八章），
  `## 本章节拍表` 会被自动开成一页垃圾分镜；
- 并进**剧本**：没有解析风险（`script` 不做结构化解析），但节拍表的「页格」列依赖"页"这个分镜概念，
  剧本阶段还没有页 → 只能并入剥离了页格列的"节拍清单"，收益有限，不值得单独立项。

### 9.5 成本：全部是零代码

### 11.1 一条必须先说清的红线：分镜加「新字段名」不是免费的

第十章留了一个待验证点，现在验证完了，结论比预想严重。

解析链路（`storyboardService.ts`）：

| 位置 | 事实 |
|---|---|
| `:531` | `const field = line.match(FIELD_RE) ?? line.match(PLAIN_FIELD_RE)` |
| `:288` | `FIELD_RE = /^[-*]\s*([^：:]+)[：:]\s*(.*)$/` —— **必须带 `- ` 前缀** |
| `:289` | `PLAIN_FIELD_RE = /^([^：:]{1,12})[：:]\s*(.*)$/` —— 无前缀，字段名 ≤12 字 |
| `:535` | `knownField` 是**白名单**，只有 20 个词：`画面/内容/景别/镜头/运镜/对白/台词/心声/独白/画外/旁白/人物/出场角色/动作/表情/音效/光效/备注/绘画提示词/出场资产` |
| `:536` | `if (!knownField.has(key) && !line.match(FIELD_RE))` → **不 continue**，落到后面的通用分支 |
| `:558` | 带 `- ` 的未知字段 → 走 else 链 → `else lastField = null` → **静默吞掉** |

而你的模板明确要求「字段行不要加 `-`」，所以新字段会走 `PLAIN_FIELD_RE`。于是发生这件事：

```
模板要求：核心信息：主角发现信物
  ↓ 命中 PLAIN_FIELD_RE（不进白名单，且无 '-' 前缀）
  ↓ 落到 :631  SPEAKER_RE = /^([^：:，。！？、；\s（）()]{1,10})\s*(?:（心声|画外）)?\s*[：:]\s*(.*)$/
  ↓ 「核心信息」= 4 个字、无标点 → 命中！
  ↓ 变成：说话人 =「核心信息」，台词 =「主角发现信物」
```

**后果**：不是被吞掉，而是被**当成一句台词**，说话人叫「核心信息」。它会渲染成气泡、被 panel-prompt 当成 `台词：核心信息："主角发现信物"` 画进画面。**任何 ≤10 字、不含标点的新中文字段名都会中招**（`页尾钩子`、`本章末状态交接` 全在射程内）。

如果加了 `- ` 前缀呢？走 else 链 → 全不匹配 → `lastField = null` → **静默丢弃**，不报错、不提示。

**结论：新增字段名必须改代码（白名单 + 解析分支 + 序列化），三条出路：**

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A 折进既有字段** | 塞进白名单内已有的字段（`备注` 最合适，直通 panel-prompt 且不参与气泡解析）| **零代码** | 想马上拿到收益 |
| B 新字段 | `knownField` + 解析分支 + 类型 + `buildPanelInfoText` + 测试 ≈ 5 处 | 小改代码 | 需要干净的页级语义 |
| C 不做 | —— | 零 | 该信息本来价值有限 |

顺带确认两条「放在分镜末尾」的安全性：

- `## 本章末状态交接` **不会**被 `PAGE_HEADER_RE`（只认 `分镜 N` / `第 N 页`）开成新垃圾页——比节拍表安全；
- 但它**也不会被丢掉**：`STRUCTURAL_RE` 虽然认 `#{1,6}`，却只在 `if (!current)` 时生效（`:504`），最后一页的 `current` 已存在 → 该行掉到 `:653` → `cell.content += line` → **并进最后一格的「画面」**，随后经 `formatCellsForPrompt` 的 `画面：` 行进入 `{{当前分镜}}`，被模型当成画面内容。

### 11.8 缺图门禁 `panelRefReadiness` —— 已实施（2026-10-05，唯一一处改代码）

**现状链路（已逐行核实）：**

1. `storyboard` 输出「出场资产：A1 林小雨（便装）」→ 解析成 `assetBindings`；
2. `auditPanelAssetBindings`（`promptAssetService.ts:375`）只校验四类问题：绑定缺失／资产未匹配／状态未定／名称歧义 → 本例**全部通过、审计全绿**；
3. 出图时 `buildPanelRefManifest`（`panelRefManifest.ts:103`）调 `resolvePanelRefImage(variant, binding)`，图源是 `variant.generatedImageIds + uploadedImageIds`；该状态**还没生成过设定图** → 返回 `undefined` → `:104` 的 `if (!image) continue` **静默剔除**；
4. 后果：图号整体前移一位、提示词里不再有「图N ＝ 林小雨（便装）」、模型自由发挥 → **这一镜的林小雨与其他镜不是同一个人**，而且**全程零告警**。

问题核心在第 2 步：审计"全绿"给了**虚假安全感** —— 待核对区是空的，用户以为这一镜没问题。

**做法**：新增纯函数，与生图取图**共用同一套 `resolvePanelAssetStates` + `resolvePanelRefImage`**，使"门禁判定"与"实际是否缺图"必然一致（既不会误报，也不会漏报）。

```ts
// services/panelRefReadiness.ts（**独立模块**，原因见下方偏差 1）
export interface PanelRefReadinessIssue {
  cellIndex: number        // 0 起；-1 = 仅页级绑定
  assetId: string
  assetName: string
  variantId: string
  variantName: string
  reason: 'missing-image'  // 唯一新增的 reason
}

export function auditPanelRefReadiness(panel, assets): PanelRefReadinessIssue[]
export function summarizePanelsRefReadiness(panels, assets): PanelsRefReadinessSummary
export function formatPanelRefReadinessIssues(issues): string[]
```

**呈现位：升级中栏已有的「无图」弱占位**（`PanelAssetTabs.vue` 缩略图墙的 `v-else` 分支），**不新增占位种类**。文案「无图」→「缺参考图」，中性灰 → amber，补 `ImageOff` 图标与「生图时不会发出这张图」的后果说明；点击打开参考图抽屉（抽屉内文案同步点明后果与「去资产工作台生成」的指引）。**不自动生成**（遵守"AI 结果人工确认"红线）。

**为什么不塞进 `buildPanelBindingFixes`**：`PanelBindingFix.action` 只有 `add | set-variant | remove`，三种都能在分镜页内一步解决；而缺图的解法在资产侧（去生图）。混进去会让该类型语义变脏，并打破待核对区"点一下即完成绑定"的统一交互。

**待定口径（已定）**：同一 `(资产, 状态)` 可能同时命中 `missing-variant` 与 `missing-image`。实测后**不做去重** —— 两者描述的是不同事实（"没写状态名" vs "这个状态没图"），而去重需要在门禁里复刻审计的解析逻辑，耦合成本大于收益。呈现层用标签区分即可。

**影响面 / 风险：**

| 项 | 内容 |
|---|---|
| 新增 | `services/panelRefReadiness.ts`（4 个导出）+ `tests/modules/panelRefReadiness.test.ts` |
| 改动 | `PanelAssetTabs.vue`（现有占位升级，无新增占位、无新增 emit）；`LongProjectStoryboardTab.vue`（导入体检 + 生图前提示） |
| **不动** | 绑定机制、`buildPanelRefManifest`、`auditPanelAssetBindings`、数据模型、图号规则 |
| 性质 | **只读审计**，不写库、不迁移 → 零数据风险 |
| 回归点 | 待核对区现有三类占位不退化；图号与实发图片数组仍严格同序 |
| 测试 | 10 条断言：无图报／有生成图不报／自传成品图不报／仅参考图仍报／多状态只报缺的／取图顺序／cellIndex（页级 -1、格级格序）／同状态多格只算一条／摘要去重／整章汇总跨镜去重 |

### 实施记录（2026-10-05 已完成）

**三处施工偏差（实测才发现，比原方案更准）**：

1. **必须独立成模块**。原方案说"放 `promptAssetService.ts`"，但依赖方向是 `promptAssetService` ← `storyboardService` ← `panelPromptService`，而门禁要用 `panelPromptService` 的取图函数 —— 放进去**会形成循环依赖**。改为新建 `panelRefReadiness.ts`（无人反向依赖它）。
2. **顺序必须自己再排一次**。`resolvePanelAssetStates` 返回的是**绑定声明顺序**，而 `buildPanelRefManifest` 按 `ASSET_REF_ORDER`（人物 → 场景 → 道具）重排后才编号。门禁复用同一个 `ASSET_REF_ORDER`，否则提示语顺序与「图N」对不上（此偏差由单测抓出）。
3. **中栏原本已有「无图」弱占位**（`selectedImage` 为空时的 `v-else` 分支）—— 原方案说"新增一类占位"是错的，那会**出现两个重复占位**。改为升级现有占位。

**一处刻意取舍：生图前只提示、不拦截。**
`generatePanel` 里绑定问题仍是硬拦（`return false`），缺图只 `toast.warning` 后继续。理由：资产图常排在分镜图之后生成，硬拦会把「资产图排队中」这种正常中间态锁死 —— 项目已吃过 `PromptRunBar :disabled` 硬锁的亏；且缺图的后果是"少一张参考图"而非"操作无法完成"，真正的安全网是**三处可见**（导入体检 / 中栏占位 / 生图前提示）。
若要改成硬拦：在 `LongProjectStoryboardTab.vue` 的缺图提示块里补 `endPanelGeneration(panel.id, prevStatus)` + `return false`（两行）。

**验证**：单测 10 passed；完整套件 **40 files / 475 tests passed**；`vue-tsc --noEmit` exit 0；旧占位文案「无图」计数归零。

**可选扩展（未做）**：共用属性块开了「需要参考图」却一张图都没上传时，同样会静默少图（`getSharedRefImages` 返回空）。本门禁不管它 —— 那是配置侧问题、在设置页可见。是否纳入可另行决定。

### 11.9 本章一句话

**分镜这一环你缺的不是结构（14 个字段、台词四选一、旁白逐字溯源都比上游细），缺的是「页」这个层级的意图——格形、页字数、钩子、跨页轴线。`panel-prompt` 缺的全是「不许画什么」和「别太完美」。而绑定不用重做：你的机制在五个维度上比上游强，只差一道「缺图就拦」的门。**

## 十二、分镜与画面描述模板二轮收敛：格数上限、写法骨架与落地记录

> 触发问题：**「这两个模板参考了上游什么？感觉没有大的改变。是不是每个分镜还是只有 4 格以内？每个分镜和它的画面描述到底该怎么写？」**

### 12.1 两个模板到底参考了上游的什么（逐条映射）

上游没有「分镜模板 / 画面描述模板」这两个概念，它的对应物是 `storyboard-guide.md`（S3 拆页）与 `page-base-prompt.md` + `page-generation-guide.md`（S4 出页）。已落地的映射：

| 已落地的规则 | 落在哪 | 上游出处 |
|---|---|---|
| 页头结构名从 4 值扩到 5 值，与画面描述词表对齐（修「分镜选不出不规则主从格」的口径断层） | `storyboard` 正文 + 格式段 | `storyboard-guide.md` 格形语言 |
| 格形本身在叙事（宽格交代环境 / 长格压迫 / 斜切格整页最多一处） | `storyboard` 正文 | 同上「格形语言」表 |
| 每格 ≤20 字、单格满版 ≤30 字、**每页合计 ≤60 字** | `storyboard` 正文 + 格式段 | 同上「文字预算」 |
| 跨页延续时本页第一格重复定位信息 | `storyboard` 正文 | 同上「轴线意识」 |
| 禁止排成等宽等高整齐 2×2、相邻格边界错开 4%~8%、动作页出血、splash 稀缺 | `panel-prompt` ×2 规则 1 | `storyboard-guide.md` 动态版式 + `page-generation-guide.md` 硬性禁令 |
| 单泡 ≤12 字、手写感笔迹非印刷体、可读优先 | `panel-prompt` ×2 气泡样式 | `page-base-prompt.md` 文字元素规范 |
| 每页至少一格非居中构图、人物至少 2 处不完美、媒介质感归共用属性不重复写 | `panel-prompt` ×2【反 AI 味】 | `page-base-prompt.md` 去 AI 味条款 + `style-guide.md` |
| 跨镜延续时本镜第一格重复定位 | `panel-prompt` ×2 规则 6 | `page-generation-guide.md` 逐格内容 |

**刻意没采纳的**（连同原因）：

| 上游要求 | 为什么不采 |
|---|---|
| 每格「格 ID / 机位图编号」 | 你的绑定走文本+资产库，ID 由程序算，写进文本是倒退 |
| 检查清单 `检查清单.md` + 缺图即停 | 已由 `panelRefReadiness` 门禁替代，静态清单会漂移 |
| 本章末状态交接段 | 你有 `reapplyVariantContinuation` + `chapterRange` + 视觉状态，程序化更可靠 |
| 节拍表落盘 | `STRUCTURAL_RE` 认 `#{1,6}`，`## 本章节拍表` 会被自动开成一页垃圾分镜 |
| 提示词里写「尺寸/质量/模型」 | 走接口参数，不写进提示词（你已如此） |

### 12.2 「感觉没大的改变」的两个原因

1. **（最可能）看的是设置页里那份旧模板。** 运行用的是 `comic-settings.json.promptTemplates` 里的**用户模板**，`RECOMMENDED_TEMPLATE_BASE` 只在「该类型没有用户模板」时才生效。改推荐模板对**存量模板零影响** —— 必须在设置页点「**填入推荐模板**」，或在长故事侧栏点「一键新建」。**先确认这一条，再判断模板有没有变。**
2. **结构本身不该变。** 页头 `## 分镜 N · 结构名` + 格内 `第X格` + `字段名：内容` 是**解析器契约**（`PAGE_HEADER_RE` / `ANY_CELL_TITLE_RE` / 20 词 `knownField` 白名单）。骨架一动就解析崩，所以历次改动都只能是「加规则」，这就是它看起来「没大改」的原因。**骨架稳定 = 解析稳定，是刻意的。**

### 12.3 格数上限：从 4 格到 8 格（先收后放）

**代码侧从来没有格数限制**：`PLAIN_CELL_TITLE_RE` / `ANY_CELL_TITLE_RE` 能认 `第8格`，`cellCountLabel` 对 >4 返回 `${count} 格`，`cells` 是数组不限长，页头结构名是自由文本（`PAGE_LABEL_RE` 取 `·` 后的全部）。**格数上限纯粹是模板约定，想改就改，零代码。**

**第一版判断（本轮已推翻）**：当时建议保持 4，理由是中文气泡渲染 —— 1024×1536 分 6–8 格后气泡字号逼近模型可靠渲染下限，错字率上升，而错字的处置成本极高；并用上游的「每页台词+旁白 ≤60 字」自我印证。

**推翻的理由（用户实际创作需要）**：条漫的动作连打、POV 序列、情绪冲击段本来就需要一页内多个特写格把一个瞬间拉长 —— 4 格装不下，模型只能违规或强行合并，反而更差。**瓶颈不在格数，在于「有文字的格」有多少**：8 格页里若有 6 格是无台词的纯画面格（脸、手、眼、道具），气泡渲染压力反而低于 4 格满字页。

**所以放宽到 8 格的关键不是改一个数字，而是同时引入「双模式」**（本轮落地）：

| 模式 | 格数 | 用途 | 文字 |
|---|---|---|---|
| **叙事页** | 1~4 格 | 对话、环境交代、情绪戏（占全章多数） | 常规，每格 ≤20 字 |
| **连打页** | 5~8 格 | 动作分解、POV 序列、特写连打、快速闪回（全章建议 ≤20%） | 极简，每格 ≤12 字、多数格无台词 |

页级 ≤60 字的口径同步点明「**无文字的纯画面格不占额度**」，否则 8 格 × 20 字在算术上直接冲突。

**第一版发现的内部矛盾（仍然有效）**：原模板同时写了「一页 1~4 格」和「一格里只放一个角色的台词，两个角色对话就拆成两格」。3 轮对话往返就是 5~6 格 —— 模型必然二选一违规。现在的口径是**连打页不得塞入对话往返**（对话超过一页 4 格就拆页，不要硬压进连打格），矛盾消解。

### 12.4 本轮改了什么（纯模板，零代码）

**`storyboard`（分镜生成）**

| 位置 | 改动 |
|---|---|
| 开篇定义 | 明写「一页内 1~4 格，**4 格是硬上限**，任何情况都不得超出」（→ 三轮放宽为 8 格，见 12.9） |
| 【分页原则】 | 新增**格数分配**（常规 2~3 格最稳 / 1 格满版只给最重情绪 / 4 格只用于紧凑对话与连打且必须有一格更大）＋**拆页路由**（超 4 个信息单元一律拆两页；拆页顺序：先拆「反应格+POV格」→ 再合并同类动作 → 最后才压对白）＋**节奏**（紧张段 3~4 格密排，抒情段 1~2 格大格；每 3~5 页一个信息爆点）（→ 三轮改为「叙事页 / 连打页」双模式，见 12.9） |
| 新增【信息取舍】 | 心理描写→表情特写格或旁白框；大段环境→压成 1~2 个场景格；重复叙述→合并；例行过场能省则省；**伏笔的「埋」与「收」动作必须各占一格** |
| 格式段 + `description` | 同步写入「4 格为硬上限，超出必须拆页」（→ 三轮改为「8 格为硬上限」，见 12.9） |

**`panel-prompt` ×2（画面描述）**

| 位置 | 改动 |
|---|---|
| 规则 1 | 从「照抄结构名」升级为**必须写成具体布局语言**（哪一格贯通出血、哪一格最宽/最高、大致面积占比），并加**阅读顺序**声明——不规则布局必须补「阅读顺序：自上而下、自左而右」，必要时显式写格序 |
| 规则 4 | 补**视线方向决定气泡先后与摆放**（同一格多人说话时按视线朝向排，避免视线交叉打架） |
| 规则 7 | 钩子节奏校准：每页末格保持向下的牵引力，但**明确的钩子每 3~5 页一次**，避免每页强钩造成疲劳 |
| 新增【文字铁律】 | 画面**唯一允许出现的文字**＝给定台词/心声/画外/旁白＋带引号拟声词；禁止自创台词；**禁止编号与序号入画**（①②③④、1. 2. 3.、「第N格」）、禁止水印/签名/作者名/页码/条形码/格号 |
| 新增【禁止项】 | 不得添加分镜之外的角色/道具/场景元素；不得改动格数、格序、主格位置与页面结构；不得裁切关键信息 |
| 新增【写法原则】 | 肯定句为主（写具体可见的动作与状态，不写抽象情绪词与空泛质量词）；负面清单每格最多 1 条；不写尺寸/画质/模型参数 |
| 【写作要求】逐格行 | 情绪一律落成可见的肢体与表情动作，**不写「在说话」「很难过」这类不可画的描述** |
| 格式段 + `description` | 同步（页面结构行要补布局与阅读顺序；画面唯一允许文字边界） |

### 12.5 一个分镜和它的画面描述应该长什么样（对照样例）

**分镜（`storyboard` 的输出，就是你在分镜页看到的文本）**

### 12.8 本章一句话

**分镜这一层的骨架必须冻住（解析器契约），能动的只有规则——所以历次改动看起来都「不像大改」。真正值得改的三处是：格数上限的自相矛盾（已补拆页路由）、画面描述的「版式必须写成具体布局」、以及「不许画什么」的负向清单。而「看起来没变」最常见的原因不是没改，是设置页里那份旧模板还在生效。**

### 12.9 三轮改写：格数上限放宽到 8 格（连打页）（2026-10-05，纯模板零代码）

**触发**：用户指出 4 格太少 —— 实际创作里 POV、特写、动作连续的特写格本来就需要更多格。

**结论**：格数上限 4 → **8**，但不是简单改数字，而是引入「叙事页 / 连打页」双模式（见 12.3 的表）。

**`storyboard`（分镜生成）**

| 位置 | 改动 |
|---|---|
| 开篇定义 | 1~4 格 → **1~8 格，8 格是硬上限** |
| 【分页原则】 | 新增**双模式判定**（叙事页 1~4 格 / 连打页 5~8 格且全章建议 ≤20%）；格数分配重写（5~8 格只用于连打页）；拆页路由从「超 4 个」放宽为「**超 8 个**」；新增**连打页不得塞入对话往返**；节奏补「情绪爆点／动作高潮用连打页把一个瞬间拉长」 |
| 新增【连打页怎么写】 | 适用场景（动作分解／POV 序列／特写连打／快速闪回）＋**每格只推进一个极小时间差**（相邻格之间只变一个元素）＋景别以 特写/POV/近景 为主、**POV 必须拆两格**＋**必须有一格冲击主格**＋**文字极简（每格 ≤12 字）**＋占比约束 |
| 页头结构名 | 词表加 **`多格连打`**（5~8 格专用），并写死映射：1→单格满版、2→上下双格/左右双格、3→三格递进、4→不规则主从格、5~8→多格连打 |
| 格形在叙事 | 补「连打页格高不要平均分配，用『连续小格 + 一个明显更大的冲击格』形成节奏」 |
| 字数 | 每格 ≤20 字 → **连打页每格 ≤12 字**；页级 ≤60 字补「**无文字的纯画面格不占额度**」 |
| 格式段 + `description` | 同步（8 格硬上限、双模式、多格连打词表） |

**`panel-prompt` ×2（画面描述）**

| 位置 | 改动 |
|---|---|
| 规则 1 | 补**连打页排布**：5 格以上格高不得平均分配，用「连续小格 + 一个明显更大的冲击格」形成节奏；阅读顺序声明的触发条件从「不规则主从格」扩为「**含多格连打**」，且**格数 ≥5 时必须逐格写明格序** |
| 气泡样式 | 补「格数越多单格面积越小 —— **5 格以上的连打页气泡控制在 ≤8 字**」（与分镜层的 ≤12 字形成两级收紧） |
| `description` ×2 | 同步 |

**连打页的样子（6 格，动作分解）**

```
## 分镜 9 · 多格连打
第1格  景别：近景  → 握着门把的手，指节发白
第2格  景别：特写  → 门把被压到底，金属发出细响（音效：“咔哒”）
第3格  景别：POV   → 门缝里透进的冷白光线占满画面
第4格  景别：特写  → 林小雨瞳孔收缩（无文字）
第5格  景别：近景  → 她后退半步，肩膀撞上身后的书架
第6格  景别：中景  → 冲击主格（画幅最大）：门被完全推开，门口立着一个人影（无文字）
```

要点：6 格全部落在同一个「推门」动作上，相邻格只变一个元素；只有 1 格有文字（拟声词），页级字数远低于 60；第 6 格是冲击主格，画幅最大、留悬念。

**验证**

- `vitest run tests/features/promptTemplateRegistry.test.ts` → **33 passed**（原 31 + 新增 2 条：连打页小节、画面描述连打页排布与气泡字数）
- 完整套件 → **40 files / 479 tests passed**
- `vue-tsc --noEmit` → **exit 0**
- 21 个关键词逐条 grep 落盘；旧措辞「4 格是硬上限 / 4 格为硬上限 / 超过 4 个信息单元就拆页 / 四格及以上一律写」计数全部归零

**仍然成立的技术边界**：8 格页每格面积约为 4 格页的一半，**有文字的格**气泡字号仍偏小 —— 所以连打页的正确用法是「画面格为主、文字为辅」（已写进模板：文字极简 + 每格 ≤12 字 + 气泡 ≤8 字）。若某页 8 格都必须带台词，要么拆页、要么回到叙事页 —— 这正是「连打页不得塞入对话往返」这条存在的意义。

### 12.10 画面描述完整示例（一层一层看它到底长什么样）

**触发**：用户问「生成的分镜画面绘图描述应该是什么样的，给我一个示例」。

先分清三个层次 —— 它们经常被混为一谈：

| 层 | 谁产出 | 存在哪 | 长什么样 |
|---|---|---|---|
| ① 分镜文本 | `storyboard` 模板 → LLM | `panel.blockText` / `cells` | `## 分镜 7 · 不规则主从格` + `第1格` + `字段名：内容` |
| ② **画面描述** | `panel-prompt` 模板 → LLM | `panel.imagePrompt`（可编辑、可复制到外部 AI） | `页面结构：…` + `第1格：` + 4 行内容 |

#### 12.10.5 四个最常被写错的点

1. **在画面描述里写外貌**（「黑长直发、白色校服」）—— 会与资产状态冲突。正确写法是只写 `林小雨（便装）`，外观交给参考图。
2. **把「图N＝谁」写进画面描述** —— 画面描述是纯净层，图号必须由生图前的拼装实时生成，写死就会串图。
3. **一格塞多句台词** —— 一格一句、每格 ≤20 字、每页 ≤60 字（连打页每格 ≤12 字、气泡 ≤8 字）。
4. **写不可画的心理与抽象词**（「她很难过」「气氛很紧张」）—— 一律落成可见的肢体与表情（肩线绷紧、眼眶发红、指节泛白）。

## 十三、资产两模板三轮优化：「只写自己」「不谈下游」+ 场景两种出图版式

> 触发问题：**「我全部按照这个跑了一篇，最后成图的效果还是不理想。先重新优化资产提取和资产绘画提示词的生成。」**

归纳出三个病灶：

| 病灶 | 表现 | 根因 |
|---|---|---|
| 视觉描述被「横向比较」污染 | 模型把「与本角色其他状态的差异」写成描述主体，出一个状态时把别的状态特征混进来 → 成图画成四不像 | 模板要求「写清与其他状态的差异」，把「跨状态比较」写成了产出目标 |
| 角色设定越位到下游 | 提取模板在讲「供后续分镜/画面描述使用」，出图模板在讲「与后续漫画页质感一致」→ 模型开始**脑补下游需要什么**，而不是老老实实转译已给定的视觉事实 | 角色设定里写了下游环节的用途 |
| 场景只有一种出图版式 | 每个场景一张「一张图描述一个空间」，没有空间总览、也没有可复用的机位库 → 多页复用同一场景时机位要么靠模型自由发挥、要么前后矛盾 | 没有区分「空间全景」与「机位资料」两种产物 |

### 13.1 `extract` 模板：角色只对自己负责

三条硬约束，正文与格式段**两处都改**（红线段落只改一处会导致约束缺一半）：

1. **不谈下游**：开篇改为「你只负责把本章实体的视觉事实写清、写全、写到可直接照画的精度，**不必考虑这些内容之后会被怎么使用**」；删掉全部「供后续分镜使用」类表述。
2. **只写本状态自身的样貌**：视觉描述的产出要求与自检项里都写明——不与其他状态作横向比较、不写「与其他状态的差异」「相比前一个状态」、不把其他状态的特征混写进来。
3. **状态拆分收口**：把「一闪而过、单看某一个瞬间分辨不出的变化」明确列为**不拆状态**；场景与道具各自只输出一个视觉状态（剧情锚点写「全章默认」），时段/天气这类变化并进该状态描述里一句即可。

### 13.2 `asset-prompt` 模板：六段骨架 + 场景两种版式

**六段固定骨架**（画风基准 → 主体与身份锚点 → 变体说明 → 构图与视角 → 背景与光线 → 禁止项）：其中**画风基准不写**（不属于本环节产出，由全局参数拼接），其余五段落进一条连贯提示词，**不要写成带标题的字段清单**。

**场景两种版式**（同一场景两种版式必须共享同一套空间事实，不得互相矛盾）：

| 版式 | 何时用 | 内容 |
|---|---|---|
| ① 空间全景版式（establishing shot） | 场景的**默认状态**（状态名不含「机位图」） | 广角平视空间总览，只交代**空间结构与标志物**，不写剧情动作 |
| ② 九宫格机位图版式 | 状态名含「机位图」时 | 3×3 九宫格，**9 个互不重复机位**、固定编号 1–9 |

九宫格的 9 个机位（顺序与编号固定，不要改动）：

```
1 高位俯视   看整体布局（房间／巷道的平面关系）
2 正面广角   主视角
3 左前 45°   中景
4 右前 45°   中景
5 电影主机位 标准镜头，空间中部
6 反打机位   对面视角（与第 2 格相对）
7 内部向外   从窗边／门口看向内（或门洞内看向外）
8 侧面横向   平移镜头视角
9 低机位     地面向上（戏剧化仰视）
```

三条硬规则：

1. **每格左上角标单个阿拉伯数字 1–9**；
2. **标志物（landmarks）跨格必须一致**——同一扇门、同一根柱子在 9 格里位置关系自洽；
3. **命名固定为 `LOC-<场景>-机位图.png`**（`<场景名>` 用清单里的场景名原样，不加章节号与序号），空间全景版式不加后缀。

配套调整：光源方向与光质明确写出；场景不完美项从 ≥2 提到 **≥3**；媒介质感锚保留；「除版式要求的单字符视图标号外不出现文字与水印」这句**并进各版本式声明的引号内**（不再作为独立禁止段，见 §13.5）。

### 13.3 三种触发条件为什么只能由程序判（不是模板）

「机位图按触发条件强制出」的三条条件——**单章出镜 ≥2 页**、**跨章复用**、**场景内机位变化**——

在模板层**根本拿不到**：

- `extract` 发生在分镜**之前**，此时还没有页数；
- `asset-prompt` 的输入 `buildTargetList` 每行只有 `资产名｜类型｜状态名｜资产描述｜视觉描述｜固定特征｜attributes 前 8 项`，**没有页数、没有章节引用、没有镜头信息**。

所以新增纯函数模块 **`services/sceneRefSheetNeeds.ts`**（不引用任何 service，避免 `promptAssetService ← storyboardService ← panelPromptService` 的循环依赖）：

```ts
auditSceneRefSheetNeeds({ assets, panels, chapterAssets?, chapterId? })  // 只读审计，不写库
```

判定口径：

| 触发条件的机械口径 | 说明 |
|---|---|
| 单章出镜 ≥2 页 | 本章分镜里绑定了该场景的页数 ≥ 2（**页级 + 格级绑定都算**，同一页内绑多次只算一页） |
| 跨章复用 | 引用该场景的章节数 ≥ 2，**或**任一章节引用标记为 `appearance: 'reused'` |
| 场景内机位变化 | 该场景关联的镜头语汇里命中 **≥2 类**机位（高机位 / 低机位 / 反打）；同类只算一类，`过肩`、`POV` **刻意不收**（它们是景别取值、对话戏里高频出现，收进来会让几乎所有场景都被判定需要机位图） |

配套 UI 入口：资产工作台左栏顶部出现青色提示条「补建场景机位图状态 N」，悬停列出「场景名（触发原因）」；点击一次性为全部待补建场景各建一个「机位图」状态 + 一条 `origin: 'manual'` 的章节引用（**一次提交写一次库**，不循环写）。

### 13.4 ⚠️ 顺带修掉的一个真问题：机位图会被「重新提取确认」静默删除

上一步补建完就发现了一个必然踩的坑：

> `assetExtractionConfirm.applyCandidatesToAsset` 的口径是**「视觉状态按候选状态整表重建，本次未出现的旧状态一律删除」**，
> 而 `extract` 模板**永远不会输出「机位图」**——它是程序按触发条件补建的资料性状态。
> 结果是：用户下一次确认提取结果 → 刚生成的九宫格状态连同已出的图**一起消失**，且没有任何提示。

修法与既有 `LongProjectChapterAsset.origin` 完全同款（同一套语义、同一套缺省规则）：

| 改动点 | 内容 |
|---|---|
| `types` | `LongProjectAssetVariant` 新增 `origin?: 'extraction' \| 'manual'`，**缺省一律按 `extraction`**（旧数据行为不变） |
| `sceneRefSheetNeeds.buildRefSheetVariantDraft` | 草稿带 `origin: 'manual'` |
| `assetExtractionConfirm.applyCandidatesToAsset` | 重建后**追加保留** `manual` 状态（同名/同 id 被候选命中的走正常重建分支，不会重复两条） |
| `assetExtractionConfirm.selectDroppedVariants` | `manual` 状态**不算「本次未出现」**，避免误导用户以为成果要丢 |
| `storyboardService.defaultVariant` | 只从**非 manual** 状态里挑默认（资产只剩 manual 状态时才退化为全体），防止分镜把九宫格参考图当默认状态绑进画面 |

### 13.5 收尾修订：禁止项不再当固定尾段（用户反馈）

> 反馈原文（粘贴了真实产出）：**「资产绘画提示词最后不要固定加这种：不得出现任何台词、旁白、说明文字、水印、签名与资产编号徽章；仅允许版式要求的三视图标志与基础信息卡内容；不得出现萧薰儿之外的其他人物、动物或第二件资产；人物不得被裁切、不得重复出镜、不得持物或背负重物；三视图必须同比例、同大小；不得改变紫色衣裙配色、黑金丝袖口镶边与中分长直发发型。」**

**根因**：旧模板写的是「【禁止项】（**必须逐条以否定句写进每条提示词**）」，外加【用语要求】里「【禁止项】里的内容禁令例外，必须逐条写进提示词」、【自查】里「是否逐条写出了【禁止项】」——**三处都在命令模型把这四段禁令原文抄进每一条**。抄出来的东西里有三类纯噪音：

| 噪音类型 | 例子 | 为什么是噪音 |
|---|---|---|
| 版式重复 | 「三视图必须同比例、同大小」「人物不得被裁切」 | 版式声明里已经正向写过（「三视图等距并排、同比例同大小」「人物完整全身展示」） |
| 事实复述 | 「不得改变紫色衣裙配色、黑金丝袖口镶边与中分长直发发型」 | 配色/发型本来就在正向描述里，再否定一遍等于把事实说两遍 |
| 结构固化 | 每条提示词末尾都是同一段话 | 模型会把它当"必须满足的模板"而非"画面要求"，还挤占有效 token |

**改法（把必要条件搬到它该在的地方，然后取消"必写"）**：

1. **把该留的并进版式声明**——四个版式（人物／场景全景／场景机位图／道具）的「统一 XX 版式：…」引号内各加一句**短句**，声明这块画面里只有什么、没有什么：
   - 人物：`画面只有本角色与三视图标志、不出现第二个人物或动物、无文字与水印`
   - 场景全景：`画面只有该空间本身，不出现人物与动物，除空间固有招牌外无文字与水印`
   - 场景机位图：`画面只有该空间本身，不出现人物与动物，除每格的单字符数字标号外不出现任何文字与水印`
   - 道具：`画面中只有该道具，不出现人物、不出现手持动作、不出现场景与台面，除视图标号外不出现任何文字与水印`
2. **`【禁止项】` 改口径**：标题写成「（写，但**不许写成固定尾段**）」，正文给出反面典型原文 + 四条禁令：
   - 不要给每条提示词挂同一段通用禁令清单；
   - 必要条件已在版式声明里，**不要再抄第二遍**；
   - 只在声明盖不住时补 **≤1 句**，整条否定句 **≤2 句**；
   - **不得写成否定句的两类**：版式类（背景色／完整入画／三视图同比例／视图标号）与事实类（清单已给的配色、发型、材质、形态、尺寸、状态）；
   - 同一章内不要出现两条提示词的否定句完全相同。
3. **六段骨架的第六段重定义**：`禁止项` 保留在骨架里，但明确「**也不是独立尾段**——必要禁令并进『构图与视角』的版式声明里」。
4. **两处配套同改**：【用语要求】的例外条款从「必须逐条写进提示词」改成「版式声明里的画面内容描述照写即可，不算风格类负面提示词」；【自查】从「是否逐条写出了【禁止项】」改成「是否**并进了版式声明**、有没有复述事实的否定句、否定句是否 ≤2 句」。
5. **格式段（硬约束）同步加一句**：`提示词正文是一条连贯的中文段落：不要分点、不要带字段标题，也不要在末尾附通用禁令清单或固定尾句。`

> 注：`资产编号徽章` 一并删掉——资产提示词的输入清单里根本没有 `A1／B2`（那是分镜文本的编号，`buildTargetList` 用的是 `状态1｜资产：…`），旧模板等于凭空空造了一条禁令。

## 十四、人物版式改「四联图」：整张图只保留一处高分辨率人脸（2026-10-05）

### 14.1 为什么改：远景人脸必然是糊的

用户跑完整篇后反馈「成图效果还是不理想」，并给出一个来自实践的关键做法（原文）：

> 同一人物四联角色设定图，1×4 非等宽排版。第 1 格为 2:3 竖幅人像，宽度明显大于后 3 格；第 2 至第 4 格等宽排列，完整展示全身。……第 2 格：全身正面视图，A-POSE，**头部完全裁出画面，禁止出现脸部**。第 3 格：全身 3/4 前侧视图，A-POSE，**头部完全裁出画面**。第 4 格：全身背面视图，A-POSE，**完整保留头部至脚部**。
> **里面有一个方法很重要：只出现一次人物大脸，其余三视图只出现头部以下，这样 AI 能更好的提取信息。** 如果按照现在的来，三视图因为是远景，会导致人脸很糊，后续做参考不好。

这是**参考图可读性**问题，不是画风问题。旧版式是「画面右侧大尺寸脸部特写 + FRONT/SIDE/BACK 三视图」，四格里的全身格都要容下一个完整人头——
**一张图里人物的总像素是有限的，塞进一个全身照之后，脸只剩几十像素**；下游分镜生图拿它当参考，读到的人脸就是这么糊。

### 14.2 改前 / 改后

| | 旧版式 | 新版式（四联图） |
|---|---|---|
| 排版 | 右侧大脸 + 三视图（**等宽**） | 横向 **1×4 非等宽**：第 1 格 **2:3 竖幅**、明显更宽；第 2~4 格等宽 |
| 人脸 | 全身格里都带脸（远景 → 糊） | **整张图只出现一次脸**，且是唯一的高分辨率位 |
| 第 1 格 | 脸部特写（与全身格并列） | **2:3 竖幅脸部大特写**，裁切至锁骨，脸部占该格主要面积，直视镜头 |
| 第 2 格 | 正面全身（含头） | 正面全身，**画幅从颈部中段以下开始，头部完全在画幅之外** |
| 第 3 格 | 侧面全身（含头） | 3/4 前侧全身，**同样从颈部中段以下开始** |
| 第 4 格 | 背面全身（含头） | 背面全身，**完整保留头部至脚部**（只给后脑与发型背面），背对镜头看不到脸 |
| 背景光线 | 18% 灰哑光背景 | **影棚纯色中性灰（18%）无缝背景 + 柔和伦勃朗光（45° 侧上方主光、柔和三角光斑）**、自然阴影与清晰皮肤细节 |
| 文字 | 基础信息卡 + `FRONT/SIDE/BACK` 标志 | **无文字、无标注**（信息卡与英文标志全部删除） |

### 14.3 三条必须写进模板的话（少一条就白改）

1. **机制本身要写明**：`**整张图的脸只出现一次**：第 1 格是唯一的高分辨率脸部，第 2、3 格的画幅从颈部中段以下开始、头部完全在画幅之外`。
2. **必须声明「这是刻意的」**：`这是刻意的版式，把画幅让给服装，不是裁切失误，不要补画头部与五官`。
   —— 图像模型见到「全身照缺头」会当作失误主动补上，**不写这句，「不出现人脸」当天就失效**。
3. **第 4 格要单独说明**：`全身背面、完整保留头部至脚部，但人物背对镜头、看不到脸`。否则模型会把「裁头」这条规则套用到背面格，丢掉发型背面资料。

### 14.4 连带改动（同一个口径不能留双份）

- 【转译要求】「最小必要补全」的举例从「全身出镜」改成「画格排布」（新版式里有刻意的裁切，`全身出镜` 会与之矛盾）。
- 【禁止项】「版式类不得写成否定句」清单：`完整入画` → `多视图同比例同大小`，并补 `人物版式的「第 2／3 格不画头部」（这是版式设计，写成否定句会反过来诱导模型补头）`。
- 【自查】：从「基础信息卡、三视图标志、全身展示、9 维外貌齐全」改为「1×4 非等宽、第 1 格 2:3 竖幅脸部大特写、第 2／3 格头部在画幅之外、第 4 格全身背面、18% 中性灰无缝背景、A-POSE、无文字无标注、四格同比例」。
- `description`（模板元信息）同步。
- 【禁止项】里那段**反面典型原文保留不动**——它本来就是给人看的「错误示范」。

### 14.5 两个保留 / 一个提问

- **保留 A-POSE 与姿态约束**：`四格一律 A-POSE，双手自然下垂、不持物、不背包`（A-POSE 便于下游判断体型与手臂位置）。
- **「标准九头身黄金比例」降级为「统一头身比例」**：参考模板是超写实电商人像风，与九头身冲突；若你的漫画确实走九头身，一句话加回。
- **风格词没有进模板**：`超写实电商人像摄影`、`SOFT REMBRANDT LIGHTING` 里的**风格**部分归**共用属性块（漫画工艺）**；只把**光线做法**（伦勃朗光、45° 侧上方主光、柔和三角光斑）留在模板里——它是「光线必须具体」这条既定要求的一部分，不算渲染流派词。

### 14.6 验收

## 十五、漫画排版：分格结构扩表 + 气泡放置规则 + 情绪背景（2026-10-05）

用户反馈「**分镜模板与画面描述模板 ×2 里对漫画排版的设计不好**」，并给了三样东西：
① 一篇公众号条漫（`mp.weixin.qq.com/s/XfDB2qSvbrC_26Ir3zG5dw`）的排版参考；
② 一份**期望的输出样例**（`版面：` + 左栏/右栏 + `文字元素：` 列表）；
③ 一条明确诉求：多格页要**多一些不规则排版，不要太传统**，并把气泡／旁白框的放置规则**用文字描述出来交给生图 AI**。

### 15.1 参考图读到了什么（抓正文图片后逐张看）

公众号正文里的 28 张漫画图能直接抓下来读。看下来的固定手法：

| 手法 | 图里长什么样 | 能落成什么规则 |
|---|---|---|
| 竖屏满宽堆叠 | 页面就是一列格子，宽度基本满宽 | 条漫默认是纵向流；**分栏只用在少数页** |
| 格与格之间不是白线 | 用**带纹理的窄带**当沟槽 | 沟槽宽度＝时间的「可写」证据 |
| 气泡溢出画格 | 圆形气泡直接**压在沟槽／留白上**，不包在格内 | 允许气泡溢出格线，但不得盖住邻格主体 |
| 气泡形状＝情绪 | 平静＝椭圆；**喊叫＝锯齿爆炸形** | 形状表（见下） |
| 拟声词是手写艺术字 | 「看脉——」「!!!」带描边直接压画面，有时带**指向线** | 音效不进气泡，写成手写艺术字并注声源／朝向 |
| 情绪小字标注 | 手写体小字「惊喜不已」压在画面上 | 可选，本模板未收（避免与台词边界混淆） |
| 局部大特写做爆点 | 眼睛／手部极特写独占一格 | 冲击主格 + 出血 |
| 元素破格 | 花朵压过画格边缘 | 未收（属画风，归共用属性块） |

### 15.2 结构名词表：从 6 个名字扩到 12 个，抽成四份模板共用的单一事实源

**老病**：词表只有 `单格满版 / 上下双格 / 左右双格 / 三格递进 / 不规则主从格 / 多格连打`，
而且 **4 格一律写「不规则主从格」**——等于没有不规则；「左右分栏」这种最典型的现代排版根本没进表。

新增三条常量（`promptTemplateRegistry.ts`），**storyboard 与 panel-prompt ×2 都插同一份**，
再也不会「分镜选的名字画面层认不出来」：

- `PANEL_STRUCTURE_NAMES` — 名字与格数对应（12 个名字）
- `PANEL_STRUCTURE_SEMANTICS` — 每个名字的排布语义（panel-prompt 据此展开成布局语言）
- `PANEL_LAYOUT_RULES` — 不依赖具体名字的通用规则（禁等宽阵列 / 沟槽即时间 / 出血稀缺 / 阅读顺序 / 章内要有变化）

| 格数 | 结构名（新） | 相对旧表的增量 |
|---|---|---|
| 1 | 单格满版／**满版出血** | 新增「主体压过页缘」 |
| 2 | **上下错位双格**／左右双格／上下双格 | 新增不等高的错位排法，并立为推荐 |
| 3 | **一主两辅**／三格递进 | 新增「大格 + 两个贴边小格」 |
| 4 | **跨栏主格**／**左右分栏**／不规则主从格 | **这是本轮重点**：主格贯通整栏 + 三小格错落；以及用户样例那种「左栏堆叠 + 右栏贯通」 |
| 5~8 | ~~条带连打~~／多格连打 | 新增窄条快速推进 + 一个冲击格 —— ⚠️ **当日即被用户否决，见 §16，已换成悬浮类结构名** |

⚠️ 结构名**不是解析白名单**：`storyboardService` 用 `PAGE_LABEL_RE` 原样取页头「·」后的文本，
`panel.cellLabel` 直通左栏与画面层且不做校验 —— 所以**加名字零代码**，唯一要求是四份模板同一份词表。

### 15.3 气泡：形状承载情绪 + 六条放置规则

`【文字气泡与旁白框】` → **`【文字元素与气泡】`**（不再只是气泡，含音效艺术字）。

**形状表**（形状选错，读者会读错语气）：

| 场合 | 形状 |
|---|---|
| 对白 | 椭圆，细黑描边、手绘感微不规则 |
| 喊叫／愤怒／惊叫 | **锯齿尖角（爆炸形）**，边线粗 |
| 低语／气音／虚弱／生病 | 虚线或抖动的细边，或双层轮廓 |
| 心声 | 云朵边／波浪边，或**边缘虚化成雾**，气尾是一串小圆点 |
| 画外 | 形状同对白，但**气尾不得指向画面内任何人物**，朝声源方向伸出画面 |
| 旁白／说明 | **方角矩形框，无气尾**，贴左上或左下角 |

**放置规则**（本轮新增，全部是「写出来交给生图 AI」的）：

1. **顺序**：先说话的排上面；同格多气泡按**从上到下、从左到右**（中文阅读方向），同高时左边先读。
2. **配额**：一格最多 **3 个气泡**；气泡总面积不超过该格的 **1/3**（一般 15%~25%）；字多就拆格拆页，不要把气泡撑大。
3. **避让**：绝不遮挡角色的**眼睛与脸部表情**、手上的关键道具、画面里的拟声词艺术字。
4. **气尾**：指向说话者嘴部／下颌，不穿过其他角色，保持短；心声指向头部。
5. **溢出**：**允许气泡压在两格之间的沟槽留白上**（参考图里到处都是），但不得盖住相邻格的关键画面，气尾仍须指向本格说话者。
6. **引流**：**用气泡把视线引向下一格**——下一格在下方，就把本格最后一句气泡放在本格下部中央或右下。

另加一条**沉默格**：一格完全可以不放字，震撼瞬间与无言对视比塞满台词更有力。

### 15.4 情绪背景（用户点名要的「背景是闪亮的粉色」）

新增 `【情绪背景】` 一节，用背景替人物说情绪：

- 只在**情绪焦点格**（反应格／特写）用；写实环境格、动作格、对话格一律写实背景。
- **一个场景第一次出场必须先用写实环境交代空间**，空间没交代清楚之前不许上抽象背景。
- **同一页最多 1~2 格**用，多了整页就散。
- 用法是**把写实背景整体替换**成图案／色块，**不是叠滤镜**；人物照旧写实画。
- 对照表：闪亮粉色 + 光斑 + 飘落粒子＝心动／暧昧｜放射线 + 高对比网点突变＝震惊｜火焰与红色放射＝愤怒｜黑色漩涡、乱线、碎裂网点＝内心崩溃｜花瓣蕾丝飘带＝恋爱｜猫爪饼干小心心＝可爱｜冷灰薄雾 + 稀疏网点＝失落｜亮黄 + 波纹 + 摇动感＝烦躁。

### 15.5 输出形状改成用户样例那样

```
版面：
页面纵向分成左右两栏，左栏宽约 7 成…… 阅读顺序：自上而下、自左而右。
左栏分镜：
1. 第1格：中景／平视。<画面内容>。表现元素：无。
文字元素：
- 对话气泡（林小雨）：“？”（头部右上；气尾指向其下颌）
- 音效：“叮咚♪”（门铃响，画在格右下角，朝向声源方向）
2. 第2格：……
右栏分镜：
4. 第4格：……（右栏一格贯通整栏高度，画成本页高纵向主格）
文字元素：无
```

- 第一行由「页面结构：」改为 **「版面：」**；末行由「文字气泡：」改为 **「文字元素：」**（含音效艺术字）。
- **分了栏就按栏分组**，组前单独一行写「左栏分镜：」「右栏分镜：」（两栏以上写「第一栏分镜：」…）；**格号跨栏连续、不重新起编**。
- 每格的「表现元素：」一行（拟声词艺术字／速度线／集中线／情绪符号／气氛网点／留白／情绪背景），没有写「无」。
- 「文字元素：」下逐条写 `- 类型（说话人）：文字（位置；气尾指向）`，类型取 **对话气泡／内心气泡／旁白框／说明框／音效**（后三者不写说话人）；本格没有就整段写「**文字元素：无**」。

## 十六、多格页改「悬浮散格」：否决条带连打（2026-10-05 同日二次收敛）

### 16.1 用户的否决理由

用户贴回了模板实际产出的一段版面描述：

> 条带连打（本页 6 格），连续窄条格快速推进；第 1 至第 4 格为连续小格沿页面右侧纵向排列，各占约 12%；第 5 格占约 12%；
> 第 6 格为冲击主格占约 40%……格高不平均分配，形成「小-小-小-小-小-大」节奏……

**问题不在「不平均」，而在「等占比 + 同一条页边平铺」**：五格都是约 12%、都沿页面右侧纵向排列，
本质仍是**一列等宽窄条**，只是高度有差——读起来是呆板的瓷砖阵列。
用户的要求：**多格分散、错位、悬浮**，「每一格不占满宽度，也可占满宽度，多个交替」。

### 16.2 改法

**一、新增常量 `PANEL_FLOAT_RULES`（悬浮散格规则）**，与 `PANEL_LAYOUT_RULES` 同源同插：

| 条 | 内容 |
|---|---|
| 不占满页宽 | 允许只占页宽 **55%~85%**，左右任一侧露出留白、底衬或另一格的一角；也可某格占满整页宽做重音；**满宽格与偏窄格交替**，不要连续三格同宽 |
| 分散错位 | 每格水平起点都不同（左偏／右偏／居中交替，相邻起点差 ≥10% 页宽），垂直间距不等；**禁止沿同一条页边等距平铺成一列等宽窄条** |
| 悬浮边界 | 偏窄格用清楚画框包边，框外保留可辨识的**统一底衬**（纯色底／网点／上一格画面的延续），让所有格子浮在同一层空间上 |
| 局部叠压 | 允许相邻格局部叠压（压住一个角、不超过被压格 1/5），按阅读顺序**后读的压住先读的**；被压处不得是关键信息 |
| 中轴与视线 | 偏窄格优先落在中轴或中轴两侧交替；**POV、特写、反应格优先做成偏窄的悬浮格**（画幅小＝离读者近）；阅读引导靠构图与文字元素**自然形成**（人物看向的方向、气尾指向、气泡摆放位置、明暗对比），**不要在画面里画引导线、指示线、视线连线或指向箭头**（2026-10-05 修正，见 §16.5） |

**二、结构名词表换血**（`条带连打` 删除，不再出现在任何一份模板里）：

| 格数 | 旧 | 新 |
|---|---|---|
| 4 | 跨栏主格／左右分栏／不规则主从格 | 跨栏主格／**错落浮格**／左右分栏／不规则主从格 |
| 5~8 | 条带连打／多格连打 | **悬浮散格**／**浮格连排**／多格连打 |

语义分工（选名时对照）：

- **错落浮格**（4 格）＝一格占满或多半页宽，其余格缩小后左右交替错开浮在它四周，**至少两格不占满页宽**；
- **悬浮散格**（5~8 格）＝分散、疏密不均、留白多，多数格不占满页宽 → 用于**时间跳跃／心理流动／悬疑铺陈**；
- **浮格连排**（5~8 格）＝沿一条**错位轴线**密集连排、宽窄交替（宽-窄-窄-宽），可局部叠压，冲击格压在动作顶点 → 用于**动作连打／POV 序列／特写连打**；
- `多格连打` 保留为泛称，语义改为「分散错落、格高与水平位置都不平均」。

**三、四处连带改口**（同一个口径不能留双份）：

| 位置 | 改动 |
|---|---|
| storyboard 正文【连打页怎么写】 | 补「其余格**跟着主格分散错落**——缩小、左右交替错开、浮在页面上」 |
| storyboard 正文【每一页怎么写】 | `${PANEL_LAYOUT_RULES}` 后追加 `${PANEL_FLOAT_RULES}`；「连打页格高不要平均分配／别排成等高的条带」改为「**多格页优先用悬浮散格**…别排成等宽等高的条带或方格阵列」 |
| panel-prompt ×2 规则 1 | 追加 `**悬浮散格规则**：${PANEL_FLOAT_RULES}`；旧的「格高不得平均分配…其余格沿动作方向依次递进」改为「优先用悬浮散格…不要沿同一条页边平铺成一列等宽窄条」 |
| 格式段（storyboard + panel-prompt ×2） | storyboard 加硬约束「**不得排成等宽等高、沿同一条页边平铺的窄条阵列**」；panel-prompt ×2 的版面展开项补「**哪些格不占满页宽、各自落在页面左中右哪一处、哪一格压住哪一格**」，并禁写「各占约 X%、沿同一条页边依次排列」 |

### 16.4 「漫画表现元素」去哪了？——只是改了输出行标签，同时统一 token

**用户问**：「现在漫画表现元素不描述了吗？」**答：没删，描述一字未动。**

上一轮改输出形状时，把**输出行标签**从 `漫画表现元素` 改成 **`表现元素：`** —— 因为这一行现在还要装
新加的**情绪背景**（原来那五类是 拟声词艺术字／速度线·集中线／情绪符号／气氛网点／留白），
用更宽的名字才对得上。正文里的规则小节、五条细则、以及「逐格写进这一行」的要求**全部保留**。

| 位置 | 改前 | 改后 |
|---|---|---|
| 正文小节标题 | `【漫画表现元素】` | **`【表现元素】`** |
| 逐格输出行标签 | `漫画表现元素：` | **`表现元素：`** |
| 交叉引用（拟声词段、严格基于给定信息段） | `按【漫画表现元素】处理` | `按【表现元素】处理` |
| `【情绪背景】` 末条 | — | 新增「**情绪背景属于表现元素**：逐格写进该格的「表现元素：」行」 |

⚠️ **改前是同一模板里两个 token**（节标题叫「漫画表现元素」、输出行叫「表现元素：」，格式段还明令
不得出现「漫画表现元素」）—— 与历史上 `文字气泡：无` ↔ `无文字` 是同一类问题：
**同一份模板出现两个说法，模型会在两者之间摇摆**。这次一并统一，并把
`漫画表现元素` 同时列入**正文与格式段都必须归零**的 token。

**它最终去哪了**：`panel-prompt` 产出的整段文本就是 `panel.imagePrompt`，
生图时由 `panelPromptService.buildFinalPromptSections` 原样放进 `content`（`return { ..., content: imagePrompt.trim(), ... }`），
所以「表现元素：」这一行**逐字进入最终生图提示词**，不会被任何环节丢掉。

### 16.5 修正：「引导线」不需要（2026-10-05 用户实报）

**用户实报的产出**（画面描述里的「表现元素：」行）：

> 表现元素：萧媚视线方向用一条极淡的细引导线穿过人群，指向画面右远处的背影，不压人物面部。

**病根在我自己的模板**：§16.2 的悬浮散格规则第 5 条原文是「格间可用一条**细引导线**、视线或气尾串起阅读路径」。
「阅读引导」这件事本身没错（漫画确实靠人物视线、气尾指向、气泡摆放位置牵引阅读），但**「引导线」是一种画在画面上的元素**——
条漫里没有这种东西。模型把「视线方向」与「引导线」拼起来，就造出了一条现实中不存在的线。

**改法（4 处，两份画面描述模板同源）**：

| 位置 | 改动 |
|---|---|
| `PANEL_FLOAT_RULES`（**四份模板共用常量**，覆盖面最广） | 「中轴与引导」条改为「中轴与**视线**」：阅读引导靠构图与文字元素**自然形成**（人物看向的方向、气尾指向、气泡摆放的位置、明暗对比），**不要在画面里画引导线、指示线、视线连线或指向箭头** |
| `【表现元素】`（panel-prompt ×2） | 新增硬约束「**不画引导线**」：画面里不出现引导线／指示线／视线连线／指向箭头／任何画在画面上的路径标记；并明写**这条不要写进「表现元素：」行**（否则又变成新的固定尾段） |
| `【禁止项】`（panel-prompt ×2） | 新增「不得出现引导线、指示线、视线连线、指向箭头或任何画在画面上的路径标记（漫画里没有这种元素）」 |
| 【文字元素与气泡】分流第 6 条 | 「用气泡把视线引向下一格」补一句：这靠的是**气泡摆放的位置**，不是画一条线 |

**为什么要三处一起下**：错句是在「表现元素：」逐格行里产出的 →【表现元素】与【禁止项】必须显式禁；
而规则源头在共用常量，改那里一次覆盖四份模板，避免只改一处、别的模板继续诱发。
