## 资产生图配置「版式」tab 保存无效（真 bug）

**现象**：改版式文本 → 点「保存配置」→ 再次打开仍是默认推荐文本。

**根因**：`AssetImageGenDrawer` 的 `layoutDraft` 是 `computed({ get: () => ({...}), set })`，而模板写 `v-model="layoutDraft[field.type]"`。模板里 setupState 会 unref 拿到 ref 的 `.value`（getter 返回的**临时新对象**），赋值只改到那个临时对象，**setter 永远不会被调用** → 编辑内容静默丢失，`config.layoutPrompts` 保持打开时的值。
实测确认（最小脚本）：`draft.value.character = 'EDITED'` 后 `config.layoutPrompts.character` 仍是 `'RECOMMENDED'`。

**修复**：草稿改成 `reactive<Record<LongProjectAssetType, string>>` + `resetLayoutDraft()`（打开抽屉时按 `config.layoutPrompts` 重置，字段缺失则预填 `RECOMMENDED_LAYOUT_SPECS`）+ `handleSave` 里 `config.layoutPrompts = { ...layoutDraft }` 再 emit。

**同源第二处**（顺手修）：`ImageConfigDrawer` 的 `refUsageDraft`（分镜绘图配置「参考图用途」）是完全相同的写法，手改同样不生效。
- 改法同上；新增 `mergeRefUsageDraft()`，`save` 与 `autoSaveConfig` 两个「读 config 落库」的地方都先合并草稿。
- 三字段全空 → 存 `undefined`（语义 = 全走内置默认），不留空壳对象。
- `resetRefUsage()`（恢复默认）必须同时清草稿，否则输入框还显示刚被清掉的旧文案。

**通用红线**：`computed` 返回对象，就不要在模板里对它的属性 `v-model`（`v-model="c[field]"`）。要么 `reactive` 草稿 + 显式重置/回写，要么 `@input` 显式调 setter。

## asset-prompt 人物提示词缺性别/年龄/身高（模板重写）

**现象**：生成的资产绘画提示词只有形容词（「极度高瘦且病态苍白的窄肩身形…」），没有性别、年龄、身高，生图无法控制比例。

**根因（两层）**：
1. 模板规则是「清单没写的字段跳过，不许编造」；
2. 存量资产（2026-10-23 字段化之前提取）`attributes` 里根本没有「性别年龄／身高体型」，只有一段散文描述 → 模型只能跳过。
不是解析或拼接问题：`buildTargetList` 的 `slice(0,8)` 顺序是对的，attributes 也只装字段行（别名/重要性/原文依据/描述/视觉描述/剧情锚点/绘画提示词/状态标签 都在解析器里特判掉）。

**改法（四处同源 + 测试 + 文档）**：
- `promptTemplateRegistry.ASSET_PROMPT_FORMAT`：加人物「十项必须写到」清单 + 两条缺失处理；字数 150~220 → **160~260**。
- `RECOMMENDED_TEMPLATES['asset-prompt']`：把【人物：固定输出顺序】换成【人物：十项必备要素】，新增【缺失项怎么补】：
  · ② 身高体型：形容词必须换算成可测量的量（「极度高瘦、窄肩」→「约 182cm·7 头身·极瘦·窄肩」），只做量级换算、不新增特征；
  · ① 性别年龄：只认明确线索，**无线索不写、绝对不许猜性别**（猜错骨相，比缺更糟）；
  · ③~⑧ 缺了就跳过；推断值跨状态必须同一组。
  · 新增「可画的量优先」：程度词 → cm／头身比／可画痕迹。
- `assetPromptService.buildSingleAssetPrompt` 默认指令同步（单条重写路径）。
- 🔴 **输入侧**：`buildTargetList` / `buildSingleAssetPrompt` 对人物补一行「缺失必填项：…（按描述换算，不得猜测性别）」。没有这行，模型读到的是「清单里没这两个字段」→ 按默认规则跳过，模板写再多也没用。`missingCharacterTraits` 用关键词模糊匹配（性别/年龄、身高/体型/头身），兼容手改过的键名。
- `extract` 模板：前两行必须给可画的量（身高带 cm、头身比、体型、肩型），「不许只留形容词」+ 自查一条，让新数据一次到位。
- 测试：`promptTemplateRegistry.test.ts` 加十项/换算断言；`promptBuilders.test.ts` 加缺项标注三例（缺→标、有→不标、场景道具→不标）。全量 43 文件 / 551 项通过。
- 文档 `docs/资产绘画提示词-新口径与示例.md`：标注旧「脑补补全」口径已废弃，补《2026-10-24 人物十项必备要素》一节（十项表 + 缺失规则 + 改前改后 + 字数）。

**遗留判断**：老资产要不要重跑提取？模板换算能立刻救回比例，但性别只能靠描述线索；对主要角色建议重新提取一次拿到精确字段。


## 二次修正：③~⑧ 从「缺了就跳过」反转为「必须推定写满」

**用户实报**：改完仍缺——输出只有「男；约182cm、7头身、极瘦、窄肩；常垂眼、薄唇；皮肤苍白、凌乱短黑发；…」，
脸型／眉眼／鼻唇（鼻梁鼻头）／皮肤头发细节／年龄全无。

**根因**：上一版把「③~⑧ 缺了就跳过，不许编」写进了模板。老资产 `attributes` 只给了 8 行里的 4 行
（性别年龄／身高体型／标志／面部张力），缺的 4 行按规则被忠实跳过。**规则写对了，但口径错了**——
用户要的是「人物特征全写清楚」，不是「清单没有就留白」。

**新口径：缺失字段分三类，措辞必须分开**（`assetPromptService.CHARACTER_REQUIRED_TRAITS` 加 `mode` 字段）：
- `convert`（性别年龄／身高体型）：只换单位与量；性别线索不明确整项不写，**绝不猜**。
- `infer`（脸型／眉眼／鼻唇／皮肤头发／面部张力）：缺字段**必须推定一组协调值写满**。
  推定依据只用已给事实——性别年龄定骨相与肤质、身高体型定面部脂肪、面部张力定眉眼与唇角走向、身份定肤质。
  **先搬用资产描述/视觉描述/固定特征里已有的写法**（「圆脸」「单眼皮」「垂眼」），推定只补真的没有的部分。
  每项必须写全：脸型＝轮廓·颧骨·下颌；眉眼＝眉形·眉头间距·眼型·眼距·眼皮·瞳色；鼻唇＝鼻梁·鼻头·唇厚·唇角；皮肤头发＝肤色·肤质·发色·发长·发质·发梢。
- `never`（痣／疤／胎记／纹身／义肢／眼镜／项链／手绳／手表）：清单没写就一定不写。母题与反差只在清单已写出时点明。
  **理由**：具体标记会被剧情核对，编一个断疤会跟后面几章打架；但骨相不会被核对，缺了只会让生图瞎猜脸。

**改法（五处同源 + 测试 + 文档）**：
1. `promptTemplateRegistry.RECOMMENDED_TEMPLATES['asset-prompt']`：开头「你不是设定稿作者——清单没有的信息不补」改成「不改写事实：身份层骨相允许受控补全」；【缺失项怎么补】重写成 A 换算 / B 推定 / C 绝不编 三段；⑦标志 标注「清单写了才写」；自查加「十项是否写满」「有没有编造标记」「骨相是否逐字相同」。
2. 字数 **160~260 → 200~320**（`ASSET_PROMPT_FORMAT` + 模板正文 + description 三处同改）。写满十项 260 字必然挤掉骨相。
3. `assetPromptService`：`missingCharacterTraits` 返回 `{ convert, infer }` 两组 + `missingTraitText()` 分措辞拼装；缺项**从每行状态挪到清单末尾**统一一段【缺失项提示】，**按 asset.id 去重**（多状态只提示一次，否则同一资产 3 个状态刷 3 遍）。
4. `buildSingleAssetPrompt` 兜底指令同步（单条重写路径与批量路径同口径）。
5. `extract`：加规则「脸型／眉眼／鼻唇／皮肤头发这四行是骨相，必须写全、一行不能省，原文只给零碎词时按性别年龄与体型推定补全」+ 自查「这 8 行是否真的都输出了」。原模板只有示例值、没有强制规则，这很可能是 4 行丢失的原因之一。
6. 顺手：模板加「资产名只写名字本身，清单里的类型括注（人物／场景／道具）不要带进提示词」——实跑输出开头是「宋玉（人物），男」。

**测试**：`promptBuilders.test.ts` 断言从「缺失必填项：…」改为「【缺失项提示」+ 推算措辞，新增「多状态只提示一次」用例（`split('面部张力——字段缺失').length - 1 === 1`）。相关两文件 61 项通过。

**新遗留风险（要告诉用户）**：推定只保证**同一次请求内**跨状态一致。分两次生成（先出状态A、再出状态B）会得到两张不同的脸。
根治办法不是更强的提示词，而是**把 8 行字段真正落库**——即对缺骨相的老资产重跑一次「本章资产提取」。

## 资产生图的「动态参考图」清单（生图工作台复用同角色）

**用户诉求**：生成同一个人的另一个视觉状态时，要去资产库勾图，再手写「参考图X的人物形象」。想要快捷化。
他自己提的方案是「选图时编好话术 → 确认自动插入提示词，但图号要算」。

**先纠正的认知**：图号早就有了 —— `AssetVariantCard` 的参考图角标 `图N` 就是实际发送数组的顺序。缺的是**「图N 是什么」的定义段**：分镜侧 `buildFinalPromptSections` 一直在生成【动态参考图】，资产侧 `composeAssetPrompt` 一个字都没有。

**为什么不能写进正文**（用户原方案的三个坑）：
1. 图号写死 → 之后追加图 / 关掉「拼接共用属性」会整体位移，**不报错，只是安静画错**；
2. 正文会被「批量生成 / 重新生成」覆盖；
3. 同一角色 5 个状态要写 5 遍。

**做法（与分镜同源：清单在生图那一刻现算）**
- 新 `services/assetRefManifest.ts`：`buildAssetRefManifest`（取图 + 判归属）、`buildAssetRefSection`（渲染 `图N = 标签：用途`）、`previewRefImageIndexes`（选图弹窗的图号预览）。
- 新 `services/assetRefUsage.ts`：资产侧**独立**的三段用途模板（不与分镜共用），默认文案刻意不同——
  🔴 人物默认 = 「身份参考，仅取脸型、五官、发型、肤色与体型；**服装与当前状态以本段文字为准**」。
  不这么写，模型会连参考图的衣服一起抄，提示词里刚写的新服装直接失效（用户实报痛点）。
  占位符 `{图号}`，运行时渲染，所以用户写跨图引用也不会错位。
- 类型 `AssetGenConfig.refUsage?: Partial<Record<LongProjectAssetType, string>>`。
- `composeAssetPrompt` 顺序改为 **front → layout → 参考图清单 → 正文 → back**（与分镜 front→references→content→back 同构）。
- 选图弹窗加「参考描述」区：人物/场景/道具三段切换、`insertImageNumbers` 按光标插入 `图2、图5`、只在确认时 emit 一次（避免写放大）。按钮 disabled 条件放宽成「没选图但描述改过」也能保存。
- 卡片加「复用同角色」按钮（`siblingReferenceFor`）：一键带入同资产其它状态的首张成品图，**跳过已在参考图里的**，所以连点可依次带入多个状态。查找用 `props.allAssets` 补全（本章 variants 已被章节引用过滤）。

🔴 **顺序红线**：`buildAssetRefManifest` 的取图顺序必须与 `AssetWorkbench.genRefImages` 完全一致（共用属性 front 图 → 本状态图），否则图号与卡片角标、发送数组全部错位。

🔴 **踩到的坑**：`AssetImageGenDrawer` 保存时 `emit('save', 整份 config)`，而它的 reactive 初始化只有旧字段 → 打开抽屉点保存会**悄悄抹掉 refUsage**。已在 reset 里显式 `config.refUsage = clone(props.config.refUsage)`。**以后给 AssetGenConfig 加任何字段都要检查这个抽屉**（layoutPrompts 当年也是同样的问题）。

**测试**：`tests/modules/assetRefManifest.test.ts` 13 项（顺序/后置块排除/attachShared 开关/默认文案/自定义模板/空串回落/图号预览去重）。全量 44 文件 / 566 项通过。

**遗留**：用户此前手写在正文末尾的「参考图X的人物形象」会与自动清单重复，需要他手动删（正文是直译层，那句本来就不该写在里面）。

## 五次修正：弹窗底部按钮溢出 + 参考描述标题按类型改名
