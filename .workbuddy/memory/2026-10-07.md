## 二次修正：「性格」→「气质」＋ 迁移 character-casting-studio 的人物设计方法论

**用户原话**：「也不是性格，应该是气质」；并给出 `dacnay816y62-hub/character-casting-studio-skill`
（写实人物 casting 设计 skill），要求结合本项目改造。

### 口径修正：从「一个抽象词」到「两处落点」

用户的反感点在**旧写法会把气质当形容词写**。「高冷 → 眼神清冷疏离」会被生图读成一张**当场的表情**，
随剧情情绪漂走。新口径拆两处：

| 落点 | 内容 |
|---|---|
| **资产级字段行** | `- 气质：清冷、克制、有距离感`（2~4 个基调词，落 `attributes`，零代码） |
| **资产「描述」第 3 维（面部张力）** | **只准落四处**：① 眉眼舒展度/眉头间距 ② 唇角走势 ③ 咬肌与下颌松紧 ④ 目光（聚集/疏离、直视/低垂） |

🔴 **通用判定：气质的落点必须写成可测量的结构量，不能写成形容词。**
`asset-prompt` 侧措辞从「化成**静态可读的气质**」改为「落成**看得见的静态生理结构**」，并把四处写死。
**气质三禁**：不写情绪词、不写表情动作、不写台词。**不碰躯干与四肢**（体态属 A-POSE 版式，写了打架）。

### 从该 skill 搬过来的两条新规则

1. **补全的取舍顺序**（两个模板都写）：
   `清单硬事实 > 气质 > 识别锚点 > 面部骨相（脸型/五官结构/颧骨与下颌）> 具体取值（发色/肤色/材质/颜色）> 装饰性细节`。
   出处 `character temperament > identity memory anchors > realistic human bone structure > ...`。**硬事实永远第一**。
2. **人物差异矩阵**（替换原「剪影可辨与体型差」）：同章主要人物**两两至少 5 维**明显不同，
   共 12 维（脸型/眼型眼距/眉形眉头间距/鼻型/唇形唇角/下颌线/发长发质/肤色区间/年龄感/体型剪影/气质基调/识别锚点），
   反面样本写死「鹅蛋脸＋黑色直发＋大眼睛＋高鼻梁＋中性表情」。出处 identity matrix（`not sisters, not twins`）。

**骨相维补齐**：第 2 维补「颧骨的高低与位置、下颌线的走向与宽窄」；第 3 维改名「**五官特征与面部张力**」。

### ⛔ 明确不搬

- **摄影/渲染层**：蜡像感、白平衡、85–105mm 焦段、白底、商业完成度 → 那是「共用属性」的画风职责，写进模板会打架。
- **素材驱动/版权层**：三分类素材包、source map、去身份化、不得复刻明星 → 本项目无真人参考图。
- **体态张力**：它把肩背松紧也算气质落点，本项目 A-POSE 版式已统一规定 → 不采用。

### 改动（6 个文件，均为模板/文案层，零结构改动）

`promptTemplateRegistry.ts`（`extract` 6 处 ＋ `asset-prompt` 5 处 ＋ `analysis` 1 处消歧）／
`assetPromptService.ts`（单条 fallback 写作要求）／`promptTemplateRegistry.test.ts`／`promptBuilders.test.ts`／
`docs/资产绘画提示词-新口径与示例.md`（补《外部方法论迁移》章节）／方案文档 §18。

`analysis` 那处是**消歧**：它的「气质」原先指「表情、站姿、习惯动作」（叙事层），
改为「气质基调 ＋ 静态表现 ＋ 叙事表现」三段并列，免得与资产层的「气质」撞名。
`script` 模板的「角色性格」不动（指原文里的人物性格）。

**校验**：`vitest` 43 files / **543 tests passed**；`vue-tsc --noEmit` **exit 0**。

## 第三次修正：删除「媒介质感锚」（固定尾段）

**用户原话**：「资产绘画提示词生成最后为啥都有『带有轻微漫画杂志印刷质感。』这种呢，这个规则去掉吧」。

**根因**：`asset-prompt`【去 AI 味】写着「每条带 1 个媒介质感锚」——**取值空间封闭**
（纸张颗粒／网点／笔触三种），模型必然反复选同一句 → **退化成固定尾段**；
这与同模板已立的「禁止项不许写成固定尾段」红线自相矛盾，也与 `panel-prompt`
「媒介质感归共用属性、不要重复描述」**互相打架**（同工程里分镜禁写、资产必写）。

**改法（模板 5 处同改 ＋ 单条路径 ＋ 测试 ＋ 文档）**：

| 落点 | 改动 |
|---|---|
| 开头总纲 / 【与共用属性、版式的分工】 | 补入「媒介质感（纸张颗粒、网点、笔触这类）」→ 归**共用属性** |
| 【去 AI 味】 | **删「每条带 1 个媒介质感锚」** → 换成禁令：不写媒介质感与画风词、不给每条结尾挂同一句质感标签；点明「**去 AI 味的落点是主体自身的具体瑕疵，不是加一句质感描述**」 |
| 【用语要求】 | 「不写绘画风格与渲染画质词」→ 「不写绘画风格、渲染画质与**媒介质感**词」 |
| 【自查】 | 「与 1 个媒介质感锚」→ 「有没有在末尾挂媒介质感／画风句（有就是越界）」 |
| `description` / `assetPromptService.ts` 单条 fallback | 同步 |
| 测试 | `toContain('媒介质感锚')` → **`not.toContain`**；并断言**模板里不得抄回该句原文**（抄了模型就会照写） |
| `docs/资产绘画提示词-新口径与示例.md` | 三份样例末尾的「轻微纸张颗粒质感。」**全删**；迁移表「生活痕迹」行注明该锚**不采用** |

**沉淀一条通用判定**：**「每条都要带 X」这种写法，只要 X 的取值空间是封闭的，就一定退化成固定尾段。**
放行「每条必带」的前提是取值逐条不同且由清单决定（如不完美细节 `人物 ≥2 项`），否则一律改成「由共用属性统一拼接」。
详见 `topics/asset-pipeline.md` §7.17；方案文档 §19。

## 第四次改动：剧本「开场与收尾」——爆款开头 + 章末留人

**用户原话**：「最先把小说的爆点展示出来吸引人，然后结尾留足悬念」，并追问「是不是改剧本提示词模板就行了，
分镜生成的模板就按前面生成」。

### 研究结论（短剧／漫剧／条漫三方向共性，已核过来源）

黄金 3 秒开场不铺垫（**漫剧拆解 100 条里 95 条前 3 秒都是「强冲突画面 + 一句悬念台词」**）；
卡点停在危机爆发前／真相揭露前／反转那一瞬；首尾双钩子；每 30 秒一个小钩子、每 3 集一个闭环；
钩子要与下一集爽点强关联；条漫特有**首屏 hook + 话末卡点（最后 3~5 格，决定付费转换）**。

### 回答用户的问题：分镜确实不用改，但画面描述要补一条

分镜（`storyboard`）**保持原样** —— 这是既有分工、不是省事：测试里早有断言
`expect(storyboard).not.toContain('页尾钩子')`，理由是 `备注` 会被 `cellScanText` 扫描 → 钩子里出现角色名会误报未绑定。
钩子从一开始就归画面描述层（`panel-prompt` 第 7 条，靠构图与焦点实现、不改台词）。

两个真缺口：① 旧 `script` 模板**一个字没提**开场怎么起、章末怎么落，且 `剧情目的` 里有个 `收束` 枚举等于鼓励把章末「收」掉；
② 画面描述层只有**平的**「每页末格留牵引」，缺**章末页**这一档。

### 改动清单

| 落点 | 改动 |
|---|---|
| `script` · 角色定位 | 加第 6 条专长「连载内容的留人节奏」 |
| `script` ·【强制写作流程】 | 加第 4 步「先定两端，再写中间」 |
| `script` · **新增【开场与收尾】节** | 开场（禁铺垫清单 + 允许前置 + **前置三禁**）／章末（**禁收干净** + 六类钩子 + 只调落点不调内容 + 钩子必须画得出来）／中段（每 3~5 场一爆点） |
| `script` ·【改编要求】+ 格式段 + `description` | 新增字段 `- 钩子：`（位置在「场景」后），**只有第 1 场与最后一场写**；末场剧情目的不得只写「收束」 |
| `panel-prompt` × 2 · 正文 | 新增第 8 条**章末页强化**（最后 1~2 格给本章最强悬念、最大格/最集中焦点/最少文字、悬念停在未解决处） |
| `panel-prompt` × 2 · 格式段 + `description` | 硬约束「章末页…禁止收束式画面」+ **「不要把这句判断写进输出」**（防新固定尾段） |
| 测试 | script 组新增一整个 `it`（约 25 条断言）；panel-prompt 组两份同源 + 格式段 + storyboard 仍无钩子的回归守卫 |

### 沉淀三条判定

1. **钩子不是一个模板能装下的**：章级（剧本）／页级（分镜，刻意不写）／格级（画面描述）各管一段。
2. **前置唯一真正的坑 = 跨越状态切换点** → 第 1 格要声明一个后面的资产状态，分镜判断不出来。
3. **章末页判定零代码**：`{{本章分镜概要}}`（`buildChapterOutline` 每行一镜）最后一行序号 == `{{当前分镜}}` 的分镜序号。

**校验**：`vitest` 43 files / **544 tests passed**；`vue-tsc --noEmit` **exit 0**。

⚠️ 生效三步：设置页 → 提示词模板 →「长篇章节漫画剧本」点「填入推荐模板」；两个画面描述模板**都要点一次**。

## 2026-10-07（续）分镜「叙事连贯」：全章台词 + 旁白要能连读成一条故事线

用户：「我感觉需要所有分镜把整个事件串联起来，主要是通过旁白内容和对话内容，这两个要能知道整个小说的走向和故事」，并要求先调研他现在的分镜生成方式对不对。

### 调研结论（McCloud 镜头衔接 / 漫画脚本教程 / 漫剧拆解 三方交叉）

- McCloud 六种镜头衔接里 **scene-to-scene（跨时间、跨空间）读者最容易迷路**：「Always pair with a caption or an establishing shot or **the reader is lost**」。
- 另一本分镜模板 FAQ 点出最常被漏的两件事：**「这一格是谁的视角」与「距上一格过了多久」**（「Leave those out and the finished art will feel off」）。
- 旁白的**唯一正当用途**是「补画面给不了的信息」；**复述画面＝错误**（comicink 常见错误清单含「Captions repeating the panel」）。
- 诊断法：**把这一页读给一个不知道故事的人听，让他复述「主角是谁、赌注是什么」** —— 讲不出来就是没写完。

**判读**：现有 `storyboard` 模板**没错，是缺一层「过桥」** —— 旧【旁白怎么写】「来源唯一＝逐字继承剧本/原文、没叙述就整行省略」漏了「剧本与原文都没写叙述句、但这一页已经跨了时间/地点/视角」这一类。

### 改动（只动 `promptTemplateRegistry.ts` + 测试 + 文档，纯模板）

| 落点 | 改动 |
|---|---|
| `storyboard` · **新增【叙事连贯】节**（插在【信息取舍】与【分格原则】之间） | 判定标准（连读能答 谁/在哪/发生什么/为什么/接下来）／**三类断层必须用旁白过桥**（时间跨越·地点转移·视角切换 + 可画写法）／取材只允许来自剧本场景头、**只交代跨度不写剧情**／因果断口补前因／**主线必须落在文字上**／**不许复述**／**只在断层处补、不是每页都写**／连读自检不作为输出 |
| `storyboard` ·【旁白怎么写】 | 「来源唯一」拆成**两种职责、两个来源**（原文旁白＝逐字／衔接旁白＝跨度的桥）；一格最多一条 + 衔接旁白优先落无台词文字的格；末条改为「无叙述文字**且本页无跨越**才省略」；禁止借它编剧情/加人物/改对白 |
| `storyboard` ·【台词怎么写】 | 补「**台词是故事主线的主要载体**」——关键台词一句不漏、额度不够拆格拆页 |

| 测试 | 新增一整个 `it`（约 20 条断言）+ storyboard 仍无「页尾钩子」的回归守卫 |

### 三条沉淀

1. **零字段新增**：主线类信息只能折进既有 `旁白`/`台词`（新字段名 → `SPEAKER_RE` → 变成一句台词被画进画面，见 §11.1）。
2. **「只在断层处补」是防固定尾段的关键** —— 「每页都要交代跨度」会立刻退化成每页挂同一句（同 §19 媒介质感锚的病）。
3. **衔接旁白只放分镜层，不动剧本层**：剧本场景头已给「地点 + 时间」，从剧本取材不算编造；两层都写会口径打架。
4. **画面描述层零改动**：衔接旁白就是普通 `旁白` 字段 → `panel-prompt` 既有的「旁白＝方角矩形框、无气尾、贴左上/左下」自动接管。

## 画面描述层：主观视角 / 背景与群众补全 / 文字零遗漏（用户四项诉求）

用户诉求：① 旁白和对话不能遗漏、要准确描述出来；② 没有场景的分镜要脑补出背景；
③ 群众人物要简单描述出来；④ 人物主观看任何东西（看手机/信件/书…）不能只写「看手机」——
生图模型会把屏幕翻向读者，应该「人物看屏幕、手机背面朝读者，内容用另一个 POV 画面体现」。

### 根因（④）：一格塞两个视角，物理上不成立

「她在看手机」要她侧/背对镜头，「屏幕内容正对读者」要屏幕正对镜头 —— 模型只能二选一，它选了让屏幕朝读者。
**不是模型不听话，是指令自相矛盾。**
分镜层原本已有拆格意图（【分格原则】「看手机/电视/书/窗外，同时读者也要看到内容时，必须拆成两格」），
但**画面描述层没有任何落地口径** → 拆格意图在下一环节蒸发。

### 改动（`promptTemplateRegistry.ts` + 测试）

| 落点 | 改动 |
|---|---|
| **新常量 `PANEL_POV_RULES`** | 主观视角：观看格物件**只露背面/侧缘**、屏幕内容/字迹/图文**一律不画**；内容另占**POV 格**（只画内容物正面、**不出现人物的脸和上半身**）；POV 格紧跟观看格且取景落在观看视线上；**分镜没给 POV 格时不许自己加格**；一格只允许一个观看方向；同类清单（手机/平板/电脑·信件/文件/账单·照片/相册·书/报纸/清单/告示·门缝/猫眼/窗外/监控·镜子） |
| **新常量 `PANEL_BACKGROUND_RULES`** | 背景与群众：**场景为空的格必须补写实背景**（空间类型＋时代地域＋2~3 件标志性物件＋光源方向与色温），禁止「虚化/纯色/无背景/留白」，可省细节不可省光线；**群众是背景不是角色**（数量＋随身特征＋在做什么，群体词指代，不给姓名/资产名、不给面部特写、不互动、不抢焦点、不撞主角辨识特征） |

| `panel-prompt` ×2 ·【禁止项】 | 「不得添加分镜之外的角色、道具或场景元素」**拆两条**：只禁**剧情角色**；**群众不许起名号/写成资产名** |
| `panel-prompt` ×2 ·【写作要求】 | 「要素齐全」补**交付前文字清点**自检（附「不要写进输出」）；「不要补写原文没有的**细节**」→「**剧情**」，并把补背景/群众、POV 处理、视觉参数列为**必做项** |

### 三条沉淀

1. 🔴 **跨界面的规则必须钉在「能改的那一层」**：格数/格序只有分镜能定 → **拆格归 `storyboard`**；
