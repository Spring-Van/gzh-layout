## 诊断：分镜 ↔ 资产视觉状态绑定为何遗漏（只诊断，未改代码）

用户反馈分镜绑定资产状态有遗漏。全链路排查结论（含行号，便于下次直接下手）：

**根因：状态身份以自然语言传递三次，每次靠字符串猜回来。**

1. 提取侧模型写 `### 视觉状态：状态名`（promptTemplateRegistry.ts:215），分镜侧模型独立写 `出场资产：资产名（状态名）`（:206）。中间的注入清单 `renderChapterAssetsText()`（storyboardService.ts:21-37）是纯散文，**无编号无 id**。`bindingsFromValue` 的 `exact` 是全等匹配（:105）→ 措辞一差就断。
2. `defaultVariant()`（storyboardService.ts:70-91）判据只有**章节级**顺序（chapterRange/firstAppearanceChapterId）。同章内状态切换 → `latestStart` 相同 → `latest.length>1` → 无唯一默认 → `return undefined`（:87）。**系统内不存在章内时间轴**，它除了放弃别无选择。
3. `LongProjectChapterAsset.variantId`（types:115-126）是人工确认过的状态证据，但只用于过滤注入清单（LongProjectStoryboardTab.vue:512-526）与判孤儿；绑定回填走的是 `defaultVariant` 重新猜（assetExtractionConfirm.ts:289）。且 `appearance:'changed'` **无任何产出路径**（:269 只写 introduced/reused），是个死字段。
4. 静默丢弃链：`findAsset` 要求唯一精确命中（storyboardService.ts:62-67）→ `detectAssetSpans` 歧义名 continue、<2 字不入索引（promptAssetService.ts:57,30）→ `cellScanText` 不扫台词旁白（:99-103）→ `resolvePanelBindings`/`resolveCellBindings` 找不到 variant 直接 continue（panelPromptService.ts:43-45,102-104），绑定在取图/统计中彻底消失。
5. **人工兜底缺口**：PanelAssetTabs.vue 的 `entries`(:236-242) / `drawerEntries`(:379) / `saveDrawer`(:423) 全部只遍历**已有绑定** → 无法补一条漏掉的绑定，也没有逐格绑定 UI。漏了只能回去改 Markdown 重解析。

## 定位并修复：编辑器保存后丢资产状态（同日，真正根因）

用户提示「是不是输入框保存后又做了解析导致值变了」——**完全正确**。

**证据链（先证数据无责，再证编辑器有责）**：
1. 读真实落库数据 `%APPDATA%/gzh-layout/comic-gen.json`（项目 22，章节 7b91b20b）：最近 4 次手动导入的 13 镜绑定**全部正确**（assetId + visualVersionId + matchSource=model，0 未匹配 0 无状态）。用同一个 run 的 `rawResponse` + 真实 assets/chapterAssets 跑「预览路径（裸解析）」vs「导入路径（解析+syncPanelsAutoBindings）」逐镜对比 → **完全一致**，sync 只多补 auto-text。→ 导入链路无责。
2. 历史 17 个 run 里，17:32 那批老数据确实存在「无状态」绑定（最多 17 条），17:35 之后都干净——症状真实存在过。

**根因（一行）**：`parsePanelBlock(text)`（storyboardService.ts:799）以 **空 assets / 空 chapterId** 调 `parseStoryboardResponse` → `bindingsFromValue` 里 `findAsset` 必失败 → `visualVersionName: variant?.name` 变成 `undefined` → **状态名在编辑器解析这一步就被丢掉**。于是：
- `serializeBindings` 只写回资产名 → 输入框里 `出场资产：测验魔石碑（萧炎测验·三段显示）` 被悄悄改写成 `出场资产：测验魔石碑`（用户所说的「变成了另外的样子」）；
- `savePanelEdit` 重解析时只剩名字 → 状态落到 `defaultVariant()`，而**同章多状态无唯一默认时返回 undefined** → `visualVersionId` 为空 → `resolvePanelBindings` 直接 `continue` → 取图清单/中栏里该资产消失（看起来像「导入没绑定成功」）。

**修复**：`bindingsFromValue` 的 `visualVersionName: variant?.name ?? (asset ? undefined : visualVersionName)`——**资产整体未命中时保留文本原样状态名**；资产命中时口径不变（仍只存实际匹配到的状态名，保证「显示状态」与「发送图片」一致）。这条同时让 `resolvePanelBindings` 的 `find(name === visualVersionName)` 兜底生效。

**复现/回归测试**：新增 `tests/modules/panelEditRoundTrip.test.ts`（7 例，锁死「文本里写了什么，往返后还是什么」）：往返留状态名 / 文本不悄悄改写 / 重解析还原同一 id（`['v1','v4','v1']` 而非 `[undefined,'v4',undefined]`）/ 未命中保留原文 / 命中但状态写错仍回落 / 只写资产名不凭空造状态 / 编号剥离不污染资产名。修复前 5 条红、修复后 7 条全绿。全量 **312 通过 / 0 失败 / 28 文件**，`vue-tsc --noEmit` 零错误。

## 答疑：「描述过期(stale)」标记机制与粘性问题（只诊断，未改代码）

左栏 `PanelListSidebar.vue:97-108` 共 **8 种标记**，if 链优先级：生图中 > 推导中 > 推导失败 > 生图失败 > **描述过期** > 已成图 > 已描述 > 未推导（即 stale 排在「已成图」之前，成图后仍显示过期）。另有缩略图「当前」角标 + 顶部 `N 已描述 · N 已成图` 统计。

**stale 打标两处**：`panelPromptService.migratePanelArtworks:416-422`（重跑/导入分镜后按 order 对位迁移）与 `useStoryboardOps.reevaluatePromptStatus:162-166`（合并/拆分/编辑后重估）。条件均为 `contentChanged && imagePrompt 非空`。

**根因（真实数据实证，项目 22 / 章节 7b91b20b）**：
- 17:32 那批 11 个 run 内容各不相同（14/33/38/31/32/7/8/25/13/18/17 镜）；
- **17:35:58 起 6 次导入 rawResponse 完全一致（4881 字符）、13 镜 content 逐字符相同**；
- 13 条 artwork 全部绑定到最新 run 的 panel、`promptStatus='stale'`、`updatedAt` 每次导入被刷新为迁移时间；
- 抽查 3 条描述：P3 已存描述讲「少年冷笑斜视萧炎」，当前 P3 是「广场+萧炎走向末排」→ **描述确实停留在 17:32 那版分镜，是真实警告不是误报**。

**机制缺陷（结论）**：`migratePanelArtworks` 的判据是「相邻两版 content 是否相同」（`oldPanel.content !== target.content`），且 stale 是**单向棘轮**——`contentChanged=false` 时走 `: artwork.promptStatus` 保持原值，**从不因内容一致而清除**。所以首次内容变化打上 stale 后，之后无论重复导入多少次相同内容都不会自愈，系统也没有「描述对应哪一版内容」的记录。

**建议修法（待用户定）**：① 给 artwork 加内容指纹（描述生成时记录对应 panel.content 的 hash），重新导入时 `当前指纹 === 描述指纹` 即判为新鲜，可自愈（老数据无指纹回落现逻辑）；② 提供手动「标记为已核对」入口清 stale；③ hover 提示 stale 含义。
