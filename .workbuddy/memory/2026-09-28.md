## 资产提取默认模板：新增「道具排除规则」（人物穿着不再重复建道具）

**问题**：默认模板下，道具区把人物穿在身上的服装也提取成独立道具资产（如「萧薰儿紫色衣裙」「萧炎素色交领衣衫」「萧炎掌心指甲」），与人物视觉状态重复，同一件衣服被生图两次且两处描述易写歪。

**改动文件**：`src/modules/comic/services/promptTemplateRegistry.ts`
1. `RECOMMENDED_TEMPLATE_BASE.extract.content` 新增【道具排除规则：人物身上的东西不算道具】（约 483 行）：
   - 服装/鞋袜/腰带/发带/首饰/随身武器归人物第 7 维（服装）与第 8 维（配饰），禁止再作独立道具；
   - 判断口径：能不能脱离人物单独摆在地上出图；
   - 例外：剧情围绕该服装/配饰本身展开且需单独特写时，才建道具并写明理由；
   - 自查项：道具清单里不得混进人物穿着。
2. 【整体提取规则】补一条「人物只提取身体与穿着；穿着与随身物不另建道具」。
3. 【自查】新增一条道具清单检查。
4. `OUTPUT_FORMAT_SPECS.extract`（约 215 行）补一行硬规则 —— 该段会拼进推荐模板末尾，也是「返回格式」的唯一来源。
5. `description` 同步更新。

**关键口径**：模板有两层 —— `RECOMMENDED_TEMPLATE_BASE.extract`（正文）+ `OUTPUT_FORMAT_SPECS.extract`（返回格式），由 `withFormatSpec()` 拼成 `RECOMMENDED_TEMPLATES.extract`。改规则要两处都改，否则「填入推荐模板」后仍缺一半约束。

**注意**：用户若已在设置页存过 extract 模板，`defaultTemplateContent('extract')` 不会被读取（存量模板优先）。需要用户在设置页重新点「填入推荐模板」或在原模板上手动加这条规则。

### ⚠️ 关键坑（务必记住）

**手动新建资产写章节引用时，必须写 `origin: 'extraction'`（或不写 origin 字段），绝不能写 `'manual'`。**
因为 `assetExtractionConfirm.ts:269` 的 `buildExtractionConfirmResult` 重建本章引用时只保留 `origin === 'manual'` 的条目，而资产本体（`scope:'chapter'`）会被第 265 行的过滤器剔掉 —— 若引用写成 manual，下次「确认本章资产」就留下一条**指向已删资产的悬空引用**，且 manual 引用不参与悬空清理，成为清不掉的死数据。代码里已用注释标明，改这块时别顺手改成 manual。

## 第二轮调整（用户反馈三点）

### 1. 删除入口改为「列表项 hover 图标」
- **上一版用的是 Tailwind `group` + `group-hover:opacity-100`，悬停不显示** —— 根因：`tailwind.config.js` **没有 `safelist`**，`group` 类被 purge 掉了，群组 hover 机制根本不成立。
- 改为 scoped CSS：`.owned-row:hover .owned-remove{opacity:1}` + `.owned-remove{opacity:0}`（另有 `:focus-visible` 兜底键盘操作）。已 grep 构建产物确认 `.owned-row:hover .owned-remove[data-v-...]{opacity:1}` 正常输出。
- 同时删掉了中列「资产信息」标题行右侧那个「删除资产」文字按钮（用户要求取消）。

### 2. 所有资产都能删（解除取值限制）
- **原因**：删除入口此前挂在提取候选上、靠 `suggestedAsset`（候选命中已有资产）显示，所以「本次没识别到的资产」没有删除入口 —— 看起来像权限控制，其实是数据来源太窄。
- 改为：`LongProjectAssetExtractionReview` 新增 `ownedAssets` prop，左列新增「本章已有 人物/场景/道具」分组（独立于「本次识别」），每条资产行 hover 出删除图标。
- 容器侧新增 `ownedChapterAssets` computed：从 `chapterAssets` 取本章涉及的 `assetId`，过滤 `assets` 得到本章全部已有资产（**含本次未识别到的**）。

### 3. 「确认本章资产」可重复执行
- **原因**：`canConfirmReview` 要求 `latestRun.status === 'completed'`，确认一次后 run 变 `confirmed`，按钮即禁用 —— 想再刷一遍绑定只能重新跑提取。
- 改动：`canConfirmReview` 放行 `completed` **或** `confirmed`；新增 `reviewConfirmed` 判断是否已确认过。
- `confirmExtraction()` 本身就是幂等的（纯函数：`run` × 最新数据 → 重建同名状态 id 复用、重算绑定），重复执行安全。
- 按钮文案随状态切换：「确认本章资产」↔「重新确认本章资产」；`ConfirmExtractionDialog` 加 `reconfirm` prop，标题与正文同步改口径（新增一句「结果与已保存的一致时不会有任何变化，可安全重复执行」）。

## 第四轮：删除对**全部**候选项放开（纯新候选也能划掉）

用户指出：「现在是本次识别和本章已有的才能删除？应该都可以删除啊，比如我本次识别的我觉得多余了我就删了啊」。

**改动口径**：删除图标挂在**每一行**候选项上（去掉 `v-if="assetOfCandidate()"` 限制），点删除时按候选**是否命中已有资产**分两种含义：

| 情况 | 判定 | 确认文案 | 动作 |
|---|---|---|---|
| 命中已有资产 | `candidate.suggestedAssetId` 能在 `assets` 里找到 | 「将删除已有资产「X」（连同 N 个视觉状态与全部图片）……」 | emit `delete-asset` → 容器 `createAssetManually` 同级的 `deleteAsset()`，**动库** + 悬空修复 |
| 纯新识别（未入库） | 找不到对应资产 | 「将从本次识别结果中移除「X」……」 | emit **`remove-candidate`** → 容器 `removeExtractionCandidate()`，只改 `run.candidates` |

**新增实现点**：
- `LongProjectAssetExtractionReview.vue`：新增 `assetOfCandidate()` / `deleteTitleOf()`（图标 title 随含义变）/ `removeConfirmVisible` / `removePlan` / `requestRemove()` / `confirmRemove()`；`defineEmits` 补 `(event:'remove-candidate', payload:{candidateId:string})`；文件顶部补 `import ConfirmDialog from '@comic/components/ConfirmDialog.vue'`（该组件非全局注册，每个用到的文件都要显式 import）。
- `PanelGenAssetTab.vue`：新增 `removeExtractionCandidate(payload: {candidateId:string})` —— 走既有的 `updateRun(run.id, { candidates: run.candidates.filter(...) })`；**已 confirmed 的 run 拒绝改候选**并提示「本次结果已确认，如需调整请点右上角『重新确认本章资产』」（因为已确认的 run 不会再重新写库，静默改候选是假操作）；模板上绑 `@remove-candidate`。
- **emit payload 类型**：`remove-candidate` 传对象 `{candidateId}` 而非裸 string（与 `delete-asset` 的 `{asset}` 风格一致），容器 handler 签名要对应，否则 vue-tsc 报 TS2322。
