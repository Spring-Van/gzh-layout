### 补充定论：stale 到底是「哪里内容变了」（用户追问后查实）

**不是 P02 自己变了。** 实测 `d2f798dc`(09-21 09:35) 之后的所有 13 页 run（含最新 `ee3db6b4`）**P01–P13 正文 md5 完全一致**，即 13 页时代内正文一字未动。

**真正变的是分页结构**：`d2f798dc` 重导入时，前一版是 **`d0ed6c46`（09-20，17 页）**。`migratePanelArtworks` 按**页序号**对位（`oldPanel.order` → `newPanelByOrder.get(同一 order)`），逐页比对 `旧第N页.content !== 新第N页.content` —— **13 页全部不同**（17 页与 13 页的分页边界不同），故 13 页全被标 stale。这条逐页比对结果与实测「13 页全 stale」**精确吻合**，根因确认。

**另一个必须纠正的点**：`migratePanelArtworks` 成功迁移时 **`updatedAt: Date.now()` 是无条件写的**（`panelPromptService.ts:428`），所以「artwork.updatedAt == run.updatedAt」**不能**证明描述刚被生成/迁移过内容，只能证明迁移跑过。我上一次用它当「描述是这次导入的」证据是**误读**；真实判定应看 `promptSource`（manual/inferred）+ `promptStatus`。

**口径沉淀**：`stale` 的真实语义 = **「这份画面描述是给另一版分镜正文写的，不保证对得上当前页」**，其触发条件是**页序号的首页对位**，不是「这一页自己被编辑过」。所以最简单的用户操作（把 17 页版重导入成 13 页版）就会让**整章**变 stale，且描述内容仍停留在旧分页语义上。

## 三问排查：编辑往返 / 新状态绑不上 / 一镜两状态（只诊断，未改码）

### ① 分镜内容编辑 = 结构化重排，不是「变默认内容」

链路：`PanelContentEditor.commitDraft` → `parsePanelBlock(text)` → 父级 `savePanelEdit` 存 `panel.cells` → 回显时 `serializePanelBlock(panel)` 按**固定字段顺序**重生（`第X格` 标题重生，顺序 景别/镜头/画面/人物/出场资产/动作/表情/台词/旁白/音效/光效/备注）。**内容不丢，排版必被规整。**

实测 6 组往返（temp vitest 探针，已删）：

| 输入 | 结果 |
|---|---|
| 正常字段行 | 一致（仅末尾换行差） |
| 字段顺序打乱 | 重排为标准顺序 |
| 纯自由文本（无字段名） | 自动补 `画面：` 前缀，内容保留 |
| `出场资产：测验魔石碑（萧炎测验·三段显示）` | 往返一致 ✅ |
| **`- 画风：治愈系柔和光`**（markdown 列表 + 未知字段名） | **整行被静默丢弃** |
| **`画风：治愈系柔和光`**（无横杠 + 未知字段名） | **被误判成台词** → 回显 `台词：画风：“治愈系柔和光”` |

根因在 `storyboardService.ts:515-544`：未知 key 若命中 `FIELD_RE`（`- 字段：值`）走进 else 分支后落到 `else lastField = null` → 丢弃；未命中 FIELD_RE 则落到注释分支继续走台词解析 → 被 `SPEAKER_RE` 当成「说话人：台词」。**真实数据风险：用户自加字段会丢或变脏。**

### ② 新增视觉状态为何绑不上（设计使然，非 bug）

状态三级回落链：`variantMentionedInText`（状态名或 tags 在文本里 ≥2 字出现）→ `lastVariantByAsset`（上一镜延续）→ `defaultVariant`。新状态的名称几乎不会出现在分镜正文里，前两步都不中；而 `defaultVariant`（`storyboardService.ts:118-139`）在「同章多状态且无唯一默认」时**故意返回 undefined**（注释：不能靠数组顺序静默猜测）。**结论：多状态资产在无文本线索时必然落到「有资产、无状态」，只能手选。**

### ③ 一镜内能否绑同一资产的两种状态：**数据模型可以，UI 不行**

- **可以**：绑定分页级（`panel.assetBindings`）与格级（`cell.assetBindings`）两层。`bindingKey = assetId ?? 名称`，所以**页级一资产只可能有一条**；格级每格独立，可各持不同状态。
- **真实数据已存在**：P09 的 `测验魔石碑` = 格1 `萧媚测验·七段显示` + 格2、3 `萧薰儿测验·九段显示`。`resolvePanelAssetStates` 按 (资产, 状态) 展开成多条 entry，生图清单确实会出**两张图**（页级 九段 已在格级变体列表里，不额外补「整镜」条目）。
- **界面看不见**：`PanelAssetTabs` 的 `entries` 只由 `props.panel.assetBindings`（页级）构建 → 一卡一状态；抽屉也只切页级那一条。P09 界面显示 九段，与实际发图的 七段+九段 不一致。
- **手选会抹平**：`applyBindingFix(action:'set-variant')` → 先按 assetId 改页级那条（`LongProjectStoryboardTab.vue:833-836`），再把**所有**命中该资产的格级绑定统一改成同一 patch（`:842-860`）。所以手选后全镜只剩一个状态 —— 用户观察到的即 P05（页级与格级全是 七段显示）。
- 另注：**同一格内**重复声明同一资产会被 `mergeCellBindings`（`storyboardService.ts:228-234`）合并为首条 → 同格两状态连文本都表达不了（漫画语义上也不需要）。

**待用户定方向**（已给方案对比）：A=抽屉按格分组选状态；B=中栏展示改用 `resolvePanelAssetStates` 展开结果（一状态一卡）；C=只让多状态可见、编辑留后。

### ③ 补刀：解析时就存模型原文（用户追问「输入框还是自己格式化」后）

上一轮的 blockText 只在**用户编辑保存时**才产生 —— 模型生成的页没有 blockText，编辑框回落 `serializePanelBlock` 拼固定格式，所以用户看到的「还是自己格式化」属实。**根因：`parseStoryboardResponse` 一直把模型原文扔掉，只留格结构。**

改法：解析循环改为按下标遍历 `allLines`，记 `pageStartLine`（页头行下一行；无页头自动开页时为结构行本身），`assignBlockText()` 在页头分支与循环结束时把 `allLines.slice(pageStartLine, lineCursor)` 存进 `current.blockText`（trim 掉首尾空行，**页头行不进原文**）。空行在解析里被 `continue` 跳过，但原文按下标切块所以完整保留。

效果：模型/手动导入的分镜，编辑框显示的就是模型写的那段原文（`### 第1格`、`- 字段：`、空行、自定义字段全保留）；`parsePanelBlock` 自身往返也逐字一致。**legacy 数据（本轮之前解析的 run）仍无 blockText，首次打开显示的固定格式拼稿无法避免（原文已不存在于库中），编辑一次后即锁定为原文。**

校验：vitest **384 通过 / 0 失败（34 文件，panelMultiState 13 例）**，`vue-tsc` 零错误。

### ④ 编号（A1/B1/E1）不再被剥（用户贴 P13 实例后发现）

**「出场资产」行手写条目的四种落点（bindingsFromValue + findAsset，实测口径）**：
1. **写对**（名字归一化后全等命中资产名/别名 + 状态名精确）→ `model` 绑定；回写归一为「正式资产名（正式状态名）」，用别名写的会被替换成正式名。

## 中栏占位框两处修正（用户复测）
