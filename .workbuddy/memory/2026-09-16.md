## 资产确认支持「合并 / 覆盖」两种应用方式

**背景**：重新提取后用户无法选择覆盖还是合并，且审核页看不到归属建议（盲选）。梳理中发现原「合并」语义不纯：资产级 `content/description/attributes` 其实是**新数据优先**（会覆盖手工编辑过的内容），只有视觉状态是旧数据优先。

**改动**（4 个文件 + 新增 1 个测试文件）：

1. `types/index.ts` — 新增 `ExtractionApplyMode = 'merge' | 'override'`。
2. `services/assetExtractionConfirm.ts`
   - `mergeCandidateIntoAsset` 收紧为**已有值优先**：`asset.content || candidate.content`、`asset.description || candidate.description`、`{...candidate.attributes, ...asset.attributes}`；状态级 `existing.description || state.description`。aliases 仍求并集（身份标识不做取舍）。
   - 新增 `overrideAssetWithCandidate()`：资产级候选优先（候选为空回退旧值）；视觉状态**整表重建**，本次未出现的一律删除；重建时优先按 `suggestedVariantId` / 同名复用原 variant id，让分镜绑定尽量不悬空。**例外**：候选无任何状态时保留旧状态（防模型退化返回清空资产视觉身份）。
   - `buildExtractionConfirmResult(..., mode = 'merge')` 增参。
   - 新增 `repairDanglingBindings()`：覆盖删除状态后，`model/manual/chapter-range` 来源绑定的 `visualVersionId` 会悬空 → 回落到 `defaultVariant`；顺带同步改名后的 `assetName`。**只在原来有 visualVersionId 且已失效时修**，不主动给无状态绑定补状态；无变化返回原引用。
3. `panel-gen/PanelGenAssetTab.vue` — `confirmExtraction(mode)` 透传；**override 时对全项目 storyboardRuns 跑 `repairDanglingBindings`**（悬空即坏数据，不限本章）；新增暴露 `applySummary`（并入 N / 新建 M）。
4. `LongProjectAssetTab.vue` — 「确认本章资产」改**分体按钮**：主按钮按记忆的方式执行，右侧箭头展开菜单，菜单项 = 切换 + 立即执行；override 走 `window.confirm` 二次确认；方式记忆到 `localStorage['comic-long-extract-apply-mode']`。
5. `LongProjectAssetExtractionReview.vue` — 左列候选加「并入 XX / 新建资产」归属标签，右列 header 加「N 归属」，归属状态 tag 改虚线边框 + 紫点。

**校验**：`vue-tsc` 零报错；`vitest run` 175 passed / 16 files（新增 17 例）；`vite build` 成功（16.58s，产物 `D:/gzh-build-check`）。

**回答的既有疑问**：确认资产**会**回填分镜绑定，但只绑「分镜文本里出现资产名」的（`auto-text`），不是每个分镜都绑。

**遗留观察（未改）**：`LongProjectChapterAsset.appearance` 是按**候选**粒度标记（`candidate.suggestedAssetId ? 'reused' : 'introduced'`），所以「命中已有资产但新增了视觉状态」也会记 `reused`，语义略不准。属于既有行为，改动会影响其他消费方，暂不动。
