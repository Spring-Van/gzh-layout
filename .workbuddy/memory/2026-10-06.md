## 修复：不同章节的「生图工作台」显示同一组资产（跨章串数据）

**现象**：项目「长篇」下章节「111」「222」，资产 tab → 生图工作台内容完全一致。
**根因**（读真实数据 + 代码定位，证据确凿）：

- `PanelGenAssetTab.vue` 的 `workbenchAssets` 有一条兜底：
  `if (!selectedChapterAssets.length) return sortAssetsByExtractionOrder(props.assets, latestRun)`
  → **本章没有任何 `chapterAssets` 引用条目时，回退成全项目的 assets**。
- 真实数据（`~/Library/Application Support/gzh-layout/comic-gen.json`，project `f43e3610`「长篇」）：
  `chapterAssets` 8 条**全部属于 111**（`edcc1fd6`），222（`da6c89ad`）**0 条引用**、也没有 extract run。
  → 111 走「按引用过滤」得到 6 资产 / 8 状态；222 走兜底也得到同一份 → 两章看起来一模一样。
- 附带影响：tab 上的「提示词 x/y · 生成图 x/y」在 222 章节显示的是 111 的进度；
  222 里还能直接改 111 资产的提示词/生图。
- **口径不一致的铁证**：「图片」tab 用的是 `selectedChapterAssets`（严格按本章引用），
  222 在那边是空的，只有工作台串了数据。

**改动**（2 个文件）：

1. `src/modules/comic/components/panel-gen/PanelGenAssetTab.vue` — 删掉兜底分支，
   `workbenchAssets` 一律按本章引用过滤（与「图片」tab 同口径）；零引用 → 空数组。
2. `src/modules/comic/components/LongProjectAssetWorkbench.vue` — 空态分清两种原因：
   左侧「本章暂无资产」优先于「全部资产都已有参考图」；右侧空态补一句指引
   （资产按章节归属，先去「信息」页提取并确认）。

**校验**：`npx vue-tsc --noEmit -p tsconfig.json` → exit 0。

**教训（已写进 topics/asset-pipeline.md §7.13）**：
「本章无数据 → 回退全量」这种兜底在**按章节归属的数据上一定是 bug**，
表现为「不同章节显示同一份数据」；子 tab 之间必须共用同一个过滤口径。

## 修复：弹窗底部按钮尺寸不一致（只写 `secondary-button` = 走全局大号）

**现象**：批量生成绘画提示词弹窗底部的「复制提示词 / 导入外部 AI 结果 / 取消」
比「开始生成」大一圈。

**根因**：`src/style.css`（`@layer components`）里 `.primary-button` / `.secondary-button`
的默认值是 `padding: 0.625rem 1.25rem; font-size: 0.875rem` —— 即 10/20px 内边距、14px 字号的
「大按钮」。弹窗里**只写 `class="secondary-button"`** 的按钮就按这个大号渲染；
写了 `h-9 px-3 text-xs` 的才是 36px / 12px（Tailwind 的 utilities 层后于 components 层，
同特异性下可以覆盖）→ 同一个底部按钮组里两种尺寸混排。

**统一口径（项目惯例）**：弹窗底部按钮组 = 次要按钮 `secondary-button h-9 px-3 text-xs`、
主按钮 `primary-button h-9 px-4 text-xs`（36px 高 / 12px 字号）。
**新增底部按钮照此写，别只写裸类名。**

**改动（4 个文件，纯补尺寸类、无逻辑改动）**：
1. `AssetPromptGenerateModal.vue` — 5 处裸 `secondary-button`（复制提示词 / 导入外部 AI 结果 /
   复制本条提示词 / 导入本条结果 / 取消）；关闭确认子弹窗的 2 个 `h-8` → `h-9`。
2. `common/PromptPreviewDialog.vue`（「确认发送内容」）— 3 处。
3. `common/ManualResultImportDialog.vue` — 2 处。
4. `panel-gen/PanelPromptGenerateModal.vue`（画面描述推导）— 3 处。

⚠️ 刻意保留：`AssetPromptGenerateModal` 里「模型原始返回」浮层头部的 `h-8`、
卡片内的小按钮（`h-6` / `h-7`）—— 那些是自成一套的紧凑尺寸，不属底部按钮组。

**校验**：`vue-tsc --noEmit` exit 0。

## 改动：asset-prompt 模板瘦身 —— 版式搬到共用属性，逐条只写主体自身

**动因**（用户）：固定版式写死在模板里 → 模型每条都复述一遍；人物那条还要把上装/下装/袜鞋
在第 2/3/4 格各写一遍，外貌细节被稀释；且示例里出现「一只手插兜、站姿随意」这类
**提取阶段根本不该给、模型自己脑补**的姿态，与固定版式打架。

**改动（3 个文件，不动数据结构）**：

1. `services/promptTemplateRegistry.ts`
   - 新增章节 **【与共用属性的分工】**：本环节只写主体自身（人物＝外貌与服装／场景＝空间结构与光线／
     道具＝轮廓各面与尺寸材质）；版式与画格排布、每格画什么、背景与打光、画风画质词、姿态与手部动作、
     镜头机位**一概不写**；**唯一例外＝状态名含「机位图」**。
   - 【转译要求】：六段骨架 → 「每个状态只输出一条连贯中文段落」；按类型只写主体内容；
     **同一套服装只写一次**（不再为第 2/3/4 格重复）。
   - 移出模板的版式文本：人物四联（含「脸只出现一次」红线）、道具多视图、场景空间全景 establishing shot。
     机位图九宫格**保留在模板**（条件分支，放块里会和场景全景同拼）。
   - 【禁止项】改为「版式已在共用属性里正向说清，本环节不抄第二遍、更不写成否定句」。
   - `ASSET_PROMPT_FORMAT` 同步加两句（格式段与正文同源：只写什么 / 不写什么 + 机位图例外）。
   - `description` 重写。⚠️ 回归旧 bug 模式：**格式段与正文必须同改**。
2. `services/assetPromptService.ts` —【写作要求】改为「只写主体自身样子」+ 明确不写
   「版式/背景打光/画风画质/姿态手部动作/镜头机位」。
3. `tests/features/promptTemplateRegistry.test.ts` — 拆成两支：① 版式类措辞**必须归零**
   （`统一角色设定版式`/`统一道具设定版式`/`统一空间全景版式`/`六段骨架`/`中性 18% 灰哑光背景` 等
   用 `for...of banned` 断言 not.toContain）；② 机位图全文保留。格式段断言 `版式与画格分工`+`唯一例外`。

**校验**：`vitest run tests/features/promptTemplateRegistry.test.ts` → 39 passed；
`vue-tsc --noEmit` → exit 0（31m47s，勿与测试并行跑）。

**交付物**：`docs/资产设定图版式-共用属性块.md` —— 版式块整段文本（三类分支 + 让路句 + 使用步骤），
给用户复制到「资产生图配置 → 共用属性 → 插入最前」。

**遗留 / 下次注意**：

- 共用属性 `SharedPromptBlock` **没有「适用资产类型」字段** → 一个块会拼到每张资产图上。
  当前用块内「主体是人物/场景/道具」**软判定**绕开；若实测混用，可选升级＝给类型 + 加 `appliesTo`，
  且 `composeAssetPrompt`（文字）与 `genRefImages` / `sharedRefImageCount`（取图）**必须同口径过滤**（图号红线）。
- 改完模板必须让用户去设置页点 **「填入推荐模板」**（存量模板优先）；存量提示词需重跑。

## 改动（同日晚，替代上一节的「版式搬共用属性」方案）：版式落到生图配置的「版式」tab

**用户否掉了「共用属性块加适用类型」**，改为：**在资产生图配置里加一个 tab，人物/场景/道具三个输入框，
生图前拼在共用属性（插入最前）之后、绘画提示词之前**（同款范式 = 分镜绘图配置的「参考图用途」tab）。

**为什么这个更好**（写下来备查）：① **图号零风险** —— 三段是纯文字、不挂参考图、不进
`getSharedRefImages`，front 组编号口径一个字没变；② 改动面小（不用动 `SharedPromptBlock` /
`createEmptyBlock` 白名单 / 块卡片 / 块排序）；③ 改版式**不必重跑提示词**。

**改动（5 个文件 + 1 新文件 + 1 新测试）**：

1. `types/index.ts` — `AssetGenConfig.layoutPrompts?: Partial<Record<LongProjectAssetType, string>>`
   （**只加在 AssetGenConfig**，分镜的 ImageGenConfig 不加 → `composeFinalPrompt` 链路零影响）。
2. **新增** `services/assetLayoutSpecs.ts` —— `RECOMMENDED_LAYOUT_SPECS`（三段推荐版式，从模板搬出的原文）
   + `LAYOUT_SPEC_FIELDS`（UI 字段）+ `resolveLayoutPrompt(config, type, variantName?)`。

**两条容易踩的口径**：

- **机位图豁免写进函数**（`resolveLayoutPrompt` 判 `REF_SHEET_VARIANT_NAME`）而不是靠模板自觉 ——
  场景的「机位图」状态若同时拼上空间全景版式，会和提示词正文里的九宫格版式打架。
- **「字段缺失」vs「字段存在但为空串」必须分开**：
  `layoutPrompts` 整个缺失（旧项目）= 从没配过 → **用推荐版式兜底**，否则升级即静默丢版式（原先模板一直在输出）；
  字段存在哪怕三段全空 = 用户主动清空 → **不拼、不兜底**。抽屉首次打开也是按「字段缺失 → 预填推荐版式」处理。
