## 分镜格式升级 v4：符号规则 + 13 字段 + 左栏格数标签

用户明确否掉了上一轮的「台词用 `【】` 包裹」方案（v3.1），改为 **v4 符号规则**：

```
## 分镜 1 · 双格
【第1格】
「景别」：近景转特写
「镜头」：从角色A侧脸下摇至小臂
「画面」：角色A的手臂占前景，指节收紧，青筋凸起。
「人物」：角色A
「动作」：指节收紧，手臂绷紧。
「表情」：侧脸冷硬，眼神压着怒意。
「台词」：角色A：“破坏了它的关键部分，跟要了它的命有什么区别？”
「音效」：沙沙——表面摩擦。
「光效」：暖黄顶灯，背景压暗，手臂局部高光。
```

要点：
- **符号规则**：分镜格用 `【第X格】`、内容标题用 `「XXX」`、冒号后写具体内容。`【】` 从此只用于 `【第X格】`；`「」` 只用于字段名，二者不混用。
- **13 字段固定顺序**：景别 / 镜头 / 画面 / 人物 / 动作 / 表情 / 台词 / 心声 / 画外 / 旁白 / 音效 / 光效 / 备注；没有内容的字段**整行省略**。
- **台词类四选一**：`台词` / `心声` / `画外` / `旁白` 同一格最多出现一个。写法 `「台词」：说话人：“台词”`（引号中文，入库去引号、出库补回）。`「旁白」` 不带说话人。
- 语义注意：v3 的 `【镜头】` = 景别；v4 拆成 `「景别」`（→ `cell.shot`）与 `「镜头」`（运镜 → `cell.camera`）。解析器按行首符号分流，两套语法互不干扰。

## 审查：资产提取链路 —— 绘画提示词该由谁生产（规划，未改码）

### 现状（三块）
1. **提取默认提示词**两处：`promptTemplateRegistry.ts` 的 `extract` 推荐模板正文（角色：资产分析师；要求「有明确外观信息时写视觉描述和绘画提示词」「信息不足时留空，不要猜测」）+ `OUTPUT_PROTOCOL_DEFAULTS.extract`（`### 视觉状态：名称`，块内字段：视觉描述 / 状态标签 / **绘画提示词**）。变量表 `VARIABLE_REGISTRY.extract` 只有 章节原文/原文分析/漫画剧本/分镜概要/已有资产 —— **没有「风格上下文」**。
2. **解析**：`assetExtractionService.ts` → `parseChineseAssetReport`（`# 人物/场景/道具` + `## 资产名` 切片）→ `parseCandidateContent`（逐行 `- 字段：值`；`### 视觉状态：X` 起块；字段「视觉描述/状态标签/绘画提示词」按 currentState 或 pendingStateFields 回填）→ `states[]`。另有 `parseLegacyJson` 兼容旧 JSON（`visualVersion.imagePrompt`）。序列化 `serializeCandidateContent` 反向输出。
3. **落库与消费**：`assetExtractionConfirm.ts` 把 `state.imagePrompt` 写进 `variant.imagePrompt`。消费方三处：资产生图工作台（`LongProjectAssetWorkbench.vue` 直接用 `variant.imagePrompt` 生图）、分镜画面描述（`panelPromptService.buildPanelAssetsContext` 注入「绘画提示词：」）、文本自动绑定扫描（`promptAssetService.panelScanText` 含 imagePrompt）。

### 诊断（4 个问题）
1. **角色错位**：提取模板是「分析师 + 不编造 + 信息不足留空」，与绘画提示词需要「补全为可直接生图」相冲突。
2. **缺风格上下文**：extract 模板无风格变量 → 提取阶段产出的 imagePrompt 天然无画风一致性。
3. **「仅补缺失」把专门环节跳过**：`LongProjectAssetWorkbench` 的 `promptTargets` = `variants.filter(v => !v.imagePrompt?.trim())`；提取既已写入 → 不再走带风格上下文的 `asset-prompt` 环节。
4. **解析脆弱 + 语义冗余**：`- 绘画提示词：xxx` 是单行匹配，长提示词若换行会被截断；且 `description`（视觉描述）与 `imagePrompt` 语义重叠。

### 建议方案（待拍板）
**分层**：提取阶段只产「视觉状态 + 视觉描述（客观特征）」；绘画提示词生产权下移到 `asset-prompt` 环节（它有风格上下文 / 目标生图模型）。`variant.imagePrompt` 字段**保留不动**（三处消费方接口不变），只是不再由提取阶段写入。
- 备选 A（维持现状）不推荐；备选 B（提取可选「顺带出初稿」开关）增加复杂度，暂不采用。
- 涉及改动：`extract` 模板正文与输出协议、`parseCandidateContent`/`serializeCandidateContent`（保留「绘画提示词」解析分支作向后兼容）、`assetExtractionConfirm` 落库时不再写 imagePrompt、审核页右列状态标签（如需展示特征）。
- 风险：存量 run 的 candidates.states 已带 imagePrompt → 保留即可，不破坏；旧输出仍可解析。

### 方案 C 已落地（用户拍板：采用 C / 不新增字段复用视觉描述 / 审核页维持现状）
- `promptTemplateRegistry.ts`：
  - `OUTPUT_PROTOCOL_DEFAULTS.extract`：视觉状态块内字段由「视觉描述、状态标签、绘画提示词」改为「视觉描述、状态标签」；新增「视觉描述只写客观外观特征（体型/发型发色/面部/服饰材质/配色/标志物/受损痕迹）…不要输出绘画提示词」。
  - `extract` 推荐模板【信息要求】：`写"视觉描述"和"绘画提示词"` → 只写"视觉描述"（客观特征），并加一句「这里只沉淀可复用的外观特征，绘画提示词由后续『资产绘画提示词』环节生成」。
  - `asset-prompt` 推荐模板【写作要求】：新增「清单中的『视觉描述』是客观特征基准，必须完整体现」；末条由「严格基于清单给定信息撰写」改为「不得编造与清单信息冲突的细节」。
- `assetExtractionService.ts`：`parseCandidateContent` 的「绘画提示词」分支加注释，标明**向后兼容**（旧协议结果 / 手动导入仍解析）；`serializeCandidateContent` 保留输出。**落库逻辑未改**——提取不再产该字段即天然为空，但手动导入带此字段仍会保留。
- 校验：79 单测通过；`vue-tsc` 无报错；`vite build` 渲染层 2155 模块 + 主进程 654 模块通过。

## 审查：资产提取提示词的「变量拼接」机制（诊断，未改码）

### 渲染规则（`promptTemplateRegistry.renderPromptTemplate`，全链路唯一）
对每个注册变量：**在模板中 → 原地替换**（值为空用 `emptyText`）；**不在模板中 → 按 `fallback` 兜底**：`always` / `if-nonempty` 且有值且有 `blockLabel` → 追加 `【blockLabel】\n值` 到末尾；`drop` → 跳过。最后清理未注册 `{{...}}` + 附加输出协议。
→ **结论：没写进模板的变量会被自动补充**，这是"防丢上下文"设计，但用户无法用"只写 {{章节原文}}"来精简。

### extract 的 5 个变量兜底
| 变量 | fallback | 未插入且非空时 |
|---|---|---|
| 章节原文 | always | 追加【章节原文】 |
| 原文分析 | if-nonempty | 追加【原文分析】 |
| 漫画剧本 | if-nonempty | 追加【漫画剧本】 |
| 分镜概要 | if-nonempty | 追加【本章分镜概要（已确定会被绘制的画面）】 |
| 已有资产 | if-nonempty | 追加【项目已有资产】 |

### 分镜概要的数据源与口径
- 数据源：`LongProjectAssetTab.vue` → `latestStoryboardRun`（本章 `status==='completed'`，按 **updatedAt** 倒序取首个）；分镜页 `currentRun` **同口径**，两页一致。
- 生成：`panelsOutline = panels.map(p => '分镜'+order+'：'+p.content)` —— **只取页级 `content`（各格「画面」拼接），不含格级「人物」/台词**。v4 分格里 `cast`（人物）才是角色出现的关键证据。
- 相关缺口：`countCandidatesAppearances`（出现次数统计，用于审核页参考重要性）扫描文本 = `content + dialogue + narration + imagePrompt`，**不含 `cells[].cast`**；`promptAssetService.panelScanText`（自动绑定扫描）同样不含 cast。
- "不是最新"的排查方向：① 排序用 `updatedAt` 而非 `createdAt`，编辑旧 run 会把它顶成"最新"；② 只取 `completed`，最新 run 若为 running/failed 会退回上一版。

### 建议优化项（待用户确认）
1. 分镜概要带格级要点（人物 + 画面），或复用 `formatCellsForPrompt` 精简版 —— 直接提升角色/道具召回。
2. `countCandidatesAppearances` 与 `panelScanText` 纳入 `cells[].cast`。
3. 兜底策略透明化：设置页变量列表标注「未插入时是否自动追加」，让用户可预期（不建议新增禁用语法）。
4. 可选：重新评估「原文分析 / 漫画剧本」与「章节原文」的信息重叠，考虑降为不自动追加，减少噪声与 token。

### 环境坑（重要）
`pnpm build:renderer` 在 chunk 渲染阶段被静默中断、日志停在「2155 modules transformed」且退出码可能假报 0 —— 两种成因，按序排查：
1. **孤儿进程**：上一轮被中断的构建残留 node/esbuild 进程（锁文件、占内存）。`Get-Process node,esbuild` 找出「非 11:xx 起的」残留 PID → `Stop-Process -Force`。
2. **Node 堆不足**（本机内存紧张，可用常仅 2.5~3GB）：给构建加 `$env:NODE_OPTIONS = "--max-old-space-size=3072"` 后，渲染层 2155 模块 23s 顺利通过。
**注意：不要误杀 11:29 起的 vite dev / electron（用户开发环境）。** 排查时先跑 `vue-tsc --noEmit && vite build` 里的 vue-tsc 段——它能过说明类型检查 OK，崩的是 vite 打包段。
