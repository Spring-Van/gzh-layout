### 量化（本机实测）
- `comic-gen.json` **400.0 MB**（`.bak` 另 400MB），其中 **142 张内联 base64 = 399.5MB（99.9%）**。

**一次导入 ≈ 两次 188MB 跨进程搬运 + 一次 400MB 重写 ≈ 4~6s，全程同步。**

### 绘图页面：生图 loading 提前消失 + 多张成图切换卡顿

用户反馈两件事：①同一分镜生成多张时「loading 已经停了，图片过很久才出来」；②左右切换多张成图非常不流畅。

**实测（本机库 299MB，长篇项目 86.5MB）**：`panelArtworks` 26 条 / 7 张成图，
单张 dataURL 3.07~11.34MB（中位 3.07MB），3 个分镜有多图（2/2/3）。
`atob` 解码 3MB 仅 2ms、charCodeAt 循环 6ms（V8 有快路径）→ **解码本身不是瓶颈，全量写库才是**。

**根因一：「生图中」写在项目数据的内存补丁上，被落库整体替换冲掉。**
`artwork.genStatus === 'running'` 只由 `patchArtworkInMemory` 写，而任何一次落库
（生图前的补绑同步、其他 keep-alive 页面的保存、生图结果写回）都会 `project.value = updated`，
用 DB 数据整体替换 → 补丁消失 → loading 提前熄灭，但生图还要跑十几秒。

**根因二：切图每次触发一次整库 read-modify-write。**
`switchPanelImage` → `upsertArtwork` → `mutateLongProjectData`，端到端要
`comicDb.getProject`（IPC 回传 86MB，渲染层同步反序列化）+ 整库重写 → 单次切图卡约 1~2s。

**改法（`LongProjectStoryboardTab.vue` 为主）**：
1. **`runningPanelIds`（渲染层 `reactive(new Set)`）成为「生图中」的权威来源**——
   `isPanelGenerating(panelId) = runningPanelIds.has(id) || artwork.genStatus === 'running'`；
   `beginPanelGeneration` / `endPanelGeneration` 成对收口（所有出口都必须走 `endPanelGeneration`）。
   左栏 `PanelListItem` 增加 `generating` 字段，`PanelListSidebar` 的四态标签同样吃它。
   **这是通用约定：进度/进行中这类瞬时状态属于渲染层，不要塞进项目数据。**
2. **生图成功先内存出图再落库**：`patchArtworkInMemory(新图 + selectedImageId + done)` 后立刻
   `endPanelGeneration`，用户马上看到新图，不再等那次数秒的整库写盘；写盘失败**回滚内存补丁**并提示
   （不能留「界面有图、库里没有」的假保存）。
3. **切图改为内存覆盖 + 合并落库**：新增 `selectedImageOverlay`（`reactive(new Map)`，panelId → 图），
   `artworkMap` 合并它作为显示真相；`pendingSelectedImages` 攒待落库切图，停手 600ms 后合并成一次写盘，
   `chapterId` 变化 / `onDeactivated` / `onBeforeUnmount` 强制冲刷。
   覆盖在「落库追上（`selectedImageId` 相等）」后由 `watch(panelArtworks)` 自动消散。
   → 连点箭头零写盘；且写盘回包不会把选择打回旧值。
   注意：删图（`removeGenImage`）删的若是当前显示图，必须同时清 overlay + pending；
   生图成功也要清 overlay（否则旧选择会盖住新图）。
4. **大图显示加速**：`src/shared/image/imageUrl.ts` 新增 `toFastDisplayImageUrl` ——
   dataURL → **带 LRU（上限 32）的 Blob URL 缓存**，非 data 地址仍走 `toDisplayImageUrl`。
   理由：3~11MB 的 dataURL 每次渲染都要重新解析、解码在主线程；blob URL 短、可命中浏览器解码缓存。
   转换成本实测 3MB≈8ms（Node 里 `atob` 仅 2ms），可放心在渲染路径同步做。
   落点：`PanelPreview`（主图）、`PanelListSidebar`（缩略图）、`PanelAssetTabs`（绑定图/候选图）、
   `PanelPromptPanel`（参考图）、`AssetImagePreviewModal`（大图预览，含预加载）、`AssetVariantCard`（资产状态图），
   并统一加 `decoding="async"`。
   注：`Uint8Array` 直接当 `BlobPart` 会报 TS2322，用 `bytes.buffer as ArrayBuffer`。

## 上游技能 `konka0812/novel-to-manga-skill` 拆解 + 结合方案（分析类产出）

### 做了什么
克隆并通读上游技能（SKILL.md + 10 篇 references + 2 个脚本），逐个环节比对项目现状，
产出 `docs/novel-to-manga技能拆解与工作台结合方案.md`（结论 + 逐环节对照表 + 三档落地方案）。
**未改任何源码**，纯分析。

### 上游技能的骨架（供后续查阅）
S1 全书拆解 → S2 设定图 → S3 单章分镜 → S4 单章出页；三个硬停靠；一次只做一章。
工程目录 + ID 外键（`CHAR-角色-三视图` / `LOC-场景-机位图` / `CH001-P003`）+ `生成日志.md` 断点续跑。
九个机制：前瞻阅读（做第 N 章前读到 N+20）/ 描述考古 / **留白拍板** / 设定图精确到形态 /
检查清单机读 + **缺图即停** / **场景 3×3 机位图**（量化触发）/ 风格基因五维 + 去 AI 味 /
**节拍表先行**（页数是节拍的输出）/ 页级重生 + 错误类型决策表。

### 关键结论（结论已沉淀进方案文档，此处只留最容易忘的）
1. **正面冲突**：它的「留白禁止静默补全」vs 我们 extract 模板的「全维度脑补、不留空白」。
   化解口径：**结构性留白**（空间布局/材质/磨损/服装纹理）继续脑补；
   **身份性留白**（体型/脸型/五官瞳色/发型发色/肤色/标志性配饰）脑补但必须**显式标注 + 给候选**，
   按它的「补全决策表」四要素输出（设计依据 / 剪影冲突检查 / 连带返工范围 / 不采纳后果）。
   我们已有审核页这道闸门，缺的只是把「脑补」与「原文事实」在审核页上区分开。
2. **零代码落点（最值钱）**：全员设定图 → **共用属性块**（`enableRefImages` + `insertPosition:'front'`）；
   画风基因五维 → 5 个共用属性块；去 AI 味清单 → 同一个画风块；场景 3×3 机位图 →
   **直接当场景状态的成品图**（一图两用，无需改 `resolvePanelRefImage`）。
   —— 依据：`panelRefManifest.ts:85-97` 就是按 front 块先编号，「图1」语义天然成立。
3. **⚠️ 新发现的真实风险**：我们给模型的「出场资产」是 `A1 资产名（状态名）` 带编号，
   模型有充分理由把 `A1` **画进画面**。`panel-prompt` 两份模板缺「禁止序号/编号徽章入画」这条禁令
   （上游技能有）。**改一处的成本 = 两个模板同改**（`panel-prompt` 与 `panel-prompt-chapter` 正文重复）。
4. **⚠️ 陷阱（已实测验证）**：想把「节拍表」并进 storyboard 同一次输出会**凭空多出一页** ——
   `storyboardService.ts:293` 的 `STRUCTURAL_RE` **认 `#{1,6}`**，而 `PAGE_HEADER_RE`（:263）
   只认 `分镜 N` / `第 N 页`，所以 `## 本章节拍表` 会被自动开页。要走这条路必须先加
   「首个页头之前的内容整体丢弃」的剥离（这本就是已知缺口：extract/storyboard 都不去前言结语）。
   **推荐改为新增独立模板类型。**
5. **⚠️ 参考图无压缩**：全项目搜不到参考图发送前的压缩逻辑（`output_compression` 是出图参数不是入参压缩），
   而分镜成图单张 3~11MB、base64 后 ×1.37 → 多图（全员图+3 角色+场景+道具）会撞 413。
   上游技能明确要求「传入前统一压到 ≤1152px JPEG」。列为待办。
6. **不要照搬**：目录式工程 + 静态检查清单（我们已有 DB + 纯函数实时清单，是倒退）；
   「不自动续章」（我们有节点树 + `node.stage`）；「前瞻阅读」（输入是逐章录入，架构上拿不到后 20 章，
   改用 extract 模板约束代称角色「挂待确认 + 不填易误命中的别名」）。

### 追加：为什么不需要「全书拆解」（已写入方案文档 §八）

**结论：不需要全书拆解这个动作，但需要补「全书视野」。** 一章一章拆是对的。
它 S1 全书拆解是因**产物是文件、没有数据库**；你有资产库 + 归一化匹配 + chapterRange + 引用统计，
8 项价值里 6 项你已有且更强，只有「身份不提前绑定」「剪影/体型对错」两项缺。

**⚠️ 本次新发现的第三条跨章风险（最隐蔽，之前不知道）：「每章都在重写已有资产的描述，而模型看不到原描述」**

三条代码证据：
1. `assetExtractionService.ts:332-343` —— 「已有资产」上下文只序列化
   `- 林晚（人物；已有视觉状态：便装（<锚点前 30 字>））`：**不含 9 维外观描述、不含资产级 description**，
   `variant.anchor || variant.description` 再**截断到 30 字**。
2. `assetExtractionConfirm.ts:123-124` —— `content: candidate.content || acc.content || candidate.description`、
   `description: candidate.description || acc.description` → **候选优先覆盖**。
3. `assetExtractionConfirm.ts:108` —— `description: state.description || existing.description` → 状态级视觉描述同样候选优先。

**合成后果**：第 5 章重提「林晚」→ 模型只看到名字+状态名 → 基于第 5 章原文**重新脑补** 9 维 →
覆盖第 1 章那份**已被用户审过**的描述 → **描述漂移且界面上看不出来**。
（已有的两条跨章风险是「模糊匹配误合并」与「确认删本批未出现状态」，这是第三条。）

**方案（推荐 B + C）**：
- **B1**：`buildAssetExtractionPrompt` 把已有资产上下文从「锚点 30 字」扩成「状态名 + 完整视觉描述」（或截 300 字）。
- **B2**：`applyCandidatesToAsset` 命中已有资产 → 描述**保留旧值**（候选优先 → 命中则保留）。
  ⚠️ B1+B2 必须同做：只做 B1 = 覆盖变准但还在覆盖；只做 B2 = 模型看不到原描述却被要求沿用（做不到）。

## 分镜 + 分镜画面描述 两环对照分析（只写文档，未改代码）

产出：`docs/novel-to-manga技能拆解与工作台结合方案.md` **第十一章**（11.1–11.6）。

⚠️⚠️ **新发现的硬约束（重要，之前只有猜测）**：**分镜模板新增字段名会变成一句台词，不是被吞掉**。
- `storyboardService.ts:535` `knownField` 是 20 词**白名单**；`:531` 先试 `FIELD_RE`（`^[-*]\s*` 必须带 `- `）
  再试 `PLAIN_FIELD_RE`（无前缀，字段名 ≤12 字）。
- 模板要求「不要加 `-`」→ 新字段走 `PLAIN_FIELD_RE` → `:536` 条件成立且**不 continue** →
  落到 `:631` `SPEAKER_RE`（说话人 1–10 字、无标点）→ **新字段被解析成「说话人=字段名，台词=值」**，
  再经 `formatCellsForPrompt` 变成 `台词：核心信息："…"` 被画进画面。
- 若加了 `- ` 前缀 → 走 else 链 → `lastField = null` → **静默丢弃**。

## 分镜 / 画面描述模板三轮收敛：格数上限放宽到 8 格（连打页）

**用户诉求**：4 格太少 —— POV、特写、动作连续的特写格本来就需要更多格。

**结论**：上限 4 → **8**，但不是改一个数字，而是引入「叙事页 / 连打页」双模式。
- 叙事页 **1~4 格**：对话 / 环境 / 情绪（占全章多数，每格 ≤20 字）
- 连打页 **5~8 格**：动作分解 / POV 序列 / 特写连打 / 闪回（全章 ≤20%，每格 ≤12 字、多数格无台词）
- 页级 ≤60 字补「**无文字的纯画面格不占额度**」——否则 8 格 ×20 字在算术上直接冲突

**推翻了自己上一轮的判断**：上一轮以「中文气泡渲染瓶颈」为由建议保持 4 格，本轮按用户创作需要放宽。
关键认识：**瓶颈不在格数，在「有文字的格」有多少** —— 8 格页若有 6 格是无台词纯画面格，气泡压力反而低于 4 格满字页。

**代码侧零改动**（动手前先验证）：`PLAIN_CELL_TITLE_RE`/`ANY_CELL_TITLE_RE` 认「第8格」；
`cellCountLabel` 对 >4 返回 `${count} 格`；`formatCellsForPrompt` 用 `map` 不限长；
页头结构名是自由文本（`PAGE_LABEL_RE` 取 `·` 之后的全部）。

**`storyboard`**：硬上限写 8；【分页原则】加双模式判定、拆页路由改「超 8 个」、新增「连打页不得塞入对话往返」；
**新增【连打页怎么写】**（逐格极小时间差 / 特写·POV·近景为主 / POV 拆两格 / 必须有冲击主格 / 文字极简 / 全章 ≤20%）；
页头词表加 **`多格连打`**（5~8 格专用）并写死映射；格形补「格高不平均分配」；字数加「连打页 ≤12 字」。

**`panel-prompt` ×2**：规则 1 补连打页排布（格高不平均分配 + 冲击格；阅读顺序触发条件扩为含多格连打，且格数 ≥5 逐格写格序）；
气泡样式补「5 格以上连打页气泡 ≤8 字」（与分镜层 ≤12 字形成两级收紧）。

**验证**：模板单测 **33 passed**（新增 2 条）；完整套件 **40 files / 479 tests passed**；`vue-tsc --noEmit` exit 0；
21 关键词逐条 grep 落盘；旧措辞「4 格是硬上限 / 4 格为硬上限 / 超过 4 个信息单元就拆页 / 四格及以上一律写」全部归零。

**仍然成立的技术边界**：8 格页每格面积约为 4 格页的一半，**有文字的格**气泡字号仍偏小 →
连打页必须「画面格为主、文字为辅」；若 8 格都要带台词，应拆页或回到叙事页。

## `asset-prompt` 禁止项改口径：不再当固定尾段（用户反馈真实产出）

**反馈**：用户粘贴了真实产出，最后一段恒为
「不得出现任何台词、旁白、说明文字、水印、签名与资产编号徽章；仅允许版式要求的三视图标志与基础信息卡内容；不得出现萧薰儿之外的其他人物、动物或第二件资产；人物不得被裁切、不得重复出镜、不得持物或背负重物；三视图必须同比例、同大小；不得改变紫色衣裙配色、黑金丝袖口镶边与中分长直发发型。」

**根因**：旧模板是「【禁止项】（**必须逐条以否定句写进每条提示词**）」——**三处一起在命令模型照抄**：
① 【禁止项】标题；② 【用语要求】「【禁止项】里的内容禁令例外，必须逐条写进提示词」；③ 【自查】「是否逐条写出了【禁止项】」。

三类噪音：**版式重复**（三视图同比例/不裁切，版式声明里已正向写过）／**事实复述**（「不得改变 X 配色／X 发型」，等于把正面描述再说一遍）／**结构固化**（每条尾句都一样，模型当模板满足、还占 token）。

**改法（必要条件搬到该在的地方，再取消「必写」）**：
1. 「不出现第二人物与动物／无文字与水印／只有本角色／只有该道具／只有该空间」**并进四个版式声明的引号内**（人物、场景全景、场景机位图、道具各一句短句）；视图数字标号写成「除每格的单字符数字标号外不出现任何文字与水印」。
2. 【禁止项】标题改「（写，但**不许写成固定尾段**）」，并**把反面典型原文写进模板**（模型才知道哪种写法被禁）+ 四条：不许挂同一段通用清单；版式声明已说清的不要抄第二遍；只在盖不住时补 ≤1 句、整条否定句 ≤2 句；**版式类（背景色/完整入画/三视图同比例/视图标号）与事实类（配色/发型/材质/形态/尺寸/状态）一律不得写成否定句**；同一章内不得两条否定句完全相同。
3. 六段骨架的第六段保留但重定义：「禁止项**也不是独立尾段**，并进『构图与视角』的版式声明」。
4. 【用语要求】例外条款改为「版式声明里那句画面内容描述照写即可，**不算风格类负面提示词**」；【自查】改为查「是否并进版式声明／有没有复述事实的否定句／否定句 ≤2 句」。
5. **格式段（硬约束）加一句**：`提示词正文是一条连贯的中文段落：不要分点、不要带字段标题，也不要在末尾附通用禁令清单或固定尾句。`
6. **删掉「资产编号徽章」**——资产提示词输入清单里根本没有 A1／B2（那是分镜文本的编号，`buildTargetList` 用 `状态1｜资产：…`），旧模板等于凭空造了一条禁令。

**验证**：模板单测 35 passed（更新 3 处旧断言 + 新增 6 条锁定反固定尾段）；完整套件 **41 files / 507 tests passed**；`vue-tsc --noEmit` exit 0。

## 人物版式改「四联图」：整张图只保留一处高分辨率人脸（用户提供的实践方法）

**用户给的原话（关键方法）**：「同一人物四联角色设定图，1×4 非等宽排版。第 1 格为 2:3 竖幅人像，宽度明显大于后 3 格……第 2 格 全身正面，**头部完全裁出画面，禁止出现脸部**；第 3 格 3/4 前侧，**头部完全裁出画面**；第 4 格 背面，**完整保留头部至脚部**」
**+ 一句方法论**：「**只出现一次人物大脸，其余三视图只出现头部以下**，这样 AI 能更好地提取信息。如果按现在的来，三视图因为是远景，会导致人脸很糊，后续做参考不好。」

**这是参考图可读性问题，不是画风问题**：一张图总像素有限，全身格里再容下人头，脸只剩几十像素 → 下游分镜生图参考到的就是糊脸。

**改前 → 改后**（`asset-prompt` 人物版式整段重写）：

| | 旧 | 新 |
|---|---|---|
| 排版 | 右侧大脸 + 三视图（等宽） | 横向 **1×4 非等宽**：第 1 格 **2:3 竖幅**、明显更宽；第 2~4 格等宽 |
| 人脸 | 全身格都带脸（远景糊） | **整张图只出现一次脸**，且是唯一高分辨率位 |
| 第 1 格 | 脸部特写 | 2:3 竖幅脸部大特写，裁切至锁骨，占该格主要面积，直视镜头 |
| 第 2/3 格 | 全身（含头） | 正面／3/4 前侧全身，**画幅从颈部中段以下开始，头部完全在画幅之外** |
| 第 4 格 | 背面全身 | 背面全身，**完整保留头部至脚部**（只给后脑与发型背面），背对镜头看不到脸 |
| 背景光线 | 18% 灰哑光 | **影棚中性灰（18%）无缝背景 + 柔和伦勃朗光（45° 侧上方主光、柔和三角光斑）**、自然阴影与清晰皮肤细节 |
| 文字 | 基础信息卡 + `FRONT/SIDE/BACK` | **删除**，改为「无文字、无标注」 |

**三条必须写进模板的话（少一条就白改）**：
1. 机制本身：`**整张图的脸只出现一次**…第 2、3 格画幅从颈部中段以下开始、头部完全在画幅之外`；
2. **必须声明「这是刻意的」**：`这是刻意的版式，把画幅让给服装，不是裁切失误，不要补画头部与五官`
   —— 图像模型见「全身照缺头」会当失误主动补上，**不写这句，机制当天失效**；
3. 第 4 格单独说明：`完整保留头部至脚部，但人物背对镜头、看不到脸`，否则模型会把「裁头」规则套到背面格、丢掉发型背面资料。

**连带改动（同口径不能留双份）**：
- 【转译要求】「最小必要补全」举例 `全身出镜` → `画格排布`（新版式有刻意裁切，原词自相矛盾）；
- 【禁止项】版式类清单 `完整入画` → `多视图同比例同大小`，并补 `人物版式的「第 2／3 格不画头部」（写成否定句会反过来诱导模型补头）`；
- 【自查】改为查「1×4 非等宽 / 第 1 格 2:3 竖幅脸部大特写 / 第 2／3 格头部在画幅之外 / 第 4 格全身背面 / 18% 中性灰无缝背景 / A-POSE / 无文字无标注 / 四格同比例」；
- `description` 同步；【禁止项】里的**反面典型原文保留**（它本就是给人看的错误示范）。

**两个保留 / 一个待确认**：
- 保留 A-POSE 与 `双手自然下垂、不持物、不背包`；
- **「标准九头身黄金比例」降级为「统一头身比例」**（参考模板是超写实电商风，与九头身冲突）——已列入待办，用户一句话可加回；
- **风格词刻意没进模板**：`超写实电商人像摄影`／`SOFT REMBRANDT LIGHTING` 的**风格**部分归**共用属性块（漫画工艺）**，只把**光线做法**（伦勃朗光、45° 侧上方主光、柔和三角光斑）留在模板里（属「光线必须具体」的既定要求，不算渲染流派词）。

**验证**：`promptTemplateRegistry.test.ts` **36 条**（新增 1 条锁定四联机制，含 `FRONT`／`附角色基础信息` 必须归零）；完整套件 **41 files / 508 tests passed**；`vue-tsc --noEmit` exit 0。

### 改动二：`【文字气泡与旁白框】` → `【文字元素与气泡】`
形状表：对白＝椭圆｜**喊叫/愤怒＝锯齿尖角爆炸形**｜低语/虚弱＝虚线抖动细边或双轮廓｜
心声＝云朵边/波浪边或**边缘虚化成雾** + 一串小圆点气尾｜画外＝同对白但**气尾不得指向画面内任何人物**、朝声源伸出画面｜

六条放置规则（本轮新增，全是「写出来交给生图 AI」的）：
① 顺序＝先说话的在上，同格多气泡按**从上到下、从左到右**（中文方向），同高左边先读；
② 配额＝一格 **≤3 个气泡**、总面积 **≤该格 1/3**（一般 15%~25%），字多拆格拆页不撑气泡；
③ 避让＝绝不遮挡**眼睛与脸部表情**、关键道具、拟声词艺术字；

⑥ **引流＝用气泡把视线引向下一格**（下一格在下方 → 本格最后一句放下部中央或右下）。
另加**沉默格**：一格可以完全不放字。

## 页面版式二次收敛：否决「条带连打」→ 改「悬浮散格」（同日）

**用户反馈**：贴回模板实际产出的一段版面描述——

> 条带连打（本页 6 格）…第 1 至第 4 格为连续小格沿页面右侧纵向排列，**各占约 12%**；第 5 格占约 12%；
> 第 6 格为冲击主格占约 40%…形成「小-小-小-小-小-大」节奏。

**根因**：问题不在「不平均」，而在**等占比 + 同一条页边平铺** —— 五格都是约 12%、都贴页面右侧纵向排列，
本质仍是**一列等宽窄条**（瓷砖阵列），只是高度有差。用户要的是：多格**分散、错位、悬浮**，
「每一格不占满宽度，也可占满宽度，多个交替」。

**改法**：

1. **新增常量 `PANEL_FLOAT_RULES`**（`promptTemplateRegistry.ts`）——五条：
   一格不必占满页宽（**55%~85%**，满宽格与偏窄格**交替**）｜**水平起点逐格不同**（相邻差 ≥10% 页宽、
   垂直间距不等，**禁止沿同一条页边等距平铺成一列等宽窄条**）｜悬浮边界＝清楚画框包边 + 框外**统一底衬**
   （纯色/网点/上一格延续）｜**局部叠压**（压角 ≤ 被压格 1/5，按阅读顺序**后读的压住先读的**）｜
   偏窄格优先落中轴或两侧交替，**POV／特写／反应格优先做成偏窄浮格**。
2. **结构名换血**：**删掉 `条带连打`**；4 格补 **`错落浮格`**；5~8 格补 **`悬浮散格`／`浮格连排`**。

| 【文字元素与气泡】分流第 6 条 | 「用气泡把视线引向下一格」补一句「这靠的是**气泡摆放的位置**，不是画一条线」 |
