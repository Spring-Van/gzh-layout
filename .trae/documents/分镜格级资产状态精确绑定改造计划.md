# 分镜格级资产视觉状态精确绑定改造计划

## Context（背景与问题）

用户目标：资产视觉状态能**准确**绑定到分镜——一格内多个资产各自绑定准确状态，同镜不同格同一资产可不同状态（换装页等），且生图/画面描述按格级状态正确消费。

探索确认的现状缺口（格级数据链路已存在，但无下游消费）：

1. 格级声明 `cell.assetBindings` 有完整写入链路（解析器 pushCellAssets、serializePanelBlock 回写、savePanelEdit 编辑合流），但**所有下游都不读它**：
   - 参考图注入：`resolvePanelBindings`（panelPromptService.ts:36）只遍历页级 `panel.assetBindings`，每资产只解析一个状态 → `currentRefGroups`（LongProjectStoryboardTab.vue:578）与 `panelRefImages`（:1107）→ 生图参考图
   - 画面描述推导：`buildPanelAssetsContext`（panelPromptService.ts:68）同样只看页级 → 「绑定资产」变量
2. `summarizeCellBindings`（storyboardService.ts:111）格级→页级汇总取**首个**格声明：同资产多状态时丢失，且延续链起点应为镜末状态
3. 画面描述的「分格详情」`formatCellsForPrompt`（storyboardService.ts:618）不含出场资产行，模型看不到各格状态
4. 提示词格式规则未要求「跨格状态变化分开声明」

用户已确认的取舍：状态 pill 手选保持**本镜全部格**（页级语义，现状不变）；中栏绑定卡**显示各格状态明细**。

## 方案总览

核心思路：**格级声明成为状态精度的补充事实源，下游解析改为 页级 ∪ 格级 展开**。页级绑定保持「资产清单 + 镜末状态」（数据结构不变、旧数据零迁移、延续链兼容）。

```
resolvePanelBindings（页级，保留：资产清单 + 镜末状态解析）
resolveCellBindings（新增：格级状态明细，按格序）
        ↓ 合并
resolvePanelAssetStates（新增：并集展开，同资产多状态各成一条目，带 cellIndexes）
        ↓
currentRefGroups / panelRefImages / buildPanelAssetsContext（改为消费新结构）
```

## 改动点（按文件）

### 1. panelPromptService.ts
- 新增 `resolveCellBindings(panel, assets): Array<{ asset, variant, cellIndex }>`：遍历 `panel.cells` 各格 `assetBindings`，解析资产+状态；资产已删 / 状态悬空（variantId 在资产库找不到且无 fallback）跳过
- 新增 `resolvePanelAssetStates(panel, assets): Array<{ asset, variant, cellIndexes: number[] }>`：
  - 以页级 `resolvePanelBindings` 为基（资产清单）
  - 每个资产收集格级声明中该资产的状态（按格序，同状态多格合并 `cellIndexes`）
  - 有格级声明 → 每个状态一条目；无任何可信格级声明 → 退化为页级绑定状态（`cellIndexes: []`）
  - 全部格级声明悬空时回退页级状态（保证至少一条）
- `buildPanelAssetsContext` 改用 `resolvePanelAssetStates`：单状态输出格式不变；多状态输出 `资产名（人物）｜视觉状态：状态A（第1格）· 状态B（第2格）`
- `resolvePanelBindings` 原样保留（PanelAssetTabs 的 currentVariantOf/focusTargetOf 等继续用，不破坏）

### 2. storyboardService.ts
- `summarizeCellBindings`：同资产多声明时取**最后一个**格的声明（镜末状态 = 页级主状态 + 延续链起点）
- `formatCellsForPrompt`：每格补 `push('出场资产', serializeBindings(cell.assetBindings))`（serializeBindings 已存在）

### 3. LongProjectStoryboardTab.vue
- `currentRefGroups`（:578）与 `panelRefImages`（:1107）：遍历源从 `resolvePanelBindings` 改为 `resolvePanelAssetStates`——同资产多状态各自取图；取图单选口径 `resolvePanelRefImage` 不变（格级条目无页级手选图时自然取状态首图）
- 注意 `MAX_REF_IMAGES` 截断顺序保持现状（类型组顺序：style → character → scene → prop）

### 4. PanelAssetTabs.vue
- 新增 computed/工具 `cellVariantRows(entry)`：从 `panel.cells` 解析该资产各格实际状态（格级声明优先，无声明格不显示）
- 绑定卡内：各格状态**有差异**时列出「格1：状态A · 格2：状态B」，与页级主状态（镜末）一致的加高亮；无差异时不显示（避免噪音）
- pill 手选逻辑不动（`setBindingVariant` 已同步写全部格的声明，与本方案语义一致）

### 5. promptTemplateRegistry.ts
- `OUTPUT_FORMAT_SPECS.storyboard` 出场资产格式规则补一条：**同一资产在镜内不同格状态不同时，各格按所在格实际状态声明，不得统一成一个状态**
- storyboard 推荐模板【出场资产怎么写】段同步补充说明

### 6. 测试
- `tests/features/` 扩展：
  - `resolveCellBindings` / `resolvePanelAssetStates`：多状态展开、同状态多格合并、悬空跳过与回退、无格级数据退化页级
  - `summarizeCellBindings` 镜末策略
  - `formatCellsForPrompt` 含出场资产行
  - `buildPanelAssetsContext` 多状态输出格式
- 全量回归

### 7. 说明文档.md
- 1.4 关键决策补「格级状态绑定精度」；进度记录表补行

## 明确不做（本轮边界）

- auto-text **不做**格级化（保持页级文本扫描兜底，状态走延续链；格级精度由 model 声明 + 文本编辑「出场资产」行保证）
- 页级 `assetBindings` 数据结构不变（每资产一条），旧数据/旧 UI 零迁移
- 台词/旁白「提及即绑定」口径本轮不动（另一话题，可后续单独调整）

## 验证

1. `npx vue-tsc --noEmit` + `npx vitest run` 全量通过
2. 手测清单：
   - 双格页同资产两状态（编辑「出场资产」行：格1 `A（便装）`、格2 `A（战斗装）`）→ 中栏绑定卡显示「格1：便装 · 格2：战斗装」
   - 右栏「参考图设置」：该资产出现两个状态各一张参考图；批量生图 refs 含两状态
   - 画面描述推导：绑定资产变量含各格状态；分格详情带出场资产行
   - 后续镜延续 = 镜末状态（战斗装）
   - 旧数据（无 cell.assetBindings 的镜）行为完全不变
